# DRAT の節削除と level-zero 推論の失効

2026-11-09、main `a7bdd689f5e0e88bd361202e1b04c2c908ebf9c3` の
`drat_check_incremental.cpp` が充足可能な CNF の偽 UNSAT 証明を受理することを再現した。
現在の知識は [K0707](../../knowledge/items/K0707-incremental-drat-deletion-unsoundness.md)。

## 最小反例

`sat.cnf` は単位節 `{1}` のみで、明らかに充足可能。
`invalid.drat` は `{2}` の追加、`{1}` の削除、`{-1}` の追加、空節の順。
最初の追加を検査すると変数 1 の真が level zero に残る。
削除後は `{2}, {-1}` が充足可能で空節は RUP ではないが、旧増分実装は
削除した `{1}` に由来する代入を保持して矛盾を報告し、`VERIFIED`、終了コード 0 を返す。
同じ repo の毎回代入を再構築する `drat_check.cpp` は空節を拒否する。

これは SAT ソルバや大規模計算の結果に依存しない、検査器の具体的な偽受理である。
既存の p=2207/2531 の結論が偽だと示したものではない。

## 修正と回帰

削除行を処理するたびに全代入、level、reason、trail、伝播カーソルを失効させる。
次の RUP 検査で残存する単位節から再伝播する。
旧版・修正版・素朴版をソースからコンパイルし、符号反転と含意鎖を含む
4 個の偽証明、正しい UNSAT、証明未完了、不正単位節、保存されていた
p=2531 の小証明 6 個を比較した（`regression.json`）。
旧版は偽証明 4 個をすべて受理し、修正版と素朴版は拒否する。正例は両実装で受理。
13 ケースの一致は修正版の一般的な健全性証明ではない。

```powershell
uv run --locked python research/experiments/drat-deletion-soundness-20261109/regression.py --tmp D:/tmp
```

小証明 6 個は `--tmp` 内の `x_2531_<d>.cnf/.drat` がある場合だけ検査する。
これらが無い環境でも、自己完結した合成 7 ケースを実行できる。
出力はソースと実際に読んだ CNF/DRAT の SHA-256 を含む。

## 監査の引継ぎ

旧 `drat_audit_full_2531.json` は当時の生データとして保持する。
観測時点の 1263 VERIFIED と 2 件の I/O エラーは、健全な検査器による全数監査完了を意味しない。
旧版で受理した証明は別実装または修正版で再検査するまで独立証拠として数えない。

`audit_all_d.py` は修正版のソース SHA-256 ごとに別バイナリと別結果ファイルを使う。
旧バイナリ `drat_inc.exe` や旧 VERIFIED レシートを自動で再利用しない。
一時CNF/DRAT名にはworkerのPIDを含め、別の監査処理との置換・削除の競合を避ける。
既存の全数出力を上書きせず、まず p=2531 の d=393,395 のみを再生成・再検査する。
全 1265 d の再監査や p=2207 の追加監査は別段階であり、本実験では完了を主張しない。

結果: d=393,395 はともに修正版で `VERIFIED`（証明170,001行と141,680行）。
466秒で完了し、`../parabola-p2207-no-equality-witness-20261107/output/drat_audit_full_2531_34249932790a9e9d.json`
に検査器ソースSHA-256とともに保存した。旧1263件は混ぜず、新しい範囲は2/1265件とする。
