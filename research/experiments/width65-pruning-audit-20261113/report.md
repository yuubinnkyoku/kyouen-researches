# w=65 枝刈り監査 — REST6 2フェーズ方式の確立（2026-11-13 高速レーン）

## 背景

w=65 P(65) キャンペーン（[width65-level-classification](../width65-level-classification-20261113/)）は
heavy band が mask 975 まで沈まず 71k..100k nodes/mask を維持し、総ノード推定が
~200..250M に上方修正された。本監査はキャンペーン機（16法 REST bit-set DFS）の
枝刈り費用を測定・改善する。

## 結論

1. **K0789 の素数冪 121 は本機では不採用**。候補掃引（mask 列挙）では 11² が決定的
   だったのと対照的に、bit-set DFS のコストモデル（word-ops）では 457 word の
   rowMask 増が 10.7% の nodes 削減を上回り純損。343 はさらに大きいので同様と判断。
2. **REST6 2フェーズ方式が最適**。実現可能な標準形行集合は全合同証明書を通過する
   （整数 (a,u) が任意の法へ落ちる）ため survivors(REST6) ⊇ survivors(REST16)。
   よって **REST6 で生残0の mask は REST16 でも生残0が確定**し、K0797 会計
   （全形 classMax < 17）+ 2210 円下界 32 点と合わせて P(65) = 32 の主張にそのまま
   使える。REST6 で生残が出た mask のみ REST16 で再走査する（フェーズ2。
   現時点で必要 mask は 0 件）。
3. **実行コスト約2倍高速化**。heavy/light 両帯で word-ops 40..45% 削減。
   キャンペーン残り 2,321 mask の再開は REST6 2フェーズ機で行うべき。

## 意味論

本監査は有限測定である。P(65) の決定には mask 0..3295 の全完走
（REST6 フェーズ1 + 必要時 REST16 フェーズ2）が依然必要。完走時の昇格先は
K0798（P(65)=32・32プラトー w=49..65）。
