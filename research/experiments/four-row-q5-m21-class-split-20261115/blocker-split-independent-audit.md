# 4×21・q=5 blocker円分割の独立監査

## 結論

sat5.js の adapted 分割は、対象の二つの難バケットについて、独立した整数演算の実装でも **p1=81件、p0=86件** と再現した。各バケットの「右端セルが石」の1件を加えると、完全被覆に必要なSAT問題数は **p1=82、p0=87** となる。

この監査は分割の完全性と幾何列挙を確認したもの。Kissat の判定は実行していないため、M_{4,5} の境界は変わらない。

## blocker が円に限られる理由

対象セルを e=(20,0) とする。各バケットでは行0の石数がちょうど3、禁止数は q=5 なので、空点 e を塞ぐには、同じ直線または円上に e 以外の4石が必要になる。

- 水平でない直線は4本の水平行それぞれと高々1点で交わる。したがって盤上の点は e を含めても高々4点で、必要な5点に届かない。
- 水平線 y=0 は21点を含むが、行0の石は3個しかなく、必要な4石に届かない。

よって、この二つのバケットでは**直線による blocker は存在せず、空点 e を塞ぐ曲線は円に限られる**。これは4行・q=5・行0が3石という条件に依存する。別の幅・q・行占有数へ、そのまま一般化してはならない。

## 円ケースの完全被覆

極大性より、e が空なら、e を通るある円 g に4石がある。安全性により5石以上は置けないため、石数はちょうど4。既に minpos で固定された石が g 上にあれば、その石も4石の一つとして必ずピン集合に含める。残りだけを選ぶのが adapted 列挙である。

- p1: 固定石は (1,0)、(0,0) は空。固定石が g 上なら、それを含め残り3点を選ぶ。そうでなければ4点を選ぶ。
- p0: 固定石は (0,0)。同じ規則で、固定石が g 上なら残り3点、そうでなければ4点を選ぶ。

したがって、右端セルが石のA枝と、空である場合の全円・全4石集合のB枝は、バケット全体を覆う。B枝同士は、複数の円が同じ空点を塞ぐ局面で重なり得るため、ここでいう「完全分割」は厳密には**完全被覆**である。

## 独立した整数演算による監査

verify_blocker_split.py は既存のJavaScript実装を読み込まず、84点から全非共線3点組を取り、整数係数の円を正規化して列挙する。各円について、生成三つ組数が C(k,3) と一致することも確認する。

| 検査 | 結果 |
|---|---:|
| 盤上の5点以上を含む円 | 538 |
| (20,0) を通る円 | 19（6点円17、5点円2） |
| (20,0) を通る非水平直線 | 45、各直線の盤上点数は最大4 |
| p1 固定石 (1,0) も通る円 | 2 |
| p0 固定石 (0,0) も通る円 | 1 |
| adapted p1 / p0 blocker ケース | **81 / 86** |
| A枝を含む総インスタンス数 | **82 / 87** |

各ケースの4ピン集合は、それぞれのバケット内で重複しない。正準ケース列のSHA-256は監査JSONに保存した。

## 旧SA記録の83件について

旧SA列挙のp1=83件は、(1,0) が既に固定石であることを必須ピン集合へ反映していなかった。次の2円では、旧列挙が固定石を除く4点をピンし、固定石を合わせると同一円上に5石となるため、実行不能な枝だった。

- x²+y²−21x+17y+20=0
- x²+y²−21x+33y+20=0

どちらも (20,0) と (1,0) を通る。旧83件のうちこの2件を除くと81件となり、adapted列挙と一致する。SA記録の fail:2 とも整合する。旧83件は当時の試行数として保持し、厳密なSAT被覆数には使わない。

## 信頼境界

これは有限盤面の円・直線 census とケース被覆の独立監査であり、SATのUNSAT証明ではない。82/87件の全てがUNSATと確認されるまでは、c0k3p0/c0k3p1 の不存在も、4×21全体の欠損極大配置不存在も主張しない。M_{4,5} は引き続き [21,140]。
