# 標準11×11：8石LOSS根の17葉証明を16葉へ厳密最適化

2026-10-24。完全指摘・通常プレイ、元先手固定視点。**空盤勝敗はUNKNOWN**。

対象8石LOSS根：`00000000000040001000044400830000`。
元の17葉証明は `n11-s8-targeted-closure-20261015/s8-loss-terminal.cert`。
今回は同じ既知LOSS根に対し、**16個の10石LOSS葉による新しい証明書**を作り、
この固定した「8石→9石→10石葉」形式での葉数最適性も確定した。

## 完全な証明境界と最適性

8石根の合法9石子はD4正準化後 **31類**。各9石子の全合法10石子を
独立した整数幾何で再生成すると、10石候補は相異なる **378類**。
**378類すべてが、ちょうど2個の9石義務を被覆**する（WIN候補も含む）。

従って、任意の10石葉を使えると緩和しても31義務の被覆には
`ceil(31/2)=16` 葉が必要。新しい `leaves16.keys` の16葉は、
全31義務を覆い、全葉が終局LOSSであるため、下界を達成する。
これは外部最適化器の結果に依存しない厳密な最適性証明である。

元の17葉はすべて個別には必要（その集合から1枚も単純には削除できない）が、
**別の16葉集合への組替えで1葉減る**。局所的な貪欲削除だけでは最適化できない例となった。

## 独立検証

- `verify_min16.py`：既存の独立4×4整数行列式（Bareiss消去）と終局再帰を再利用。
  31義務、378候補、各候補の被覆数2、16葉の完全被覆、16葉すべてLOSSを検査。
- `verify_min16.js`：別実装の3×3整数行列式と終局再帰で同じ内容を再検査。
- **16葉の個別状態数合計は両実装とも11,495、勝敗・合法手数の不一致0。**
- `--negative`：葉の欠落・重複・境界外葉・根の混入の4種を拒否。
- JavaScriptの `--full` は378候補をすべて終局まで分類し、
  **LOSS 81 / WIN 297、個別状態数合計175,066** を再現する。
  この378件全体の勝敗は今回Pythonで独立再計算していない。
  最適性の下界は378件の勝敗判定には依存しない。

リポジトリ直下から：

```sh
python3 research/experiments/n11-s8-targeted-min16-20261024/verify_min16.py --negative
node research/experiments/n11-s8-targeted-min16-20261024/verify_min16.js --negative --full
```

## 信頼境界と進展

既存の8石LOSS1件について**最小証明葉数を17から16へ削減**した。
新たな8石・7石勝敗確定、7石の新規閉包、二石root閉鎖はない。
一般の任意深さの最短証明を示したわけではなく、指定した10石葉被覆形式の最適性である。
古いcache・df-pn値・凍結勝敗表は証明に使用していない。

ローカルNode.jsとPythonで両検証器、4種の改変拒否、JavaScript全378候補の
終局再計算を実行済み。全リポジトリのknowledge checkとCIは未確認。
