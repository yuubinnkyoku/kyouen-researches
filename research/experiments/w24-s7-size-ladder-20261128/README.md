# W_24 s=7 サイズラダー全層とドデカッド/極大13-cap部分集合の全数対応

## 目的

W_24 s=7 ゲームのサイズ別 Grundy 分解（K1342）の全層を、
ドデカッド（Golay 重み 12 語、2,576 個）の k-部分集合と
極大 13-cap（30,912 個）の k-部分集合の全数カウントで説明する。
K1349 がサンプルで示した層マップ（サイズ 9-13）を全数に拡張し、
未着手だった k≤8 の構造と d11→13-cap 拡大の一様性を全数検証する。

## 方法

- 盤: `../../design-kyouen-witt-20261125/output/board_w24.txt`（24 点、759 octad）。
  ゲーム規約は既存機材と同一（局面は各 octad と高々 7 点、kyouen は octad 完成）。
- `scripts/census.c`: 759 octad の F2 張から Golay 符号を再構成し
  （重み分布 {0:1, 8:759, 12:2576, 16:759, 24:1}）、
  2,576 dodecad と 30,912 極大 13-cap（octad-free 13-点集合、個数は K1342 の
  SIZE 13 と一致、5 個の極大性スポット検査付き）を列挙。
  各々の全部分集合を 2^24 マスク配列に多重度付きでマークし、
  サイズ別の相異なる部分集合数・交差・包含多重度を全数カウント（重複排除済み）。
  同時に d11→13-cap の索引（各 13-cap の 78 個の 11-部分集合のうち d11 判定）を作る。
- `scripts/dpverify.c`: fullcheck.c と同一の memoized Grundy DP で
  **サイズ 9-13 の全 6,661,168 局面の Grundy を全数計算**し、
  (サイズ, dodecad 部分集合フラグ, 13-cap 部分集合フラグ, G) を交差集計。
  さらに k=1..8 のランダム局面 100 × 8 と k=6,7,8 の構造クラス
  （octad-6 / octad-free-6 / octad の 7 点 / dodecad 8-部分集合 /
  octad の 7 点 + 1 点）各 50 のサンプル DP。
- `scripts/d11ext.c`: 全 30,912 d11 について 12-cap 拡大（S+{x} が合法）を全数列挙し、
  各拡大が極大 12-cap か（T_12 非所属）を判定。
- `scripts/assemble.py`: 公式 GSIZE/SIZE 行と突合し対応表と監査を
  `output/correspondence.json` に統合。

並列度は共有マシンの負荷制約のため全計算 single-thread。

## d11 → 極大 13-cap 拡大の一様性（全数検証、K1349 {13:12} の完全化）

- 各極大 13-cap は **12 個**の d11 11-部分集合を持つ（hist {12: 30,912}）。
- 各 d11 は **12 個**の極大 13-cap 拡大を持つ（hist {12: 30,912}）。
- incident 総数 30,912 × 12 = **370,944**（両方向で整合）。
- 各 d11 の 12-cap 拡大はちょうど **13 個**で、**すべて非極大**
  （極大 12-cap 拡大は 0）。よって極大拡大プロファイル {13:12} が
  全 30,912 d11 で確定（K1349 はサンプルのみ）。

## ドデカッドは s=7 では非極大（G=1）— K1348 k=12 行・K1342 evidence の修正

- dodecad と octad の交差は {2:132, 4:495, 6:132}（最大 6）なので、
  任意の外部点の追加は octad を完成させない → dodecad は 12 個の合法手を持つ。
- 全数 DP で **2,576 個の dodecad すべてが G=1**（子は 12 個の極大 13-cap、mex{0}=1）。
- census でも **すべての dodecad がちょうど 12 個の極大 13-cap に含まれる**。
- したがって「サイズ 12 の G=0 1,020,096 は極大 12-cap（ドデカッド 2,576 を含む）」
  （K1342 evidence）と「k=12: 2,576, 0（極大・終端）」（K1348 k=12 行）は誤り。
  正しくは: 極大 12-cap 1,020,096 = caps_12 − T_12 に dodecad は含まれず、
  dodecad は非極大 G=1（T_12 側）。
- K1348 の k=9,10,11 行（G=2/1/0）は本実験の全数 DP で再確認（正しい）。

## k ≤ 8 の構造（K1349 未着手領域）

- G はパリティ則 `G = k mod 2`（K1342/K1343 の全数分解どおり）。
  ランダム 100 × 8 サイズと構造クラス各 50 のサンプル DP でもパリティどおり。
- dodecad k-部分集合は k ≤ 6 で**全部分集合**（C(24,k)）。
- k=7: 340,032 = C(24,7) − 6,072。欠けは **759 × 8**（octad の 7 点集合）。
  dodecad は octad と最大 6 点しか交わらないため。この欠けも 13-cap には含まれる
  （T_7 = C(24,7)）。
- k=8: 637,560。欠けは **759 × 8 × 16 = 97,152**（octad の 7 点 + 外部 1 点の 8-cap）。
  欠けを含め全 8-cap が 13-cap に含まれる（T_8 = 734,712）。octad 自身（759）は
  非局面でどちらにも属さない。全体の分割: 735,471 = 637,560 + 97,152 + 759。
- 包含多重度（均匀性）: dodecad 側 k ≤ 5 で一様 {2576, 1288, 616, 280, 120, 48}、
  k=6 は 2 軌道 {16: octad-6 21,252, 18: その他 113,344}、k=7 は一様 6、
  k=8 は一様 2（D とその補 dodecad）。13-cap 側も k ≤ 5 で一様
  {30912, 16744, 8736, 4368, 2080, 936}。

## 監査（K1349 個数表 × K1342 原表）

K1349 の 9 行の個数は K1342 GSIZE 行とすべて一致（転記ミスなし）。
ただし dodecad の所属は「12 極大」ではなく「12 非極大」側（上記の修正）。
K1349 のプロファイル主張のうち d11 {13:12}・非ドデカッド 11 の 13-cap 数 1・
dodecad 9-部分集合の 21・dodecad 10-部分集合の 12 は全数で確定。
極大 12-cap 拡大数（{12:180} 等）はサンプル主張のまま（本実験では未検証）。

## 出力

- `output/census_raw.json` — 全数カウント（per-k の D/T/both/多重度ヒストグラム）
- `output/dpverify_raw.json` — 全数 DP（k=9..13 のクラス別 G ヒストグラム）+ サンプル
