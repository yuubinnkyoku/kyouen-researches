## なぜ統合が必要か

従来の `n11-terminal-s7-union-20261024/audit.js` は、終局証明済み9石WIN
120根を一手戻した8石WIN **961類**だけを利用していた。
しかし、9石根の一覧とは別に、8石WINを直接証明した次の資料が存在する。

- `n11-s7-38-terminal-20261019/s8_38_win_proof.tsv`：38根
- `n11-s8-neighbor24-round8-20261020/proof24_optimized.tsv`：20 WIN根（24根中）
- `n11-s8-round9-global78-20261020/round9_proof_optimized.tsv`：16 WIN根（22根中）

合計74根は相異なり、961類との重複10根を除いた**64類**が
これまでの9石WIN逆向き集合に入っていなかった。
これは「新たに64件を終局証明した」という意味ではなく、
**既に終局証明済みだった64件を被覆監査に取り込んだ**という意味である。

## 再現

リポジトリ直下から：

```sh
node research/experiments/n11-terminal-s7-direct-s8-union-20261024/audit.js
NEGATIVE=1 node research/experiments/n11-terminal-s7-direct-s8-union-20261024/audit.js
```

Node.js標準機能のみ。7群の9石WIN根、K0528の18根、
8石LOSS38根、直接8石WINの3種類の既存証明表を読む。
8石直接証明では各WIN根の合法9石証人を確認し、
その証人の**全合法10石子が証明表に過不足なくあること**を検査する。
LOSS根の9石全義務・10石証人も構造的に検査する。
さらに整数行列式による安全性、D4正準化、全合法7石子、
極性衝突、既知7石WINの38子閉包を確認する。
`NEGATIVE=1` は入力欠落4種を拒否する。

**信頼境界：** 10石葉のWIN/LOSSは上記各元実験の独立C++/Python終局証明に依存する。
本監査は葉の勝敗を再計算しない。過去の凍結WIN/LOSS cache、未完df-pn、
pn/dnを証拠に使用しない。新規7石勝敗・二石root・空盤勝敗は未確定。
