# 7xm q=4 行欠損witness帯の構成的延伸 — 幅22..35・M_{7,4} >= 36

日付: 2026-11-14（高速レーン第9回・第5バッチ）

## 主張

1. **(7,4) の行欠損witness帯を m=4..21 から m=22..35 に延伸**（SATソルバ不使用・構成的）。
   witness 幅集合は {4..35} を含み **M_{7,4} >= 36**
   （上界 1929・K0068 偶奇定理。M は [36, 1929]）。
   - m=22: 既知の m=21 witness（3系統検証済み）のブロック被覆が x=21 まで連続なため、
     **空列追加のみ**で witness になる（探索不要）。
   - m=23..31: 20石構成 CA（rows [3,3,3,3,3,3,2]・maxX=22・連続被覆 W=31）。
   - m=32..35: 20石構成 CB（maxX=26・連続被覆 W=35）。
2. **ブロック被覆補題**（本手法の中核）:
   - セル (x,y) がブロック済み ⟺ 3石を含む円または直線上にある
     （追加すれば4石曲線＝違反）。
   - ちょうど q-1 = 3石の行は行直線全体をブロックする。
   - 全7行が x が [0, W) で連続被覆され全石が x < W なら、S は maxX(S) < w <= W の
     **すべての幅 w で witness** である（極大性はセルの部分集合論法、
     安全性・行欠損は幅非依存）。
3. **検証**: 全幅 m=22..35 について純TS/BigInt 厳密計算（第3検証系と同じ方式・
   scripts/extend_band.ts）で safe（任意の円/直線の最大石数 3 < q）+
   maximal（未覆空点 0）+ 行欠損 PASS。負対照（4点共線）は正しく unsafe と判定。
   記録: output/verification.json。m=22..35 の witness は本バッチでは第3検証系
   単独での検証である（jsVerify/pyVerify による再検証は今後のrunで追加する）。

## 手法

- 純TS + BigInt の厳密有理数計算のみ（SATソルバ・repoコード不使用）。
- m=21 witness の行5,6のブロック被覆集合を厳密計算したところ x=21 まで連続で
  あったため、空列追加で m=22 witness が即座に得られた。
- 貪欲追加（予算2石・行容量 <= 3・min(row5,row6) <= 2・候補はギャップセルを通る
  「2石+ギャップセル」の円/直線上の整数点とギャップセル自体の占有）と
  決定的山登り（同一行内単石移動・受理条件は W 増加かつ W > maxX）で
  CA (W=31)・CB (W=35) に到達。途中、幅23..26 を埋めるため x-cap 付きの
  限定探索も実行した（幅23は18石構成でも到達可能、幅24..26 は CA が担う）。
- 探索はすべて決定的（乱数不使用）。検証は探索経路に依存せず構成のみに対して行う。

## 正直な負記録

- 幅 >= 36 は本バッチの探索では未達（CB からの単石移動山登りは W=35 で局所最適・
  改善なし）。不在の主張ではない。前線は **7x36**。
- band の連続性: 4..21（先行SAT実験）+ 22（空列追加）+ 23..31（CA）+ 32..35（CB）。

## 観測（全称主張ではない）

- 20石構成では C(20,3)=1140 円が各欠損行に高々2点ずつヒットし、1行あたり
  被覆容量は約 2280 セル。K0068 の上界 1929 をも下回る容量障害はなく、
  残る障害は「円と格子行の交点の整数性」という設計問題のみで、延伸余地は大きい。
- 構造は行0..5が各3石（自動ブロック）+ 欠損行6が2石。先行実験の
  [3,3,3,3,3,2,1] 型と同じ「満行＋欠損行」パターンで、q=4 の行容量上限 3 と整合。

## 範囲と限界

有限構成 + 厳密検証（探索はヒューリスティックだが、主張はすべて構成に対する
厳密検証に基づく）。m=36 以降の不在は主張しない。M の確定には前線評価と
上界 1929 の改善（K0342 型 tail 評価）が残る。
