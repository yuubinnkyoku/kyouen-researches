## 最小完全対応の独立最適性検査（2026-10-27）

`verify.py` は NetworkX で28頂点の最小重み完全対応を求めた後、
`alternating_cycle_check.py` で**別方式の整数のみの最適性検査**を行う。
この検査は NetworkX の最適性判定を呼ばず、渡された14辺の完全対応が
本当に最適かを確かめる。

任意の別の完全対応との対称差は、選択した14辺と非選択辺が交互に現れる
互いに素な偶数閉路に分解できる。より安い完全対応が存在すれば、
少なくとも1本の交互閉路の費用差は負になる。
選択した14辺を頂点対として縮約し、各対の入口・出口と訪問済み対集合を
状態とする部分集合動的計画法で、すべての単純交互閉路を検査する。
負の閉路がなければ、与えられた完全対応の最適性が証明される。

検査は非負整数の辺費用、全28頂点の一対一被覆、各選択辺の存在を確認し、
費用差の計算に浮動小数点を使わない。小規模の正例・負例・代替対応なしの
試験も含む。これは**条件付き14根の397辺という最小値の独立最適性検査**
であり、7石根の勝敗証明や11×11空盤の勝敗確定ではない。
