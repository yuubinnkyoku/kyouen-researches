# 標準11×11：9石の近傍6根を終局まで独立検証（2026-10-25）

**標準11×11空盤の勝敗はUNKNOWN。** 二石rootの新規閉鎖は0件。

先行する二つの9石WIN根（K0560、K0562）の一石交換近傍から、合法10石子が12〜20件の6根を選び、**各根の全合法子を終局まで再帰検証**した。すべての10石子は元先手WINであるため、9石根6件は元先手WIN（手番側LOSS）。各9石根から一石除去した8石親は、それぞれ9石WINへの合法着手を持つため元先手WIN。

| 9石AND根 | 6件（合法10石子数は12、15、19、20、20、20） |
| 延べ合法10石子 | 106件 |
| 相異なる10石子のD4類 | 106件 |
| 相異なる8石WIN親のD4類 | 54件 |
| 先行2根の8石WIN親との重複 | 6件（各根につき1件） |
| 先行2根に対する8石WIN親の純増 | 48件（先行17類→計65類） |

証明入力は s9-roots.keys（6件）、s10-win.keys（106件）、s8-win.keys（54件）。すべて128-bitのD4正準形で昇順、重複なし。検証器は、禁止四点のない局面か、合法子の**完全列挙と証明書集合の完全一致**、8石親から9石根への合法着手、全10石子の終局勝敗を確認する。WIN/LOSSを保存済み探索表から読み込まない。

verify.py は独立した4×4整数行列式（Bareiss法）、verify_3x3.py はK0560の別実装3×3差分行列式を使う。両者は全106葉で元先手WIN、各葉の合法着手数と終局探索状態数合計12,604が一致した。C++の4×4行列式検証器との照合は reproduce.sh に含めたが、今回の作業時点では未実行。

再現手順（リポジトリ直下）：

bash research/experiments/n11-batch-s9-terminal-20261025/reproduce.sh

--negative は、10石葉1件の欠落、8石親1件の欠落、異物の混入を拒否する試験。C++出力を渡した場合は全葉のWINと合法着手数を照合する。

凍結9石WIN 1,611類・凍結8石WIN 13,501類・凍結8石LOSS 294類との突合は実施済み。新6根と54親はこれらの凍結表に未収載で、WIN/LOSS矛盾は0。ただし別の終局証明集合との重複や7石被覆の純増は**未集計**。上記48件は先行2根との局所比較であり、研究全体の新規48件を意味しない。二石root、一石root、空盤の勝敗を導出していない。
