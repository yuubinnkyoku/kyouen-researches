# 残余評価への切替閾値の比較（2026-10-21）

K0493で構造別評価器単体の改善を確認した後、実際の探索全体で残余評価へ切り替える合法手数の閾値を比較する。未知の空盤探索・新しい盤面生成は行わず、保存済み局面を使う。

## 事前に固定した比較条件

- 入力正本: `research/experiments/n11-reduction-followup-20261005/output/n11-snapshots.json`。
- 合法手数6..18の各個数と手番偶奇で26層に分け、各層の最初の保存局面を調整用とする。同じ層の末尾から、調整用と異なるtrial・異なる占有集合の局面を確認用に選ぶ。合計52局面。
- 全52局面の期待Grundy値を、残余評価器を使わないPythonの占有部分集合mexで計算する。元先手固定視点の勝敗へ変換して保存する。
- 比較する閾値はOFF（0）、6、8、10、12。共有キャッシュと上位局面cacheは使用しない。各行は新しいsolverと空のmemoで実行。
- 各rootの探索ノード予算は5000、各設定3回。繰返しごとに設定の実行順をずらす。wall timeoutは各52行の実行で120秒。timeoutや解析失敗をUNKNOWNへ読み替えない。
- 各rootで時間中央値を取り、その和を比較。UNKNOWN数が最小、次に探索時間の和が最小となる閾値を調整用だけで選び、確認用では同じ閾値の結果を別集計する。すべての確定勝敗が独立Pythonの期待値と一致することを要求する。

`fixtures.json`, `input.csv`, `protocol.json` は測定前に固定した局面・期待値・入力SHA-256。`run.py --prepare-only` で再生成できる。

## 時間の測定範囲

従来の `replay` CSVのwall_sは初期化を含む秒単位の整数であり、小さい局面の差を判定できない。CSVの列を保ったまま、追加コメント `# replay_timing` に以下を記録する。

- setup_us: solver作成・設定まで。
- solve_us: `exact_replay` 呼出し全体。盤面探索から残余構成・構造認識・mex評価までを含む。
- total_us: 初期化から診断出力・solver破棄までの行全体。

比較の主指標はsolve_us。total_usも併記し、初期化費用を含めた実行全体の改善と混同しない。異なる閾値では残余側の再帰作業が親の探索ノード予算に算入されないため、ノード数の減少だけでは高速化と判断しない。残余呼出数・memo登録数も記録する。

## 再現

```sh
python3 research/experiments/residual-gate-calibration-20261021/run.py
```

C++20 / -O2で現行solverを一度コンパイルし、固定した15バッチを順次実行する。`--solver PATH` で事前コンパイルした同じ実装を指定できる。各バッチのraw CSV、全測定行、集計を本ディレクトリへ保存する。チェックは確定勝敗の一致、行数・予算・閾値、時間の整合性、繰返し間の結果・ノード数・残余計数の一致を含む。

この保存局面標本から、全11×11局面に共通する最適閾値や空盤勝敗を主張しない。実測が出るまでは既定値を変更しない。

## 深い既存rootの補助検査

小さい保存局面の時間測定と別に、前実験・既存CIで使ったS5の3rootを各5000ノードで再実行する。比較閾値は同じOFF/6/8/10/12、各1回。これは新しいrootの探索ではなく、既存rootの予算を小さくした固定回帰である。調整用52局面の選択規則は変更しない。

`stress-protocol.json` と `stress-input.csv` は実行前に固定する。元CSVで0だったlegalメタデータは既存幾何実装から再計数する。判定・実ノード数・探索時間を `stress-summary.json` へ保存する。1回の時間測定から厳密な速度比を主張しない。UNKNOWNから確定したrootがあれば、新しい証拠として採用する前に別途独立検証する。

```sh
python3 research/experiments/residual-gate-calibration-20261021/stress.py \
  --solver /tmp/kyouen-gate-calibration
python3 -m unittest discover -s research/experiments/residual-gate-calibration-20261021 -p test_protocol.py
```

プロトコルの6テストは、確認用の値が設定選択へ混入しないこと、UNKNOWN数の優先、反復計数の不一致、勝敗矛盾、予算の不一致、不可能な時間の棄却を検査する。計測バッチは順次実行し、主実験と補助実験を並行して時間比較しない。

この結果に基づき、**既定の `--residual-exact-legal=0` を維持する**。高い閾値への変更は行わない。構造別評価器単体の改善はK0493の測定範囲で成立するが、切替のための仕事も含めると本標本の時間は増えた。通常探索は勝敗だけを短絡判定できる一方、残余kernelは全Grundy値を計算するため、仕事量も同一ではない。

初期化費用の全52行合計は約27秒で、測定した探索時間は合計7〜38ms。このため、行全体のtotal_usの揺らぎから全体高速化を主張しない。正規化済みの小さい残余集合が安価に得られる場面など、別条件での閾値は未検証。残余構築・構造認識・Grundy評価を分けた時間測定も今後の課題である。
