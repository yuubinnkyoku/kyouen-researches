# 未確定28極性衝突の幾何・計画影響ランキング

K0417の修復後19-root共同LOSS計画と、K0420の保存済み初手49 WIN証人集合を固定し、
K0423で解決した209644を除く28候補を測定した。solver探索は行わない。
当時の入力hashと実装hashを `output/ranking.json` に固定し、既存実験・knowledgeを変更しない。

## 結果と投入順

28件はすべて修復後31,636要求集合にも残っている。
全28件で、LOSSなら保存WIN被覆の少なくとも1分岐が唯一の証人を失い、
WINなら現行LOSS計画の少なくとも3選択が失効する。
したがって、旧29件から単に解決済み1件を取り除いた後も、28件すべてが固定された二計画の判断点である。

親安定化群位数は、13件が2、15件が1。正準S6子数は39〜102。
子数優先順位の先頭は144193（39子）、115540（40子）、126899（41子）、143240（42子）。
単位子数あたり影響 `(WIN時のLOSS計画失効選択数 + LOSS時の保存WIN被覆欠落分岐数) / 正準S6子数`
では、144692（10/49）、115540（8/40）、144311（8/44）、120370（17/100）、144193（6/39）が先頭。

最初の投入は **144193 → 115540 → 144692** を推奨する。
144193は幾何的幅が最小、115540は次に小さく影響が大きい。
144692は49子で3初手root・8選択に影響する。
子数最小化と総影響最大化の2目的でPareto非支配なのは、144193・115540・144692・221294・120370の5件。
221294は90子で3初手root・8選択に影響し、LOSSなら保存WIN被覆4分岐が欠落する。
120370は100子と幅が大きいが、LOSSなら保存WIN被覆14分岐が欠落するため、その後の高影響候補である。
この投入順は探索時間・実勝敗の予測ではない。

表の「新たな無料分岐」は、候補がそのS4の合法S5子である全出現を数える。
同じ応手の保存証人に登録されていない出現も、WINが実際に証明された場合には無料化できる。
「欠落分岐」は応手ごとの保存証人集合から当該候補だけを取り除いたとき、
既知WINも代替保存証人も残らない具体fourth分岐数。
代替S5・別thirdを探した結果ではなく、保存被覆の脆弱性である。
計86分岐が各候補に唯一依存するが、28局面のLOSSを証明したわけではない。
28親の正準S6子incidenceは1,960、和集合は1,867。
共有93子はすべて2親に属する。全S6の求解を必須とするものではない。

28通りの単独WIN仮定について、失効したS4を全選択肢から排除し、
残存選択の和集合を出発点に決定的greedyで修復した。
すべて19 root・2,261 thirdを覆う実行可能計画が残り、要求増加は40〜111件。
28件の同時仮定や全体最適化は行っていない。
各候補がLOSSなら、他の選択を変えず31,635未確定要求へ1件減らせる。

## 再現・独立検査

```sh
python research/experiments/n11-conflict-ranking-20261013/scripts/rank.py
g++ -std=c++20 -O2 \
  research/experiments/n11-s5-s6-quotient-20261013/scripts/verify.cpp \
  -o /tmp/n11-conflict-ranking-verify
python research/experiments/n11-conflict-ranking-20261013/scripts/verify.py \
  --binary /tmp/n11-conflict-ranking-verify
```

`rank.py` は独立整数幾何Boardで28親の全合法追加・安定化群・正準S6子・具体手を再生成し、
K0422の独立C++検査済み入力と一致確認する。
初手49の保存chosen-thirdにおける全7,519具体fourthを列挙し、
候補および既知WIN209644の正準predecessorに該当する177分岐・71相異なるS4で被覆を計算する。
現行LOSS側の影響境界と条件付き代替に用いた56 S4では、
全S5子を明示cacheと照合し完全な費用集合を再検査する。

`verify.py` はBoard・solver・rank.pyをimportせず、直接D4画像の包含判定で
保存WIN被覆の影響を再計算する。
幾何合法性は平行移動3×3行列式、28親の幅は既存の別実装C++で確認し、
28通りの保存済み条件付き修復を元計画に適用して要求集合数と具体合法fourthを照合する。
合法数改変はC++で拒否する。検証receiptは `output/verification.json`。

`output/ranking.tsv` は完全表、`output/ranking.json` は候補ごとの全具体分岐・代替・hash。
本実験は局面の新勝敗を得ておらず、11×11空盤はUNKNOWNのまま。
cache葉は従来どおりsolver-trusted、二つのパイロット追加は既存の独立終局検証receiptに依存する。
