## 再利用する証明

`n11-gap6-terminal-20261019/gap6-terminal-cert.json` は、2026-10-19に独立C++/Pythonで検証された8石WIN 18件・8石LOSS 1件を含む。既存の7石被覆監査には未統合だった。

今回、`n11-gap6-terminal-20261019/verify_js.js` を新設し、外部cache・保存済み勝敗表を使わず、整数行列式、D4正準化、全合法辺、10石以降の終局再帰をJavaScriptで再実行した。

| 検証項目 | 結果 |
| --- | ---: |
| 8石WIN根 / 8石LOSS根 | 18 / 1 |
| 8石WIN根の9石証人に必要な10石WIN葉 | 337 |
| 8石LOSS根の全9石義務 | 26 |
| LOSS根から到達する全10石境界 | 243 |
| 境界のWIN / LOSS | 200 / 43 |
| 選択したLOSS葉 | 15 |
| 異なる10石終局再計算 | **580（WIN 537 / LOSS 43）** |
| 10石ごとのメモ化状態数の合計 | **53,256** |
| WIN/LOSS判定不一致 | 0 |

26義務に対する半整数双対重みの総和は30（=15葉）で、実際のLOSS候補43件の各被覆重みは高々2。選択した15葉が全26義務を覆うため、**指定した10石一手応手形式では15葉が厳密最小**。元のPython検証と状態数53,256も一致した。

このJavaScriptは独立の再帰実装だが、円の判定にはPython側と同じ3×3整数行列式を使う。既存C++側は別の4×4行列式を使用している。終局の再計算をせずに勝敗を昇格した局面はない。

## 7石への被覆統合

`audit.js` は直前の `n11-terminal-s7-fifth-win-union-20261024/audit.js` の全基準検査を継承し、今回の18個の8石WINと1個の8石LOSSを追加する。すべての7石親と合法8石子を再生成し、D4同値、被覆辺、既知LOSSとの極性衝突を検査する。

| 指標 | 直前 | 今回 | 差分 |
| --- | ---: | ---: | ---: |
| 終局証明由来の8石WIN類 | 1,210 | **1,228** | +18 |
| 終局証明由来の8石LOSS類 | 38 | **39** | +1 |
| 7石WIN候補の親類 | 4,971 | **5,111** | +140 |
| 証明済み7石→8石着手辺 | 9,682 | **9,826** | +144 |
| 証明済み7石→8石親子類辺 | 9,680 | **9,824** | +144 |
| 8石LOSSから逆向き導出した7石LOSS類 | 268 | **274** | +6 |
| 全合法子をWINで閉じた7石類 | 6 | **6** | 0 |
| WIN/LOSS衝突 | 0 | **0** | 0 |

7石LOSSの+6は、**直前の38個の8石LOSSからの逆向き集合との比較**。全リポジトリで初めて証明されたという意味ではない。8石WIN 18件・LOSS 1件も過去の証明を再利用したものであり、今回の新規勝敗確定ではない。

最小未被覆は既知LOSSを除く**18対称類**のまま。不足数は勝敗・証明距離ではない。7石の新規閉包、二石rootの閉鎖はない。
