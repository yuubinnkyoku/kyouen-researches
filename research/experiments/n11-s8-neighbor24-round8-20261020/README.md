# 標準11×11：8石近傍第8回・24根の独立終局証明

2026-10-20。基準GitHub main `de118227d3e06c39b64515be556ab790eb55e498`。完全指摘・標準q=4・通常プレイ。WIN/LOSSは**元先手固定視点**であり、石数8はOR、9はAND、10はOR。**空盤の勝敗はUNKNOWN**。

既知6個の8石LOSSを一石交換して得られる正準候補2,047局面から、既存の選定済み139局面を除外し、9石合法手の少ない順に24局面を選定。全24局面を終局まで独立に検証した結果、8石WIN **20**、8石LOSS **4**。新しい二石rootは閉じていない。4個のLOSSから正準7石親31局面が元先手固定視点LOSSと導出でき、保存済みの過去26個の8石LOSSから未導出だったものは28局面。GitHub mainの8石WIN 13,501、8石LOSS 294、7石LOSS 2,232、7石WIN 17との照合では今回の根・親に重複または衝突なし。ただしmainの全S10 cacheとの照合は行っていない。

C++は盤面の整数行列式を着手ごとに直接計算、Pythonは残余禁止集合を構築して再帰。最初の証明は382個の相異なる10石葉（状態数合計28,416）だった。4個の8石LOSSの81個の正準9石義務について全595個の合法10石候補を両実装で終局まで計算（WIN402、LOSS193、状態数28,278、不一致0）。LOSS葉193候補から41個を選ぶ被覆が存在し、81義務への非負半整数双対の総和81/2、各LOSS候補での重み和≤1を**Python整数演算で独立検証**。従って41葉はこの4根の10石一手応手形式で**大域最小**（下界ceil(40.5)=41）。

20個の8石WIN根については、全3,975個の正準10石境界候補をC++で計算し、74個の有効9石証人候補を列挙。共有葉数を最小化する整数計画から262個のWIN葉を選定した。ただし**262の大域最小性は独立には証明していない**。4 LOSS根の41葉と合わせて303葉・状態数16,404へ削減（79葉・12,012状態、各20.68%・42.27%減）。独立Pythonが303葉すべてを終局まで再計算し、C++結果と一致した。全3,975候補のPython独立再計算は実施していない（うち595 LOSS根境界は全件独立再計算済み）。状態数は探索の費用であって勝敗距離ではない。

前回の保存済み10石結果5,561件と、今回のC++計算3,975件をキー・勝敗・状態数で照合。重複63件は全て一致し、新規3,912件、衝突0。ただしmainの51,571件への新規数ではなく、**今回の3,975件のうち全件Python独立検証済みと誤認しない**。

## 再現

Python 3.10以上・C++20コンパイラと標準ライブラリだけで `bash reproduce.sh`。全303証明葉の独立再帰、全595候補の独立再帰、半整数双対、31個の7石親、4種類の改変拒否、303葉のC++再計算を行う。`FULL=1 bash reproduce.sh` で全3,975候補をC++再計算。`PY_FULL=1 bash reproduce.sh` で全3,975候補をPython独立再計算する（長時間）。SciPyは再現・検証に不要。`optimize_*`、`make_loss4_dual.py` は候補生成・最適化専用でSciPyを要する。

`proof24_optimized.tsv` は完全なAND/OR証明の辺表、`loss4_dual_halves.tsv` は最小性の双対、`loss4_all_s10_cpp.tsv` は全候補表、`proof_s10_cpp.tsv` は選定303葉のC++再計算結果。`prior_s8_loss26.txt` は前回までの保存資料から再構成した比較集合で、main既知集合の代わりにはならない。`SHA256SUMS` が添付ファイルの内容を固定する。
