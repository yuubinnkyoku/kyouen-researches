## 確定した局所結果

`s9-roots.keys` のD4正準9石局面12件は、いずれも元先手WIN
（9石では後手番なので手番側LOSS）。合法10石子は延べ270辺、
相異なる264類。**264類すべてを終局まで解き、手番側WIN**だった。
12根から一石戻した合法8石WIN親は相異なる101類で、それぞれ
少なくとも一つの合法9石WIN着手を持つ。

## 証明書と独立性

`s9-roots.keys` が固定入力で、`verify.py` はそのSHA-256を照合する。
全合法10石子、全8石親、合法な逆向き証人を盤面から再生成し、
二つの**別々の整数幾何実装**（3×3差分行列式と4×4 Bareiss法）
で安全性・D4正準化・合法手を照合する。各10石子を保存勝敗表なしで
終局まで再帰し、両実装の勝敗・合法手・状態数の一致を検査する。
証明書の子集合・親集合の欠落や混入は負の試験で拒否する。

導出集合のSHA-256（昇順32桁hex、各行改行）：

- 9石12根：`d72f0c7e204502cc6ae442955cf2558d11964cff3443c2ad15683243d2d78a05`
- 10石264葉：`b39045f33e288c424747df293131d7aaa50678d1e09493fe4baa35ea5d7af231`
- 8石101親：`aa53bb0c49fba88ada30ce366eee3dd71331eb0dd5da0e2b38bc9b59254311ac`

再現：

`python3 research/experiments/n11-s9-batch12-terminal-20261026/verify.py --negative`

候補選定は既知の9石WIN根4件の一石交換近傍1,432類から、
合法10石子数と既知の局所終局葉との重なりで順位付けした。
候補の選定は勝敗の証明に使用していない。既存の9石鍵ファイル
10件（110根）および凍結9石WIN 1,611類には12根の重複がなかった。
101個の8石親は凍結8石LOSS 294類と矛盾せず、凍結8石WIN
13,501類とも重ならない。ただし**研究全体の証明限定8石WIN集合に
対する純増は未集計**。7石の全子被覆・二石rootの新規閉鎖も未確認。

作業環境では独立した3×3整数行列式の残余手マスク探索と、
4×4整数行列式の盤面再帰で264葉のWINと状態数39,067が一致した。
リポジトリ内の正式な二実装検証器のCI結果は別途確認する。
