# {1,1}全R崩壊定理(ones-pair total collapse): H(R;(1,1);z) = v(2,z,R) for all z,R>=0

実験: ones-pair-total-collapse-20261123(2026-11-23、単一オーナー宣言 commit 284d82c6 配下・publish-then-execute)
作成名: Vibe 高速レーン(定時自律実行)

## 命題(定理・全称)

全ての z>=0 と全ての R>=0 に対して

    H(R;(1,1);z) = v(2,z,R)

が成立する。ここで v(x,z,R):=H(R;(x);z) は単一トークン残余ゲームの値
(K0832出版の閉形式)である。すなわち {1,1} 行はK1264階段定理の窓
R<=z+min(X)=z+1 をbypassして**全R**で単一トークン(2)残余に崩壊する。
K1264 reportの未解決・次課題2「{1,1}の無分離観察の全称化」の閉包。

**この定理の全称性は本報告書の構造的帰納法による。** 機械監査は証明そのものでは
なく、エンジン・アンカー・限界ケースの独立照合である(AGENTS.md規定の区別)。

## 記法・定義域

残余ゲーム H(R;X;z) は K0832/K1138系の検証器と同一の再帰で定義する(K1264と同一・再掲):
- H(0;X;z)=0。
- 各手は残容量を1消費し、子は R-1 で評価する:
  - A手: トークン a>1 を a-1 に減らす(z不変)。
  - B手: トークン a=1 を除去する(z -> z+1)。
  - C手: z>0 のとき選択肢値 1 XOR H(R-1;X;z-1) を追加する。
- H(R;X;z) = mex(子の値の集合)(重複子は集合で潰れる)。

## 補題E(空残余・K1264再掲)

H(R;空集合;z)=0(任意の R,z>=0)。∎(K1264と同一証明)

## 補題V1(単一トークンx=1の残余の完全特徴付け・本証明の唯一の解析的成分)

全ての z,n>=0 に対して v(1,z,n) は次で完全に決まる:

    v(1,z,0) = 0
    v(1,0,n) = 1        (n>=1)
    v(1,z,1) = 2        (z>=1)
    v(1,z,n) = 1        (z>=1, n>=2)

証明: nについての帰納。x=1 の選択肢は B手(トークン除去で子は
H(n-1;空集合;z+1)=0・補題E)と C手(z>=1で 1 XOR v(1,z-1,n-1))のみ。
よって v(1,z,n)=mex({0}∪({1 XOR v(1,z-1,n-1)}|z>=1))。
n=0 は定義(K1264同様)。n=1: z=0 なら mex({0})=1。z>=1 なら
mex({0, 1 XOR v(1,z-1,0)})=mex({0,1})=2(zに依存しない)。
n>=2: 帰納より v(1,z-1,n-1)∈{1,2}(n-1>=1)。値1なら子 1 XOR 1=0 で
mex({0})=1。値2なら子 1 XOR 2=3 で mex({0,3})=1。いずれも 1(zに依存しない)。∎

**系(補題Zのx=1版が全nに拡張される)**: z>=1 なら全ての n>=0 で
v(1,z+1,n)=v(1,z,n) が成立する(n=0:0=0・n=1:2=2・n>=2:1=1)。
K1264補題Zはこの主張を n<=z に制限していたが、x=1 では窓外でも破れない。
z=0 の n>=1 では v(1,1,n)≠v(1,0,1) のケースが1点だけ残る(n=1: 2 vs 1)。

## 定理の証明(R強帰納・各段階でzは全称)

R=0 は両辺0。R>=1 とする。{1,1} 側の選択肢は:
- B手(1トークン除去・z->z+1): 子値 v(1,z+1,R-1)。
- C手(z>=1): 1 XOR H(R-1;(1,1);z-1) = 1 XOR v(2,z-1,R-1)(R-1 に関する帰納法)。

単一トークン(2)側 v(2,z,R) の選択肢は:
- A手(2->1): 子値 v(1,z,R-1)。
- C手(z>=1): 1 XOR v(2,z-1,R-1)。

C対は完全一致。残りを比較する:

**z>=1**: 補題V1の系により v(1,z+1,R-1)=v(1,z,R-1)(全n成立)。よって選択肢
集合は完全一致し、mex は等しい。

**z=0**: C手は双方に存在しない。{v(1,1,R-1)} と {v(1,0,R-1)} の mex を比較:
- n=R-1=0: {0} vs {0}・mex=1=1。
- n=1: {2} vs {1}・mex=0=0(分子値が単一側と異なるのは全領域で丁度この1点
  だが、どちらのmexも0)。
- n>=2: {1} vs {1}・mex=0=0。
全ケースで mex は一致する。∎

** remark: 証明はK0832閉形式を使わない(補題V1は生再帰から直接導く。閉形式は
機械監査のアンカーとしてのみ使用)。z=0,n=1 の丁度1点だけ定理の分子値が
単一トークン側と異なるが、mex不変量がこれを吸収する構造である。∎

## 系

1. **{1,1}行はK0832閉形式を全Rで継承する**: H(R;(1,1);z) の値は
   K0832出版閉形式 single_token(2,z,R) で全 z,R>=0 について閉じる。
2. **{1}^t 構造対比(有限census・監査D4)**: t=1 は恒等(単一トークンそのもの)、
   t=2 は本定理で全R崩壊。t=3,4 は z=0,R=3 の分離が本定理・閉形式からの
   直接計算で確定(t=3: B子H(2;{1,1};1)=v(2,1,2)=1で親mex({1})=0 vs 単一
   v(3,0,3)=1・t=4: B子H(2;{1}^3;1)=1で親0 vs 単一1)。t=5,6 は D4 census
   範囲内の観測(初分離位置は t=3..6 すべて (z,R)=(0,3)・親0 vs 単一1)。
   **アリティ2の全一対が特異**。
3. **y=1ファミリーの特異行**: K1264 C4 census でy=1行(x>=2)は境界+1 R=z+2 で
   180点の分離を示したのに対し、(1,1) 行だけは全R無分離。y=1ファミリーで
   全R崩壊する行は (1,1) のみ(x>=2行はK1264 C4掃引範囲の境界+1で180点の分離・観測)。
4. **K0832 R<=2全z条款との統合**: (1,1)行は max(z+min(X),2)=max(z+1,2) 窓を
   そもそも必要としない(全R保証)。K1264課題3の統合窓鋭さ問題から (1,1) 行が
   除外された。

## 誠実記録

1. **宣言点数算術のドリフト3箇所**: 宣言ノート(284d82c6)の機械算出総照合点
  70,595 に対し、実装後の実測は 67,513。内訳: D3 は「400点+100点×3比較」という
  本文protocolどおり 1,500 が正しいのに宣言合計では4,500と3倍に誤算上していた。
  D4 は本文「R 0..z+10」(実装どおり)に対し点数計算だけ R 0..z+11 で行って
  1,700 と出していた(実測 1,615)。D5 は published_expect を持つ3アンカーが
  期待値照合+1点を持つため均一5点/anchorでなく 33 が正しい(宣言30)。
  本文protocol(範囲・比較内容)はすべて実装どおりであり、ドリフトは点数の
  算術のみ。機器は宣言と一致、点数は上記実測値が正本。
2. **run4(env -i)のPATH事象**: 決定性4回目の env -i 実行は PATH=/usr/bin:/bin
  では python3(/usr/local/bin)に届かず1回失敗、PATH=/usr/local/bin 追加で
  再実行し byte-identical 確認。audit本体には影響なし。
3. **宣言前探査(宣言ノートに開示済み・再掲)**: 証明骨子の解析的導出と
  probe_ones.py グリッド(補題V1 4,305点 bad 0・{1,1} 2,025点 bad 0・
