# 7×7×7・共平面/共球面5点禁止版の未解決境界

2026-10-22。基準main: `ee649b3e`。現在の問いの正本はK0505。
5×5×5までの弱解決と全偶数辺長の構成的戦略はK0503・K0502を参照。

点の番号は `(x*7+y)*7+z`。2石根 `{0,5}`、座標 `(0,0,0),(0,0,5)` を探索した。
**この2石根も空盤も未解決である。** UNKNOWNは勝敗の根拠にしない。

## 幾何学的な境界

`four_ply_frontier.py` は各第三手cに対して4石を共円または共線にできる応手dを
全探索する。持ち上げ4点のアフィン階数≤2を四つの3×3小行列式で検査する。
階数≤2なら、任意の5点目を加えても5×5行列式は0なので4石終局である。
逆に階数3なら、持ち上げた盤全体のアフィン階数が4のため合法な5点目がある。

`coverage-7.json`: 全341第三手のうち306個は終局4石への応手を持つ。
残る35個は全て `z=6` の境界面上にある。`z≤5` の第三手には `z→5−z` の
鏡像応手で共円または共線4石を作れる。境界面の35手はこの4石終局戦略では
処理できず、深い探索または別の戦略が必要である。

## 増加予算のexact probe

`probe.cpp` は343点を6個の64bitワードで扱い、48対称性で正規化する。
5×5×5用実装の全四点前計算（7立方では566,685,735四点組）を避け、
探索で必要な四点組だけ、持ち上げ行列の余因子から禁止追加点を生成してcacheする。
勝敗はexact P/N再帰、着手順は子の合法手数・正規化maskの昇順。
UNKNOWNを確定memoへ挿入しない。

| node上限 | 四点cache上限 | 展開数 | 確定memo数 | 四点cache数 | 結果 |
|---:|---:|---:|---:|---:|---|
| 1,000,000 | 4,000,000 | 76,189 | 103,039 | 4,000,000 | UNKNOWN（幾何上限） |
| 1,000,000 | 20,000,000 | 1,000,000 | 1,359,510 | 18,881,241 | UNKNOWN（node上限） |

2回目は1回目より幾何上限を上げた独立processで、cacheの継承はない。
memoは探索中の確定値であり、その全体を独立検査済み証明書として配布したものではない。
根が閉じなかったため勝敗証明書は生成していない。

```sh
g++ -O3 -std=c++17 -Wall -Wextra -Werror research/experiments/cube-q5-seven-probe-20261022/probe.cpp -o /tmp/q5-large
/tmp/q5-large 7 1000000 20000000 /tmp/q5-large-7.cert 0 5
python3 research/experiments/cube-q5-seven-probe-20261022/four_ply_frontier.py 7 0 5
```

## 検査と限界

`regression.py` は独立Pythonの24置換4×4行列式で、7立方上の104四点配置の
全343追加候補、合計35,672候補を照合する。word境界を跨ぐ終局円・直線と
固定seed20261022の100標本を含む。また既知3立方の全20二石軌道をPと判定し、
生成証明書を既存の独立Bareiss検査器で検証する。予算0はUNKNOWNになる。

```sh
g++ -O3 -std=c++17 -Wall -Wextra -Werror research/experiments/cube-q5-weak-20261022/verify_certificate.cpp -o /tmp/verify-q5
python3 research/experiments/cube-q5-seven-probe-20261022/regression.py /tmp/q5-large /tmp/verify-q5
```

7立方の幾何照合は全四点組の網羅検査ではない。3立方の証明書形式は既存の
Q5CUBE1を使う。大盤で根が閉じた場合の出力Q5CUBE2（6ワードmask）の独立
証明書検査器は今回作成していないため、将来その根を解決済みとして採用する前に
追加検査を要する。今回の二つの7立方探索はいずれもUNKNOWNであり、Q5CUBE2を
出力・採用していない。

probe計算の後に `--legal` の幾何比較用モードだけを追加した。探索部分は同一。
実行binaryと最終source・データのSHA-256は `manifest.json` に記録する。
次の作業は35第三手境界からの証明構築、確定memoの保存・独立検査、幾何cacheの
圧縮、または奇数盤全体の構成的戦略であり、単なるUNKNOWN再実行を成果とはしない。
