# 11×11：既存二石LOSS証明の別実装監査と三石WIN候補の除外

`verify.js` は次の4資料をGit blob SHAで固定して再検証する。

- 2026-10-12凍結S5 exact cache（5,851類、WIN159 / LOSS5,692）
- 保存済み別系統S5 cache（WIN5差分2類）
- 二石root `{60,27}` の既存LOSS証明書（119第三手・32個のLOSS4応手）
- 差分WIN5から導出した6個のWIN4証人manifest

幾何判定は4×4行列式を使う前回の監査器とは異なる、差分座標の**3×3整数行列式**で行う。64-bit局面鍵はJavaScriptの`Number`へ変換せず`BigInt`で読む。D4正準化、全合法着手、極性、証人の合法性、WIN/LOSS矛盾を再計算する。

```sh
node research/experiments/n11-s3-loss-guard-root-audit-20261031/verify.js
```

## 独立再計算する範囲

- `{60,27}` の119合法第三手すべてに、既存の32個のLOSS4から合法な応手が存在すること。
- LOSS4・32類の**全合法S5子3,297辺**が、固定S5 cacheでLOSSであること。
- WIN5・159類→WIN4・549類、別系統のWIN5・2類を加えたWIN4・555類、差分6類。
- 差分WIN4・6類の一石除去が改善するS3親は18類、S3→S4のWIN4被覆辺は24本増加。既知WIN4子を持つS3親は609→615類。
- 18類のうち**4類には既存のLOSS4応手**がある。よってこの4類はS3 WINの候補ではない。未除外14類の最少未被覆WIN4子数は110類（除外前は14類）。
- 既知WIN4と既存LOSS4の重複は0。LOSS4子の極性を改変すると検証は失敗する。

最も見かけの被覆が進んだS3 `{56,60,63}` は、合法S4子55類中41類がWIN4だが、S4 `{0,56,60,63}` は105個の合法S5子すべてLOSSと既存cacheで確定している。したがってこのS3は既にLOSSであり、残る14類をWIN化してS3 WINを目指す探索は誤り。

## 信頼境界

**新しい勝敗証明ではない。** 119第三手と3,297辺の幾何・AND/OR伝播を別実装で再検算するが、S5の勝敗は過去のsolver-trusted exact cacheを葉として使用し、終局まで独立再探索していない。既知の二石root `{60,27}` 以外の二石rootは閉じない。標準11×11空盤勝敗は **UNKNOWN**。
