# 標準11×11：三点索引による10石終局計算の高速化（2026-10-16）

標準q=4・完全指摘・通常プレイ。既存4件の8石LOSS証明から生成できる2,325個のD4正準10石局面が対象。**新たな二石rootは閉じておらず、空盤勝敗はUNKNOWN。**

## 手法

95,670個の禁止四点組を起動時に一度だけ列挙し、287,980個の三点組ごとに、禁止四点組を完成させる第四点の121-bit集合を保存する（約4.6MB）。各10石局面の合法手は既置石三点組120個に対応する集合の和集合から計算。禁止2・3・4点組も同じ索引から生成し、幾何的に禁止と判明した候補に限って既存禁止部分集合を調べる。探索順、終局の再帰、局面ごとの探索表は従来と同じ。

## 検証

- 全8,495,410四点組で索引の4通りの参照結果が整数行列式と一致。禁止四点組95,670個。
- 4件の8石根から10石候補2,325個を再生成。入力SHA-256: 6f740634c6d89441e8ef379b6d5363cc78b9e7cd67c24b9dd250c0507d57f9b6
- 全2,325局面のWIN 1,753 / LOSS 572、合法手数、各局面の評価状態数が従来C++版と行単位で一致。全状態数2,650,365。出力SHA-256: 94aa731461706e0ca023fc59bd9b475df155f184a92143e8d2ce195e6401aa8b
- 別実装Pythonで過去に再計算した全2,325局面の勝敗・合法手数とも一致（独立Python出力SHA-256: 79a2f285a78e6601ccc8ddfb341c384ca91698b99faac31b1f22ea0b866b9065）。そのPython実装は過去の未統合 n11-incremental-legal-20261016.zip にあり、この実験単体では再実行しない。
- 全2,325局面の探索状態ごとに増分合法手集合を禁止組の直接走査と照合。全根の合法手・安全性も整数行列式で照合。入力欠損・不正石集合の拒否を確認。

## 実測

同じ共有計算環境、g++ -O3 -std=c++17、交互順で6回ずつ実行。起動・索引生成・出力を含む中央値：

| 方法 | 中央値 | 従来比 |
|---|---:|---:|
| 従来の合法手差分更新 | 2.144秒 | — |
| 禁止組判定順の入替のみ | 1.636秒 | −23.7% |
| **三点索引** | **0.396秒** | **−81.5%（約5.4倍）** |

全方式の評価状態数は同じ2,650,365。改善は探索木の削減ではなく、幾何前処理の再利用によるもの。S5探索や二石root全体へ同じ倍率が適用できるとは限らない。生の測定値は benchmark.json に保存。
