# pg25-s4-orbit-census-20261128 — PG(2,5) s=4 極大safe集合・最小2重ブロッキングの PGL(3,5) 軌道分類 (全数)

宣言: research/log/2026-11-28-pg25-s4-orbit-census-declaration.md (commit 26d82430aa35fb69dadf58ce5c10be2c841c3de9, 宣言時HEAD 709c8515)。所有セル: K1370 レジューム (c)「PG(2,5) s=4 の軌道分類」。他レーン (n11 系・8x29 系・Baer 系) とは非衝突。

定義 (K1365/K1370 と同一): S が s-安全 ⟺ 全直線が S の点を ≤s 個含む。極大安全 ⟺ s-安全でどの点も追加できない。C が t=l-s 重ブロッキング ⟺ 全直線が C の点を ≥t 個含む。極小 ⟺ どの点も除去できない。PG(2,5): n=31, l=6 (直線長), s=4, t=2。

## 手法

1. **scripts/enum.c** (zig cc 0.13.0 build): PG(2,q) の点・直線を正準射影座標で構成し、31点の include/exclude DFS + 直線カウント枝刈り (>s 即枝刈り) + full-line witness カウンタで極大性を葉で判定し、極大 safe mask (uint32, 正準ラベリング) を全件ダンプ。各 mask の補集合の 2重ブロッキング性・最小性も定義直接検査 (fail-closed)。PG(2,3)/(2,4) も同一コードで較正実行可。
2. **scripts/orbits.js** (Node.js): 生成元 4個 (shear×2・座標cycle・対角) で |PGL(3,5)| = 372,000 全要素を BFS 構成して位数検証し、1,587,975 mask をサイズ別に軌道分割。各軌道の安定化群位数は 372,000 全要素での固定元全数で直接計数 (orbit-size × stab = 372,000 を fail-closed assert)。生成元集合を変えた再分類で分割独立性を検証。
3. **scripts/verify.py** (Python・アフィンモデル): C と異なる点ラベリング (z=1 の25点 + (1,m,0) 5点 + (0,1,0)) で PG(2,5) を再構成。ラベリング写像は fail-closed (C 直線の像が全てアフィン直線)。mode `verify <size>`: 当該サイズ全 mask の安全性・極大性・補集合の最小DB性を定義直接再検査。mode `orbit <size>`: Python 独自生成元で PGL(3,5) を再構成 (位数 372,000 検証) し、サイズクラス全体を独立に軌道再分割して JS 分類 (サイズ multiset + rep 所属・rep 軌道サイズ) と照合。

## 主張 (有限全数計算)

個数 (K1370 と完全一致): 極大 safe 13:15,500 / 14:372,000 / 15:604,500 / 16:595,975 (計 1,587,975)。最小2重ブロッキング 15:595,975 / 16:604,500 / 17:372,000 / 18:15,500。

**軌道分類 (全数・今回新規)**: PGL(3,5) (位数 372,000) 作用下で 全 1,587,975 mask は **13 軌道** に分かれる。

| size | 軌道サイズ (個数) | 安定化群位数 |
|---|---|---|
| 13 | 15,500 (×1) | 24 |
| 14 | 372,000 (×1) | 1 (regular) |
| 15 | 186,000 (×2), 124,000, 93,000, 15,500 | 2, 2, 3, 4, 24 |
| 16 | 186,000 (×2), 124,000, 93,000, 3,100, 3,875 | 2, 2, 3, 4, 120 (S5型), 96 |

- line-histogram は軌道不変量だが完全不変量ではない: size-15 の軌道 2 と 3 は同一 hist [0,5,6,7,13] で別軌道。
- size-16 の 3,100 軌道 (安定化群 120 = S5 型) と 3,875 軌道 (96) は小さい安定化群をもつ特異族。
- 補集合双対 (K1365): 極大 safe size-k の軌道構造はそのまま最小 DB size-(31-k) 族に転写される (全件・要素レベルで K1370 と同一の双対性)。
- Grundy 値の計算は行わない (K1370 の「サイズ偶奇混在 → G≥2 示唆」は現状維持)。一般 q への外挿はしない。

## 較正・検証

- 較正: PG(2,3) s=2 {4:234}・PG(2,4) s=3 {7:360, 9:11,480} は K1300/K1355 出版値と完全一致。
- ダンプ byte 再現性: fresh 再実行 sha256 `9af9a06a3565520c278aa1b7d91e201d10fc9d67fa366b80508dfa7f8a6dbfc8` (6,351,900 bytes) = 宣言 pin と一致。
- 独立検証 (out/verify_log.txt): verify mode 13/14/15/16 全件 PASS (bad 0)。orbit mode 13/14/15/16 とも Python 独立再分割が JS 分類と完全一致 (位数 372,000 含む)。
- 開示: verify.py の初版は無限遠点の正規化誤り ((v0/v1,1,0) と (1,v1/v0,0) の取り違え) で生成群が PGL(3,5) を超えて膨張し BFS が異常終了していた。修正後は位数がちょうど 372,000 で fail-closed 検証通過。verify mode (群を使わない全件定義検査) はこの誤りの影響を受けない。
