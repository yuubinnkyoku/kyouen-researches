# 標準11×11：9石18根の証明限定8石・7石被覆統合（2026-10-26）

標準 q=4、完全指摘、通常プレイ。勝敗は元先手固定視点。
**空盤勝敗はUNKNOWN。二石rootの新規閉鎖は主張しない。**

## 入力と証明の境界

原証明は `../n11-s9-neighbor18-terminal-20261026/`。固定した9石18根から
全合法10石子355辺（相異なる348類）を独立した3×3/4×4整数幾何で
終局まで検証した。逆向きの8石WIN証人親は151対称類。

`audit.js` は原証明の根・葉・親のSHA-256と完全な合法子境界を
別のJavaScript整数幾何で再生成する。欠落・重複・混入の負の試験も実施する。
**境界監査は終局の再証明ではない**ため、原証明の
`verify.py --negative` と合わせて使用する。

8石親151類を既存の証明限定8石WIN 1,684類と集合和にする。
従来の9石WIN 152根との重複を拒否し、凍結8石LOSS 294類と
独立証明済み8石LOSS 76類との矛盾を即時検出する。
凍結表は勝敗の根拠には用いない。

純増8石WINから7石親を逆生成し、7石→8石の合法着手による
証明済み被覆辺、未被覆の合法子数、新たな7石全子被覆を再計算する。
数値は `audit.js` の機械可読JSONから取得する。空盤・二石rootの
勝敗はこの局所統合だけでは確定しない。

## 再現

リポジトリ直下で：

```sh
python3 research/experiments/n11-s9-neighbor18-terminal-20261026/verify.py --negative
node research/experiments/n11-s9-neighbor18-s7-union-20261026/audit.js --negative
```

通常CIにも両方を登録した。各検証器の成功を別々に確認する。
探索状態数を勝敗や最適距離として扱わない。
