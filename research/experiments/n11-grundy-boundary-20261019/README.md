# 標準11×11：18個の8石LOSS根の全10石境界について厳密Grundy数を独立照合

2026-10-19。標準q=4、完全指摘、通常プレイ。2026-10-19の18根・184葉証明で使用された**既知の18個の8石LOSS局面**を入力とする。**11×11空盤勝敗はUNKNOWN**。新しい二石根の閉鎖はない。

## 確定した結果

18個の8石局面の全合法応手をD4同値でまとめると387個の9石局面になり、さらにその全合法応手は3,044個の10石局面になる。全3,044局面を終局まで厳密に解いてGrundy数を求めた。手番側LOSSとGrundy数0は同値である。

| 石数 | Grundy数の度数分布 | 合計 |
|---|---|---:|
| 10 | 0:896, 1:294, 2:426, 3:384, 4:220, 5:684, 6:140 | 3,044 |
| 9 | 1:111, 2:54, 3:69, 4:45, 5:9, 6:60, 7:39 | 387 |
| 8 | 0:18 | 18 |

10石の全局面を終局まで求めることで、9石の値は全合法子のGrundy数のmexとして、8石の値は9石の全合法子のmexとして計算できる。9石の全387局面でGrundy数が非零であるため、既知の18個の8石局面はすべてGrundy数0である。

10石の各局面について、PythonとC++で**Grundy数および探索したメモ化状態数が3,044件すべて一致**した。状態数の加算値は両実装とも**505,832**、不一致は0。これは実行時間の比較ではなく、異なる実装の探索状態数の一致である。過去の独立C++による10石WIN/LOSS全3,044件の分類とも、キー単位で不一致0だった（従来のLOSS 896 / WIN 2,148）。

## 検証方式

- `grundy_boundary.py` はPython標準ライブラリのみを使用。18根から9石・10石境界を整数幾何とD4で再列挙し、各10石局面で「今後置くと禁止四点を完成する最小集合」を構築して、合法な石集合をメモ化しながらmexを再帰計算する。保存済みの勝敗表やDAGは参照しない。
- `verify_grundy_direct.cpp` は**禁止集合の縮約を使わず**、各再帰手で現在の盤面から四点の整数行列式を直接検査し、独立にmexを計算する。入力は `s10-input.txt` の3,044局面のみ。
- `audit_crosscheck.py` は3,044局面のキー・Grundy数・メモ化状態数を照合し、集計値と8/9石の結果も確認する。
- `shard-0.json`〜`shard-3.json` に全10石局面のGrundy数とメモ化状態数を記録。`summary.json` に9石・8石の個別値、度数分布、各shardのSHA-256を保存。

PythonとC++は幾何学的な同一ルールを別の計算方式で実装している。両者の一致は強い独立検算だが、全盤面11×11の解決や、8石以外の局面を分類したことにはならない。これまでの184葉の最小性証明は変更しない。

## 再現

Python 3.10以上、C++20対応コンパイラ、`sha256sum`。追加のライブラリは不要。

```sh
bash reproduce.sh
```

C++の実行ファイルは保存せず、実行時にコンパイルする。計算は1プロセスずつ順番に実行する。全10石の再計算はPython約27秒、C++約6秒（当該実行環境の観測値）。
