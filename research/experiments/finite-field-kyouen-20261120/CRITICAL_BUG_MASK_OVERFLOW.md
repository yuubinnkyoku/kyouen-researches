# 重大なバグの発見：64ビットマスクのオーバーフロー

2026-11-20。`finite-field-kyouen-20261120` の第106部。
**過去の C++ 実装に重大なバグを発見した。影響する結果を撤回する。**

## 1. バグの内容

すべての C++ 実装で、局面を `unsigned long long pmask`（64ビット）で表現していた。

```cpp
static void rec(int start, int sz, unsigned long long pmask) {
    ...
    if ((pmask >> i) & 1ULL) continue;   // i は 0..N-1
```

しかし **N（点の数）が 64 を超える盤**では、`i >= 64` のとき `pmask >> i` は
**未定義動作**になる。x86 では実際にはシフト量が `i mod 64` にマスクされるため、
点 `i` と点 `i-64` が**同一視**される。

| `ag16.cpp` | AG(2,16) | 256 | ✓ | **K=16 は無効** |
| `inv16.cpp` | 反転平面 q=16 | 257 | ✓ | **K=12 は無効** |

## 3. 撤回する結果

以下は**無効**であり、撤回する：

- K(AG(2,13)) = 13
- K(AG(2,16)) = 16
- K(反転平面 q=16) = 12
- K(反転平面 q=17) = 13
- K(反転平面 q=19) = 14
- AG(2,17) の K ≥ 17
- AG(2,16) の K ≥ 16

## 4. 影響を受けない結果

- K(AG(2,q)) for q = 3, 4, 5, 7, 8（N ≤ 64）
- K(反転平面 q) for q = 3, 4, 5, 7（N ≤ 50）
- パリティ法則（数学的証明、実装非依存）
- 上界 q+3, q+2（数学的証明）
- 転送閾値 D(n)（Python 実装、BigInt）
- 層サイズ公式（数学的証明）

## 5. なぜ気づかなかったか

- q ≤ 8 では N ≤ 64 なので問題が起きない。
- q=13 以上では、**結果が「もっともらしい」値**（K=13 など）になったため、
  バグを疑わなかった。
- 独立実装（`agq.cpp` と `agq2.cpp`）は**同じバグ**を持っていたため、
  「2実装で一致」という検証が無効だった。

**教訓：独立実装でも共通のバグは検出できない。**

## 6. 修正方針

`std::bitset<512>` または `std::vector<uint64_t>` による多倍長ビットセットに置き換える。
N ≤ 512 を想定（q ≤ 22 程度）。
