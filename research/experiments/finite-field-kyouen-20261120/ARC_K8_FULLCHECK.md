# k=8 の q=7 の差：全数プロファイル検証（C 実装）

2026-11-20。`finite-field-kyouen-20261120` の第226部。

q=7 の差 784,000 の残る候補「稀なケースの `n4` 過大評価」を検証するため、
**全数プロファイル検証**を C で実装した。

## 1. なぜ全数検証が必要か

500 組のサンプルでは 0 不一致だった。しかし差 784,000 は
`7,835,100` タプルのうち **0.01%** に相当する。

**500 組では 0.05 組しか当たらない計算**であり、検出できない。

**全数（7,835,100 組）の検証が必要。**

## 2. 実装

`arc_k8_fullcheck.c`：

```
for T in C(s,4):          # 70
  for X in C(n-s,4):      # 111,930
    # 6類を計算（b=350 円を走査）
    n4 = 1 + v2 + u3 + z4
    n5 = v3 + u4
    n6 = v4
    # 実際のプロファイルを計算（b=350 円を走査）
    an4, an5, an6 = 実際の4円/5円/6円の個数
    if (an4,an5,an6) != (n4,n5,n6): mismatch++
```

**計算量**：`7,835,100 × 350 × 2 = 5.5×10⁹` 操作。C で数分〜数十分。

## 3. 検証の意味

**不一致が 0 なら**、プロファイル公式は q=7 で完全に正しい。
→ 差の原因は別（`(7,)`/`(8,)` の別項か、組み立てのロジック）。

**不一致があれば**、そのケースが差の原因。
→ プロファイル公式の修正が必要。

## 4. 意義

1. **全数検証を C で実装した**（Python では不可能な規模）。
2. **500 サンプルでは検出できない稀なケースを対象**にした。
3. **差の原因を二分できる**（プロファイル公式 vs 組み立てロジック）。
4. 実行中。
