# k=8 の計算可能性分析（現状では全数計算が困難）

2026-11-20。`finite-field-kyouen-20261120` の第192部。

k=8 のアーク数計算に着手し、**計算可能性の壁**を定量化した。

## 1. 8-アークが存在する q

`K(q) ≥ 8` が必要：

| q | `K(q)` | 8-アーク |
|---:|---:|---|
| 3 | 5 | なし |
| 4 | 5 | なし |
| 5 | 6 | なし |
| 7 | 6 | なし |
| 8 | 7 | なし |
| **9** | **9** | **あり** |
| 11 | 9 | あり |
| 13 | 8 | あり |

**最小の q は 9**（`n = 82`、`b = 738`、`s = 10`）。

## 2. 計算量の見積もり

### 2.1 直接列挙

```
C(82,8) = 35,641,470,150   （356億）
```

**不可能。**

### 2.2 プロファイル法（k=7 と同じ方法）

`S = T ∪ {x,y,z,w}`（`|T| = 4`、`T ⊂ C`、外4点）として

```
タプル数 = C(s,4) × C(n−s,4) = 210 × 1,028,790 = 216,045,900
```

**2億1600万タプル。** 各タプルでプロファイルを計算（4点部分集合の列挙）。

**実測**：50,000 タプルで **397.6 秒**。

```
216,045,900 / 50,000 × 397.6 秒 ≈ 1,718,000 秒 ≈ 19.9 日
```

**約20日。不可能。**

### 2.3 7-アークからの拡張

`#7-arcs(q=9) = 17,003,520`。各7-アークに1点を追加して8-アークかを判定。

```
17,003,520 × 75（追加候補） = 1.28 × 10⁹ 回の判定
```

各判定は「追加点が7点の3点と4円を作るか」で、35三つ組 × 円の残り7点
= 245 操作。合計 **3.1 × 10¹¹ 操作**。

**Python では不可能**（C でも数時間〜数日）。

## 3. 構造的な知見（サンプルから）

50,000 タプルのサンプルで **22種類**のプロファイルを観測：

| プロファイル | 件数 |
|---|---:|
| (4,4,4,4,4) | 13,786 |
| (4,4,4,4,4,4) | 12,621 |
| (4,4,4,4) | 6,691 |
| (4,4,4,4,4,4,4) | 4,686 |
| (5,4,4,4) | 3,920 |
| (5,4,4,4,4) | 3,689 |
| (5,4,4) | 1,261 |
| (4,4,4) | 1,200 |
| (5,4,4,4,4,4) | 931 |
| (4,4,4,4,4,4,4,4) | 575 |

**k=7 の11種類から22種類に増加。** プロファイルの複雑さが急増する。

**重要な構造的事実**：`C' ≠ C` は `C` と高々2点で交わるので

```
|C' ∩ S| ≤ 2 + 4 = 6
```

よってプロファイルの値は **4, 5, 6 のみ**（k=7 では 4, 5 のみ）。
6点円が現れることが k=8 の新要素。

## 4. なぜ k=7 は可能で k=8 は困難か

| 量 | k=7 | k=8 |
|---|---|---|
| タプル数（q=9） | `C(10,4)×C(72,3)` = 210×59,640 = **12,524,400** | 210×1,028,790 = **216,045,900** |
| プロファイル種類 | 8〜11 | 22+ |
| 実測時間 | 230秒（q=9） | 見積 20日 |

**タプル数が17倍、プロファイル種類が2倍。** 組み合わせ爆発。

## 5. 意義

1. **8-アークの最小 q が 9** であることを確定（`K(q) ≥ 8` から）。
2. **3つの計算経路すべてで不可能**であることを定量的に示した
   （直接列挙 356億、プロファイル法 20日、拡張法 3.1×10¹¹ 操作）。
3. **k=8 のプロファイルは22種類以上**で、値は 4, 5, 6 を取る
   （k=7 の 4, 5 から拡張）。
4. **k=7 が計算可能だったのは幸運**（タプル数が12.5Mと小さかった）で
   あり、k=8 は本質的に困難であることを明示。
