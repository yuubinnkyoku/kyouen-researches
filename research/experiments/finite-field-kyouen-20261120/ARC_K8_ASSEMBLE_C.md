# k=8 の組み立て：C 実装で q=5 完全一致、重要な除算順序のバグを発見

2026-11-20。`finite-field-kyouen-20261120` の第202部。

k=8 の組み立てを C で実装し、**q=5 で全数と完全一致**した。
その過程で**重要な除算順序のバグ**を発見した。

## 1. 発見したバグ：除算の順序

組み立ての式は

```
#(P を持つ8点集合) = タプル数(P) / (#4円) × b
```

**この順序で計算すると壊れる。**

例（q=5、プロファイル `(10,0,0)`）：

```
タプル数 = 525, #4円 = 10, b = 130
525 / 10 = 52.5        ← 整数でない！
52.5 × 130 = 6,825     ← 整数
```

**`タプル数 / #4円` は整数でないことがある。** しかし

```
525 × 130 / 10 = 68,250 / 10 = 6,825   ← 整数
```

**`b` を先に掛ければ必ず整数になる。**

**修正**：`タプル数 × b / #4円` の順で計算する。

**影響**：C の整数除算で `525/10 = 52`（切り捨て）となり、
合計が `1,562,210` になって `65` の誤差が出た。

## 2. 修正後の結果（q=5）

```
total = 1,562,275 = C(26,8)
arcs = 0
```

**全数計算（C 実装、第196部）と完全一致。**
