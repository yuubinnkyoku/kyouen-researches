# 標準11×11：9石の隣接2根を終局まで独立検証（2026-10-25）

標準 q=4・完全指摘・通常プレイ。勝敗は元先手固定視点。
**11×11空盤の勝敗は UNKNOWN。二石rootの新規閉鎖は0件。**

## 対象と結論

既存の独立証明済み9石根 `00000000000400111000030800011000` の
一石交換近傍をD4正準化して調査した。候補選別は証明に用いない。
今回証明する9石局面は次の2件。

- `00000000000000111000030800011040`：合法10石子30類すべて手番側WIN。
- `00000000000000111000030800015000`：合法10石子29類すべて手番側WIN。

両根の10石子は延べ59辺・相異なる58類（共通1類）。
すべての10石子を、保存済み勝敗表なしで終局まで再帰した。
独立した整数幾何による局所計算では、各根の探索状態数合計は
6,408 / 7,328、相異なる58類の合計は13,596。
**状態数は実装依存の検証指紋であり、勝敗や残り手数ではない。**

全子が手番側WINなので、9石局面は手番側LOSS（元先手WIN）。
9石から合法な一手を戻した8石親は9類ずつ、重複を除き17類。
各親には9石WINへの合法な着手があるため元先手WINとなる。

## 独立性と検証境界

`s9-roots.keys`、`s10-win.keys`、`s8-win.keys` が固定証明入力。
`verify.py` は別の3×3差分行列式と4×4整数行列式（Bareiss法）の
Python実装を読み込み、両者が全子境界・安全性・合法手・対称性・
58個の10石子の終局勝敗を一致して再計算する。
勝敗cacheや未完df-pn探索は読み込まない。
証明書のSHA-256、全子の欠落、親の欠落、異物、根の欠落を検査する。

再現（リポジトリ直下）：

```sh
python3 research/experiments/n11-s9-two-neighbor-20261025/verify.py --negative
```

入力SHA-256：

| `s9-roots.keys` | `6822e87666c33b4e194d4a390cc94258518331a36c8811d5862dea75fe54a94d` |

| `s8-win.keys` | `b73b8f9fee6309532e592d0a1cbe9c998536f039dc3ca8f0b08684f282c6f1b1` |

凍結比較表の9石WIN 1,611類との重複は0。
凍結8石WIN 13,501類・LOSS 294類との重複はそれぞれ0。
これは**凍結表に対する比較**であり、証明限定8石WIN 1,574類への
純増や7石の全子被覆を意味しない。新規二石root閉鎖0、空盤 UNKNOWN。
