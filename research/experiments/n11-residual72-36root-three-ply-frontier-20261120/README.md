# 残余72行・36-rootの三手先D4重複 census

## 目的と境界

K1075の残余72行を完全被覆する36本のfresh-safe 7石rootについて、探索を再実行せず、rootから10石局面までの幾何学的重複を厳密に数えた。目的は4-workerの分割と共有表の検討材料を得ること。これはDFPNの節点数・実行時間・表命中率ではない。

入力はK1075正本だけで、SHA-256 `49b6f85f6b51cfdd8a59c7797223da3d8797885d3c992ce67dc9dae629a883fa`、Git blob SHA-1 `45744d8255f454eae3e0d59b0e2246df80e98667` を固定した。36根は7石・D4正準形・安全性済みで、残余72行を2行ずつ重複なく被覆する候補計画である。WIN証明書ではない。

## 方法

- 11×11の8個のD4変換で10石局面を正準化。
- 共円・共線判定は `[x²+y²,x,y,1]` の行列式をBigIntで計算。
- 3項余因子展開と6項Leibniz展開を各三点組・全121点で照合。
- 各rootの合法な1手、2手後の9石局面、3手後の10石局面を全列挙。
- root間の10石D4類の重複を集合として数え、公開driverの `roots[worker::4]` 分割に割り当てた場合のworker境界を集計。

## 解釈

この36-root集合の三手先では、root別D4類の0.74%が他rootと重なる。現行のstrided分割では、そのpairwise重複の約77%がworkerをまたぐため、単一worker内の表だけでは再利用できない幾何類が多い。

ただし、重複は絶対数で5,430 membershipに留まる。10石時点の同一D4類は、実際のDFPNで同じ深さ・同じ探索境界・同じ表状態に到達することを保証しない。したがって、これだけを根拠に共有表の大規模実装や現行掃引の分割変更を正当化しない。まずは実測TT hit率との比較が必要である。

このcensusは36-root掃引の単一オーナー作業に触れず、判定probeも起動していない。現行掃引の結果が出るまでは、分割変更を提案するための参考値に留める。
