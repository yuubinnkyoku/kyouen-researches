# 列ごとの高さが異なる容量占有ゲーム：偶数余裕Grundy二値性の反例

2026-10-10。基準 `main`: `ed75f33d9ccc1557df6143a59ec0994f46f28594`。

## 定義と厳密な結果

抽象容量占有ゲームを一般化し、列 `i` の上限を共通 `m` ではなく `c_i` とする。状態はラベル付き占有数 `0<=x_i<=c_i`。上位 `h` 個の占有数の和が `r` 以下である状態のみ合法で、1手は任意の列の占有数を1増やすこととする。容量余裕は `sigma=r-sum(top_h(x))`。通常プレイのSprague–Grundy値を `g(x)=mex{g(y):x→y}` と定義する。

**定理（具体的な反例、有限完全証明）**：列上限が異なる場合、`sigma` が偶数でも `g(x)=2` および `g(x)=3` の局面が存在する。以下は両方とも `h=2,r=4,sigma=2`。

| 上限ベクトル `c` | 初期局面 `x` | `g(x)` | 全合法子のGrundy値 | 根から到達可能な局面数 |
|---|---|---:|---|---:|
| `(1,2,2,3)` | `(1,0,0,1)` | 2 | `{0,1}` | 22 |
| `(1,1,2,2,3)` | `(0,1,0,0,1)` | 3 | `{0,1,2}` | 44 |

2番目の証人の合法な一手後局面（列番号は0始まり）とそのGrundy値は次のとおり。

```
column 0: (1,1,0,0,1) -> 2
column 2: (0,1,1,0,1) -> 1
column 3: (0,1,0,1,1) -> 1
column 4: (0,1,0,0,2) -> 0
```

したがって根のmexは3。列1はすでに上限1で着手できない。これらの子の値も含め、根からの**全44後続局面**の合法手とGrundy値を `certificates.json` に保存した。もう一方の証人は22後続局面。

## 証明書の独立検証

`verify_certificates.py` は証明書を**再帰的に解き直さず**、各状態の全合法子を独立に再構築し、到達可能状態の過不足と全行のmex等式を検査する。証明書の値に矛盾がないことは終局からの帰納法で根の値を保証する。

`verify_full_product.py` は証明書の木を使わず、**上限直積の全安全局面**を石数の降順で処理して独立にmexを計算する。前者は22/44後続局面、後者は62/124全安全局面を検査し、両方とも根の値と全証明書行が一致した。

`audit_equal_caps.py` は元の等しい列上限の場合を、署名公式に頼らないラベル付き全列mexで追加検証した。`2<=w<=7,1<=h<w,1<=m<=4,0<=r<h*m` の2,692,065安全局面について、偶数余裕で `g<=1`、全余裕で `g<=3` が成立した。**この範囲外への証明ではない**。等しい列上限の全称定理は別途数学的証明を要する。

## 意義と限界

K0352にある等容量ゲームの全称的な偶数余裕二値性（未統合のK0372候補）を、列ごとの異なる高さにそのまま拡張することはできない。反例は異なる列容量を導入した**別の抽象ゲーム**であり、K0352の元の等容量定理を反証しない。また、異容量版で `g<=3` が一般に成立するかは未解決である。有限実験で4以上が未発見という事実を全称定理にしない。
