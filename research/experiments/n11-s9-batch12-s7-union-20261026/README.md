# 11×11：9石12根の終局証明を8石・7石の証明被覆へ統合（2026-10-26）

標準共円ゲーム（q=4、完全指摘、通常プレイ）。勝敗は元先手固定視点。
**11×11空盤はUNKNOWN**。二石rootの新規閉鎖は主張しない。

## 証明の出典と独立性

原証明は `../n11-s9-batch12-terminal-20261026/`。
9石WINの12根から合法10石子270辺・264対称類を再生成し、保存済み勝敗表を用いず、
3×3差分行列式と4×4 Bareiss整数行列式の別実装で終局まで解いている。
原証明のPython検証器は `verify.py --negative` で実行する。
その結果から逆向きに得られる8石WINの証人親は101対称類。

`audit.js` は独立したJavaScript整数幾何を用いて、
固定12根・全合法10石子・全8石証人親を盤面から再生成する。
原証明の3集合のSHA-256、各局面の安全性・D4正準性、
全合法子のAND境界、親から根への合法なWIN証人を照合する。
欠落・重複した証明境界は負の試験で拒否する。

次に、従来の**証明限定**8石WIN 1,590類と集合和を取り、
既存の独立終局証明済み8石LOSS 76類および凍結8石LOSS 294類との衝突を検出する。
凍結表は衝突検査にだけ使い、WIN証明の根拠にはしない。
増分8石WINから7石親を逆生成し、合法な7石→8石着手の純増、
被覆対象7石類の純増、影響を受けた7石の最小未被覆子数、
新規の全子被覆を再計算する。

**境界監査だけでは10石子の終局勝敗を再証明しない。**
終局の独立検証は原証明の二実装 `verify.py` が担当する。
どちらも通常CIに組み込み、片方だけの成功を完全な証明とは扱わない。

## 再現

リポジトリ直下で次を実行する。

```sh
python3 research/experiments/n11-s9-batch12-terminal-20261026/verify.py --negative
node research/experiments/n11-s9-batch12-s7-union-20261026/audit.js --negative
```

`audit.js` の標準出力は機械可読JSON。
`addedS8Win`、`addedS7Parents`、`addedSecuredS7Moves`、
`minimumUncoveredAmongAffectedS7`、`newlyClosedS7` を確認する。
探索状態数は勝敗・距離ではなく、証明の回帰指紋である。
