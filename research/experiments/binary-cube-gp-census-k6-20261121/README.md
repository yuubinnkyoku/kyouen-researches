# GP-census による {0,1}^6 一般位置集合の完全計数と K_6 = 9 の確定（2026-11-21）

## 主張

二値六次元超立方体 $V_6=\{0,1\}^6$（64頂点）上で、相異なる7点が一つの実アフィン超平面に載ること
（退化を含む）を禁止するゲームの最大安全石数は

$$K_6 = 9$$

である。安全局面の条件「どの7点部分集合もアフィン独立」（GP: general position）を満たす部分集合の
うちサイズ10のものを有限完全列挙で数え上げた結果、**個数は 0** であった。
下界 $K_6\ge9$ は既刊の9点証人（K0553）のとおりであり、本実験は上界 $K_6\le9$ を確定する。
これにより K0568 の残課題（exactly-10 CNF の UNSAT 証明か GP-10 集合の発見）を、
SAT ソルバに依らず列挙によって解決した。

注意: これは最大安全石数の確定であり、d=6 の全局面 Grundy 値・勝敗には一切言及しない。
（d=5 の全局面強解決は K0546/K0591 が別手法で既に確定済み。）

## 証拠の水準（誠実な記載）

この結果は**単一実装（census2.js）による有限完全列挙**に基づく。ただし以下の多角度交叉検証を通している:

1. **二重素数演算**: すべてのdoubles/triples ゲート判定は PA=67,108,859 と PB=67,108,837（いずれも
   $2^{26}$ 未満の最大素数、起動時に計算・battery B0 で素数性確認）の両方で実行。
   0/1成分 7×7 行列式の Hadamard 限界は $(\sqrt7)^7=907.5\ldots<p$ なので、有限体の零検定は整数零と厳密同値。
2. **外部監査表との全桁一致**（既刊の依存集合計数からの独立導出）: アンカー計数 $s_k$ から
   非アンカー総数 $s_k\cdot 64/k$ を導くと、サイズ4/5/6/7 が d=6 circuit 監査
   （K0568: 依存 4,816 / 311,360 / 10,663,520、独立七点組 366,179,200 = $\binom{64}{7}-255{,}036{,}992$）から
   導かれる値 $(\binom{64}{k}-\mathrm{dep}_k)\cdot k/64$ と全桁一致する。
3. **独立参照実装との一致（battery B6）**: d=3,4 は全サイズで census と全列挙 brute（独立アルゴリズム: 全部分集合の rank 計算）が全桁一致、d=5 はサイズ6以下で全桁一致。加えて d=5 のサイズ7 総数 309,056 が
   K0591 の全局面DP（popcount降順・独立実装）の「七石安全局面 309,056」と完全一致（第三手法の独立照合）。
4. **関数族の数学的恒等式検証（battery B1-B4, 7000+ trials）**: 高速ゲートで使う行置換関数
   $\det(W_{\text{row} \to x})=\det(W)\cdot(W^{-\top}x)$ 型の恒等式を BigInt Laplace 展開の真値と照合。
5. **ツリー内全ゲート工事の brute 再照合（battery B8 + check6）**: ペア (0,62), (0,61), (0,58) は
   全ゲート、(0,45), (0,40), (0,35) は上限付きで、census ゲート判定と独立 brute 参照の不一致 0。
   最重量ペア (0,1) は `check6 1` で先頭600,000ゲートの brute 再照合・不一致 0
   （打切りあり・出力 `check-pair01.txt` 同梱。s9 アンカー計数 17,280 を含む当該ペア counts は
   `r6-results.jsonl` と同一）。
6. **9点証人照合（battery B7）**: 既刊9点証人 {11,22,28,37,42,49,57,58,63}、
   第二の9点集合 {0,5,6,14,21,26,35,41,52}、XOR正規化（頂点0を含む同型像）{0,23,29,33,46,49,50,52,58}
   の GP 性を brute で再確認。
7. **分割整合（battery B9）**: (0,45) ペアの v3-スライス（第3要素 46..54 / 55..63）計数の和が全走査と一致。

battery は 20/20 PASS（2026-11-21 再実行 5.1秒・出力 `battery.txt` 同梱）。

## 手法

`census2.js`（自己完結・依存ゼロ・約730行）:

- **頂点0アンカー分割**: $x\mapsto x\oplus u$ は座標鏡映の合成として実アフィン自己同型で頂点推移的。
  よって頂点0を含む GP 集合の計数 $s_k$ から全計数 $s_k\cdot 64/k$ が従う。
  ペア $(0,v_2)$（$v_2=1..63$ の63本）で木を完全分割する（`r6-results.jsonl` に各ペアの生計数）。
- **高速ゲート**: 既定 GP 前置行列 $W$（斉次化した行ベクトル）の fraction-free 両側掃き出しで
  $E\cdot W=$ 対角（ピボット非零）となる $E$ を作り、追加候補 $x$ に対する全ゲート判定を
  $W^{-\top}x$ 型疎関数の零検定に帰着する。関数ごとの行/列スケールは真の関数の定数倍なので
  零検定は普遍。d=6 の七点検定は 7×7 行列式、サイズ5以下は rank で判定。
- **正確性**: 上述の Hadamard 限界により各素体上の零検定は整数零と同値。
  doubles/triples は二素数で belt-and-suspenders（単素でも厳密）。

## d=6 の主実行

全63ペアの走査（task63 モード・v3-スライス分割対応）を合計約13分 CPU（2コア・node v22.20.0）で完了。
`r6-results.jsonl` に63ペアそれぞれの counts（各サイズごとの完全な値）を記録し、
`agg.js` が集計・交叉検証を再現する（本README冒頭の表は agg.js 出力と一致）。

## 再現手順

```sh
node census2.js primes        # 使用素数の確認 (PA=67108859 PB=67108837)
node census2.js battery       # 20項目の検証バッテリ (数秒)
node census2.js census 3      # d=3 アンカー計数 (瞬時)
node census2.js census 4      # d=4 (約1秒)
node census2.js census 5      # d=5 (数秒) → s7=67606, 総数 309056
node census2.js census 6      # d=6 アンカー計数 (約13分, 2コア) → s10=0
node census2.js task6 <v2>    # 単一ペア
node census2.js check6 <v2> [maxChecks]  # 単一ペア + 全ゲート brute 再照合

node agg.js                   # r6-results.jsonl の集計・交叉検証
```

`census 6` の再実行で `r6-results.jsonl` と同一の各ペア計数が再現されることを確認済み
（task63 v2 スライス走査との分割整合も含む）。

## 限界

- 列挙器は単一実装であり、d=6 のゲート判定アルゴリズム自体の完全性は battery の関数族検証・
  小次元全一致・ツリー内ゲートの brute 再照合・外部監査表との4階数全桁一致で支える
  （1階数も照合から外れた値はない）。独立な第二の d=6 全走査実装は今後課題。
- Grundy 値、misère 版、$d\ne6$ の全局面解析、$d\ge7$ の上界は対象外。
- $d\ge7$ の同種の GP-census（例えば $K_7\le10$ の決定）は本手法の直接拡張で、
  計算量は約 $\binom{2^d \cdot 64/2^6}{k}$ 規模で急増するため別個のレーンで扱う。
