# 容量余裕1・非二値Grundy局面の全合法手値の厳密分類

日付：2026-10-08。既存 K0358 にある「Grundy 0 の子の型」を、**物理的な列への着手の全本数と全子 Grundy 分布**に強化した。抽象容量ゲーム全体についての g<=3 は未解決であり、本結果は容量余裕1に限定される。

## 全称定理

`2<=h<w`、`0<=x_i<=m`、降順安全状態 `x`、`sum(x[:h])=r-1`、`b=x_h<x_{h-1}<m`、`n=w-h` が奇数であるとする（K0358 の E={0,1} の場合）。

`R=n*b-sum_{i>h}x_i`、`u=#{i<h:b<x_i<m}`、`c=#{i<=w:x_i=b}`、`ell=#{i>h:x_i<b}` と置く。1つの列への着手を1手と数え、盤上で異なる列は行き先の降順状態が同じでも別の手とする。

| 子の Grundy 値 | R 偶数（親 g=2） | R 奇数（親 g=3） |
|---|---:|---:|
| 0 | u | c |
| 1 | c | u |
| 2 | 0 | ell |
| 3 | ell | 0 |

上位で b より大きく未満杯の列への u 手は閾値 b を維持して容量境界へ移り、子は R mod 2。高さ b の c 列への着手は b+1 の境界子となり、子は (R+n) mod 2。下位 b 未満への ell 手だけが余裕1を保ち、子は K0358 より 2+((R-1) mod 2)。これで全合法手を尽くすので表が成立する。

勝ち手は g=2 では u 本、g=3 では c 本。上位列の満杯を無視して g=2 の勝ち手が常に h-1 本とするのは誤りである。例えば (w,h,m,r,x)=(4,3,2,4,(2,1,0,0)) は g=2 だが u=1、h-1=2。

## mex 再帰による独立有限完全検算

[check_children.py](check_children.py) は K0358 の式を使わず、合法手を全て列挙する mex 再帰で、着手先の Grundy 値を計算する。さらに降順に一致する複数のラベル付き手も個別に数える。

対象：3<=w<=8、2<=h<w、2<=m<=6、1<=r<hm、n 奇数、容量余裕1で両境界型が存在する全降順安全状態。

EXAMPLE {'example': (4, 3, 2, 4, (2, 1, 0, 0), 1, 2)}

観測不一致0。表の無界の結論の根拠は K0358 と前節の三分割による全称証明であり、この完全列挙は実装・係数数えの独立確認である。

## 実際の着手点数（列選択数とは別）

一列の占有数が `x_i` の場合、盤上の残りの点は `m-x_i` 個であり、いずれを選んでも占有数としては同じ子になる。列単位の `u,c,ell` に対応する盤上の点数は `U=sum_{i<h,b<x_i<m}(m-x_i)`、`C=(m-b)c`、`D=sum_{i>h,x_i<b}(m-x_i)`。

従って親が `g=2` のとき子 `g=0,1,2,3` へ進む **盤上の点数** は `(U,C,0,D)`、親が `g=3` なら `(C,U,D,0)`。厳密な勝ち手点数は前者で `U`、後者で `C`。上の表は列の選択肢数なので、数え方を混同しない。

検証器を拡張し、別途各合法列への着手点 `m-x_i` 個をそれぞれ足して局面子の値別点数を全件照合した。列選択としての勝ち手は合計24,832、盤上の点選択としての勝ち手は合計61,371であり、いずれも **9,825対象局面・不一致0**。実行例：

      'point_winning_moves': 61371, 'g3': 3505}
