# 強化 CNF 符号化バグの追跡記録 (2026-11-20, n9-ge19 決着レーン)

gen_strong_cnf.js (逐次カウンタ + 冗長強化の本レーン内実装) は、出版前に 2 件の
符号化バグを正負制御で捕捉・修正した。両バグとも「witness 正制御だけでは
検出できない」クラスであり、手続きとしての価値が高いので生成物の FNV 変遷と
ともに記録する。

## バグ 1: 鏡像節のリテラル 0 出力 (不正 DIMACS)

- **症状**: 生成 CNF に `-84 82 0 0` 型の行が 13,662 行 (n9_ge18)。
  節末の終端 0 に加えて節内にリテラル 0 が出力されており、
  DIMACS リーダーはこれを「節 `-84 82` + 空節」と誤読する。
  ソルバーに渡せば空節による**即時偽 UNSAT**を返しうる (静かに graft され
  9x9 では FNV/bench が合っていても中身が壊れている状態になる)。
- **原因**: 上界鏡像 `s(i,j) -> s(i-1,j) OR s(i-1,j-1)` を発行する際、
  `j==i` (対角成分) では先行変数 `s(i-1,j)` が「定数 FALSE」に相当し
  id を 0 で表現していたが、0 のまま節に混ぜて出力していた。
- **検出経路**: CNF の構造検証 (節数 = 宣言数、節内 0 なし、|lit|<=nv)
  と eval_strong.js の clauses_seen 不一致 (271,202 vs 257,558)。
  **ソルバ実行前に捕捉**された。
- **修正**: gim==0 のとき `clause(-gi, gim1)` を発行 (定数 FALSE の置換)。
- **FNV 変遷** (n9_ge18_strong): `b606f210ce591303` (バグあり) →
  `70b0eba283ccd3f3` (修正 1 適用) 。
- **教訓**: 逐次カウンタ系の出力は必ず (a) トークンレベルの DIMACS 検証、
  (b) 節数一致、をソルバ実行前に通す。

## バグ 2: 対角・境界の上界鏡像の欠落 (カウンタ意味論の不健全化)

- **症状**: 修正 1 の後、fastsat が**既知 UNSAT** の n5_ge10_strong を
  **0 conflicts で SAT** と判定。モデルの cell True はわずか 8 個。
  しかし全 10,622 節は充足 (ユニット a[25][10] を含む)。つまり CNF 自体が
  「19 石なくても at-least-K を充足できる」不健全な符号化だった。
- **原因**: 逐次カウンタの上界側で、
  - 境界: `s(1,1) -> x_1` (i=1)、
  - 対角: `s(i,i) -> x_i` (gim=0 で `s(i,j) -> s(i-1,j) OR x_i` の x_i 側が消える)
  が発行されていなかった。このため「全 cell FALSE + カウンタだけ真」の
  割り当てが unit まで到達できた。rev (逆順) および S1 (曲線ごとの
  at-most-3) ブロックにも同型の欠落。
- **検出経路**: **既知 UNSAT ネガティブ制御** (fastsat の偽 SAT)。
  正制御 (W が ge_k を満たす) では絶対に検出できない。
  検出後、モデル抽出→全節手評価で「8 cell True ですべて充足」を確認し原因を特定。
- **修正**: `gim==0` のとき常に `clause(-gi, xi)` (rev は `clause(-gi, xv)`) を発行。
  FNV 変遷 (n9_ge18_strong): `70b0eba283ccd3f3` → `d7ffb2bca4a7664f` (最終)。
  n9_ge19_strong 最終 `83f9407a12eff3ea`。
- **修正後の再検証**:
  - 全意味論制御 PASS (W5/W7/W8/W9 の正制御、W5/W7/W9 の負制御=ユニット 2 節のみ違反)
  - fastsat n5_ge10_strong: **UNSAT** 12,583 conflicts / 2.6s (既知値 K_5=9 と一致、2 系一致)
  - fastsat n5_ge9_strong: SAT (178 conflicts)、モデル 9 石を第三系で検証、新 witness
    [2,4,5,7,11,12,21,23,24]
- **意味**: S1/S2 は冗長強化なので、S1 側の欠落だけでは健全性は壊れないが、
  fwd/rev の at-least-K カウンタは「K 石存在」の唯一の表現なので、その欠落は
  偽 SAT を生む (UNSAT を証明したい問題で最悪の方向のエラー)。

## 既刊レーンの同型監査 (参照のみ)

`research/experiments/n9-k9-upper-sat-20261115/scripts/gen_n9_cnf.mjs` の
`genCNF` を監査した: c1 = `[-A, (B), i]` は常に x_i を含み、j>i-1 の定数 FALSE
置換・j=1 の定数 TRUE 置換が正しく行われている。すなわち上記バグ 2 と同型の
欠落は**ない** (健全)。既刊 `n9_ge18.cnf` / `n9_ge19.cnf` (FNV 再照合済み) は
この監査の範囲で問題なし。同レーンのファイルは一切変更していない。

## まとめ

- 逐次カウンタ符号化の健全性は「正制御 (witness 充足)」だけでは証明されない。
  **既知 UNSAT インスタンスでのネガティブ制御**と
  **モデル全節手評価 (第三系)**を必須手順とする。
- 本レーンの CNF は最終版 (FNV 掲載) のみ証明・較正に使うこと。
  FNV が上記最終値と異なる生成物はバグあり版なので破棄すること。
