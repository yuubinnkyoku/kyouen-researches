## 狙い撃ちの判断

以前のS10 cache 51,164件と、C++のみで計算され独立再検算が未完のS10 LOSS候補2,229件を**候補選定だけ**に用いた。8石LOSS候補のうち9石義務が1〜3件だけ未被覆だった120件は、既に証明済みの8石WINであり、LOSS探索対象から除外できた。4〜5件未被覆の4候補だけを調べ、407件の未知10石局面をC++で終局計算した。全407件を別実装Pythonで再計算し、勝敗・合法手数・状態数の不一致0（延べ378,648状態）。このうち3候補はLOSS、1候補はWINと確定した。WIN候補に対する新しい2個の9石WIN証人から、8石WINをさらに16件へ伝播できた。

C++のみの2,229件は今回も**全件を独立検証していない**ため、統合cacheに入れていない。選ばれた63個のLOSS証明葉は、どの由来であっても証明書の独立検証器が終局まで再計算する。統合cacheは51,164件+独立検証した407件だけ。原子的mergeで重複0、WIN/LOSS衝突0、全キーの整数幾何とD4正準性を検査した。

新しい51,571件の検証済みcacheだけを使った8石LOSS候補の再順位付けでは、既知9石LOSS証人12件以上かつ未被覆9石子5件以下の候補475件は、すべて既知の8石WINまたはLOSSだった（未分類0件）。この範囲では次に狙うべき未確定8石LOSSは残らない。

新しい7石LOSSを反映した6石候補の再順位付けでは、既知の6石LOSS1件を除いた最上位 `00000000000040001000044400010000` は51子中23 LOSS・28 UNKNOWN（従来22 LOSS・29 UNKNOWN）。新しい6石LOSSや二石rootの閉鎖はない。

## 再現

Python 3.10+、C++20コンパイラ、`sha256sum` が必要。ZIPを展開したディレクトリで `bash reproduce.sh` を実行する。Pythonの407件再計算のみ最大4並列。コードは外部の勝敗cacheを読み込まずに各証明書を検証し、C++/Pythonの独立実装で終局まで再計算する。加えて全407件のC++/Python照合、統合cacheの再構築、上位への勝敗伝播、7石親の再導出、6石再順位付け、証明書改変拒否を検査する。中間出力は一時ディレクトリに書く。`python -O` は禁止。

`OPENBLAS_NUM_THREADS=1 PYTHONPATH=scripts python3 scripts/audit_cover_ilp.py` で整数計画の最適性も任意に再検査できる（NumPyとSciPyが追加で必要）。再現に既存repo全体や過去のZIPは不要。既存cache 51,164件をこのZIPに同梱し、その各項目を終局まで独立再計算したわけではないことを明確にする。
