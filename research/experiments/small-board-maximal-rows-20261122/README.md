# 3×3〜6×6 極大安全配置の全行較正・消滅確認・D4軌道・構造分類（2026-11-22）

単一オーナー宣言: [2026-11-22-n56-rows-calibration-structure-single-owner-note](../../log/2026-11-22-n56-rows-calibration-structure-single-owner-note.md)。
セッションログ: [2026-11-22-n56-rows-calibration-session-log](../../log/2026-11-22-n56-rows-calibration-session-log.md)。

標準共円盤（q=4、禁止四点組=同一線上または同一円上の4点）について、
K0030（3×3〜6×6 極大安全集合サイズ分布）のうち n7 カタログ機材
（[n7-seven-stone-maximal-catalog-20261122](../n7-seven-stone-maximal-catalog-20261122/README.md)）
で一度も機械較正していなかった行を含む **全行** を完全列挙で較正し、
さらに各行の D4 軌道分類と構造特徴を確定した。

宣言時の予定対象は 5×5 k=5..9 と 6×6 k=6..11 の計11行であったが、
実行中に列挙が軽量（最大行で数秒〜数分）と判明したため、
**各盤面の全石数行（k=1..N²）まで全て列挙**し、K0030 の表外（5..11石列の外側）の
消滅行・零行も明示的に機械確定した（スコープ追加は下記のとおり開示）。

確定した（4×4: 16行、5×5: 25行、6×6: 36行。2回の独立した完全走行で byte 一意）。

### 1.5 essential curve count（ecc）ヒストグラム

出版 round10 規約のまま（n7 実験で n=8 出版値と 51/51 一致検証済みパイプライン）で

### 1.6 補題の機械確認ゲート（新規主張ではない）

「包含極大の定義により、極大安全集合は決して別の安全集合の真部分集合になれない」
（したがって極大安全集合族は反鎖）は定義からの補題であるが、
verify_rows.py は行間推移統計（各行の各配置 S の各石除去 S∖{s} が行 k-1 の
完全カタログに属するか）として隣接下位行の完全カタログ(行 k-1)が列挙済みである全 367,196 配置で **remov=0（エッジ0）** を機械確認した
（remov_histogram `{0: all}`、全14行）。これはパイプラインの整合ゲートであり、
数学的な新規主張としては扱わない（証明は定義そのものから直接従う）。

## 2. 検証（多系統・fail-closed・決定性）

1. **禁止四点組カタログ（2系統 byte 一致）**: census.mjs 系統A（dump_quartets.mjs）と
   独立 Leibniz 4×4行列式系統B（forbidgen.py / forbidgen_write.py）が n=4..6 で
   byte 一致。F_3=14（sha256 `335549bd…`, 系統Bのみ）、F_4=194（`0879b9f7…`）、
   F_5=826（`22d086ba…`, K0057/n7 出版と一致）、F_6=2491（`6996d772…`, 同）。
2. **DFS 全列挙**（enum_catalog.mjs・ 出版機材と byte 同一・n7 README §2 と同じ
   soundness/completeness スケッチ: 安全枝刈りは cov>0、完全性は昇順配置経路、
   最大性判定は u==0）: 全 77 行（4×4: 16行・5×5: 25行・6×6: 36行）を2回完全走行、
   canonical projection（cfg 行 + elapsedMs 削除 summary 行）で byte 一意・nodes bit 一致
   （output/determinism.json）。
3. **独立検証（verify_rows.py・系統B幾何・別言語別実装）**: 全非零行の全 367,384 配置が
   SAFE+MAXIMAL（triple→completion map による別実装）、D4 閉包・軌道和・軌道数・
   安定化群ヒストグラム・trips/dirs ヒストグラムが classify.mjs（Node・系統A幾何）と
   14/14 行で完全一致、2回実行で byte 一致、problems=[]。
   tamper 陰性対照: 全非零行で「被覆済み空点の追加」unsafe 判定・「行k-1 非要素化
   除去」not-maximal 判定をそれぞれ機械的に選んで拒否（verify_*_rows.json の
   control_* フィールドに記録）。
4. **第三方式: 部分集合全走査（brute_scan.py）**: n=3（2^9）と n=4（2^16）の
   全部分集合の列挙による行分布で DFS と一致、n=4 の非零3行は**配置集合そのものが
   完全一致**（set-identity）。n=3 は brute scan のみで K0030 明示値 56 に一致。
5. **陽性対照**: 5×5 最小4配置が単一 D4 軌道（安定化群位数2）、6×6 最小8配置が
   単一軌道（位数1）— K0030 明示文言の機械再現。

## 3. 非主張（trust boundary）

- 本成果は 3×3〜6×6 の有限計算・機械検証であり、形式証明ではない。
  列挙器・検証器・kissat に依存しない範囲での健全性/完全性スケッチと
  有限較正全一致（K0030 の C++ 出版値を含む3方式一致）が trust boundary。
- s_3..s_8 の値更新は一切しない（既刊どおり。本実験の最小行はその整合確認）。
- K0030 の分布命題は変更しない（本実験はその機械証拠の追加・最大行 M_n の明示化）。
- 7×7/8×8の既刊行（K1224・K0032）は本実験の対象外。n≥7 の k≥12 行・n=9/10 は未着手。
- n=3 の四点組は系統B単独（census は 3×3 非対応）。行数 56 は K0030 明示値と一致で担保。
- classify.mjs の ecc は単独計測（独立再計算なし・1.5 に明記のとおり）。
- nodes 数・実行時間は勝敗でも証明でもない。
- 標準 11×11 空盤・二石 root・S2・closure class は本レーン非接触（UNKNOWN のまま）。
