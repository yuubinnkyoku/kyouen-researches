# 残余29行のWIN8-D10 root 00000000000200003800200008180000 証明書抽出・三重検証（K1086掃引pin基盤）

fold23（K1133）出版後の残余29行レーンで、K1086 addtwo-greedy23 depth-10掃引正本
（残余72行を23本のquadruple-free greedy根でちょうど1回ずつ被覆・両AND順序46 probe・
SHA-256 3045e152…）のper_root pinでWIN8-D10候補として確定済みの8石root
`00000000000200003800200008180000`（石[19,20,27,45,59,60,61,81]・mobility 42・主張被覆2行）の
完全勝利戦略証明書を盲抽出・三重独立検証した。残余72期に発行された旧宣言（commit 4496c888）が
未完のまま残っていたため、fold23完了後の残余29レーンで単一オーナー宣言ノート
（commit 6fb426ba37）により旧宣言を更新（supersede）して着手した。

## 主要結果

- **証明書**: 19,525戦略行 + root行 + header行・706,180 bytes・行は昇順一意。
  SHA-256 `7bd64a47bed13c25fe069b0b3563c06081639cd3d2ad09b28a1e6c65a41fa61d`。
- **fresh-probe（K1086 pin再現）**: bit 19（root − 最小セットビット）child
  `00000000000200003800200008100000` + bit 19・depth-10・cap 30,000,000・両AND順序×2回で
  andclose1 261,294 / andclose0 288,448（合計 549,742）・両順序 uncapped loss=true・
  終局石数 [14,18]・pilot_d6 制御 4/4（nodes 3,402）がK1086掃引正本per_root pinとnode-exact一致。
- **抽出3実行**: A1 = 初手ごと新規プロセス42本（総nodes 1,399,389・最大初手 move 10 の 196,428・
  fbt_drops 0）・A2 = A1完全再実行（初手単位node-exact一致・rows byte-identical）・
  B = 単一プロセス一括（1,057,553・memo温存による会計削減）。
  **3実行とも証明書行集合byte-identical**。
- **三重独立検証の全数値一致**: BigInt 3x3余因子 / Bareiss 4x4整数行列式 / Python第三実装全木再走査の
  3方法で visited 43,649・winner-to-move 28,170・loser-to-move 8,556・loser応手辺 39,665・
  終端 6,923（全loser-stuck）・終端石数 [14,18]・consumed union == 19,525 == 証明書行
  （missing 0 / extra 0）・Bareiss 42 subroot（root-check stones 8 / loserMobility 42）が完全一致。
- **19/19 gate監査**: g01 K1086正本SHA-256 pin・g02 runner v17 git blob pin・g03 固定コピーblob一致・
  g04 root shape safe（8石・quadruple-free・D4正準）・g05 mobility 42・g06 K1086 per_root probes
  uncapped loss=true〔261,294/288,448〕・g07 covered_rows 2行・g08 fresh-probe再現 bit 19
  node-exact（pilot 4・各順序2回）・g09 初手リスト==独立再導出・g10/g11/g12 抽出3実行clean・
  g13 node会計（A1 1,399,389 vs B 1,057,553）・g14 証明書format sorted-unique・g15 B nRows一致・
  g16 第三方法全木再走査PASS・g17 三方法集計一致・g18 解釈guard文言・
  **g19 K1097 footprint intrinsic == claimed == 2行 + fold23正本pin（04f334ff…）+
  残余29行内で主張2行全行open（residual_target_rows == 29の照合込み）**。
  正本は同一cwd 2回 + 別cwd・別EXPERIMENT_ROOT・別プロセス1回の3実行でbyte-identical
  （SHA-256 `dafa177bf74fd528c34e9a858a83345df4cf8138c17f33ca0102c28840f28c04`）。
- 主張2行 `00000000000000003800200008100000`・`00000000000000a09002000080000000` は
  K1097 win16 footprint と一致し、fold23残余29行内でopen。着手前機械計算で本rootの28正準部分幾何に
  よる残余29内openは主張2行のみ（余剰なし）であることを確認済み。

## receipt foldに向けて

本証明書のreceipt fold（主張2行の閉鎖簿計）は別機材・別単一オーナー宣言の工程であり、
本実験では行を1つも閉じない。候補Aのfold24（主張3行・残余29→26想定・宣言済み・未実施）の主張3行と
本rootの主張2行は不交差であり、fold24実行後の残余簿記に本rootの2行は残る。
fold時はfold23出版正本（04f334ff…）と修復済みfold23出版機（SHA-256 c908f6c0…・commit ce5361dc）
の系譜に接続する。
