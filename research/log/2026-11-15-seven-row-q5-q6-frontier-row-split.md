# 2026-11-15 高速レーン: (7,5) 7x32・(7,6) 7x27 前線を rowY 固定分割で解決

高速レーンの1バッチ。前回までに frontier-20261115 が (7,5) 7x32・(7,6) 7x27 を
def-mode OR 200s INDET（329,844 / 744,027 conflicts）の負記録で残していた。
本バッチは rowY 固定分割（sat2.js --rowY=Y・rowsplit.sh）で両前線を SAT に解決した。
実験: `research/experiments/seven-row-q5-q6-frontier-row-split-20261115/`。

## 結果

1. **(7,5) m=32 SAT**（rowY=0・129,923 conflicts・250s cap）。
   27石 rows [3,4,4,4,4,4,4]・2系統検証 PASS。**M_{7,5} ≥ 33**（M ∈ [33, 1142]）。
2. **(7,6) m=27 SAT**（rowY=3・230,973 conflicts・250s cap）。
   34石 rows [5,5,5,4,5,5,5]・2系統検証 PASS。**M_{7,6} ≥ 28**（M ∈ [28, 862]）。
   OR 175s INDET 703,590・rowY=0/1/2 250s INDET 989,735/1,078,304/1,074,595
   （正直な負記録）。
3. **(7,4) 構成witness m=22..35 の2系統再検証 14/14 PASS**（sat.js verifyConfig +
   Python Fraction・seven-row-q4-extension-band-20261114 の公開ファイルに対して）。
   これで構成ファイルそのものも4系統検証（tsVerify + frontier/sat3 の SAT 再確認 +
   本再検証）。

## 経緯と判断

- バッチ冒頭で環境リセットが発生し、前セッションの未push成果
  （(7,4) m=22..27 SAT・(7,5) m=32 witness 等）のローカルアーティファクトが全損。
  ただし並走が (7,4) 帯を m=35 まで（構成的+sat3 SAT・四重検証）に延伸済みだった
  ため、(7,4) の再生成は不要と判断。損失が前線に影響したのは (7,5) m=32 のみで、
  較正→再生成→bit-exact 再現（129,923 conflicts・27石）で完全に復元した。
- 環境再構築: kissat 4.0.4 公式バイナリを rel-4.0.4 から再取得
  （sha256 21da5d98… 同一）・スクリプトは repo から verbatim 復元。
  較正 (7,5) m=31 def-mode 31,000 conflicts bit-exact。
- rowY 分解は (7,8) m=24・(7,7) m=25/26 に続き5例目・6例目の成功。
  OR が 200s で開かない前線でも row クラス固定で数分で開くことがある。
  7行族ではミラークラス 3 が多くの SAT を担ってきたが、(7,5) m=32 は
  rowY=0 が開いた — 成功クラスは安定していない。前線アタックは
  全 rowY を並列試行するのが定石。
- 並走との重複回避: push 直前に最新 main を再取得し、K0827/CSV は
  sat3 コミット後の最新版（d0c20dbf 時点）に基づいて編集した。

## 残課題（次回候補）

1. **(7,5) 7x33**: OR・rowY=0..3 が未評価（前セッションでは 175s cap で全 INDET
   との未検証記録があったがアーティファクト喪失で参照不能。再実行が必要）。
2. **(7,6) 7x28**: sat3.js（streaming・sat2 byte-identical）なら census 生成可能。
   rowY=3 优先で全クラス試行。
3. **(7,4) 7x36**: sat3 で生成 ~6s/幅。UNSAT なら帯の終端候補だが長時間必至。
   先に witness 探索（SAT なら前線前進）。
4. rowY 分解の成功クラス偏りの統計（7行族 q=4..8 で集計すると
   欠損行位置の設計指針になる可能性）。
