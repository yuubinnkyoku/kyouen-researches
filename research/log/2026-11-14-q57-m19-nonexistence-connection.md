# 2026-11-14 高速レーン: (5,7) 5×19 前線の決着確認と順列シャッフル kissat ポートフォリオ

## 主成果: 5×19 q=7 の不在は列挙で証明済みだった

K0815 第2弾までの流れを受け、未決着インスタンスを順列シャッフル kissat
ポートフォリオで攻撃した（全 run timeout・抵抗記録にとどまる）。その過程で
K0759 を読み直したところ、**K0738–K0759 の occupancy 完全列挙は
5×19 の全欠損クラス（単一行〜5行）で witness 0 を出しており、
5×19 に行欠損の極大安全配置は存在しないことが確定していた**。

K0738 の本文は「M_{5,7}=19 予想を補強する」と書いており、列挙レーン側は
この帰結を認識していた。しかし K0810/K0811/K0815 のSATレーンは
5×19 q=7 cap=29 を未決着インスタンスとして扱い続け、自作CDCL・fastsat・
kissat（5.54M conflicts）で grind していた。M 境界の成果物（mwq CSV の
(5,7) 行・K0815・fixed-width README）にも反映されていなかった。

接続の内容:

- 5×18 に 29石の欠損極大（K0332 証人）が存在し、5×19 に存在しない
  （K0738–K0759 列挙）。よって「欠損極大が存在しない最小の m」は 19。
- **(5,7) の下界 19 は最終確定**。witness 探索は m≥20 だけを対象にする
  （次の前線は 5×20 q=7 cap=29）。
- M_{5,7} を真の安定化長として読む場合は 19≤M≤158 が不変。20≤m≤157 の
  持続性が残る。列挙は共有runnerの正確性までの machine-verified であり
  数論的証明ではない。SATソルバによる 5×19 UNSAT の独立交叉確認は未達
  （今回も 5.54M conflicts 級の難度で予算内決着は不可）という留保を付した。
- 5×18 証人を sat.js census 不使用検証器で再検証し safe+maximal PASS。
  同じ石を 5×19 に置くと (18,0) が非極大で、列挙結果と整合。

## ポートフォリオ（全未決着・非不在）

DIMACS 変数順列シャッフル（xorshift・節順/リテラル順もシャッフル）で
探索を多様化し、kissat 4.0.4 を各 260〜280 秒で実行。制御は 2×8 q=4
（順列経由で SAT・witness 検証 PASS）と 2×9 q=4（UNSAT）の両方 PASS。

- 6×30 q=5 cap=23: 863,227 conflicts（seed2）・733,294（欠損行0固定）
- 6×23 q=6 cap=29: 1,792,902
- 6×21 q=7 cap=35: 3,626,548
- 5×22 q=6 cap=24: 2,877,252
- 6×19 q=8 cap=41: 4,363,551
- 5×20 q=7 cap=29: 4,680,968（欠損行0固定）

変数順列は難度を変えず、欠損行固定のユニット節も難度を崩さなかった。
6行盤は decisions/conflict が 9〜12 と高く、sequential counter 由来の長い
決定列が難度の主因と推定する。単発予算での決着は見込めず、
符号化改良（counter の局所化・対称性破り）か予算延長が次の一手。
