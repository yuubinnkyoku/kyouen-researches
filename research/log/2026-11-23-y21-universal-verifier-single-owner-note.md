## 解釈規約（前もって明記）

- 有限照合は有限観察であり、trust 境界（選択肢分解の健全性・mex 恒等式・
  有限型空間の完全性）は y=1..20 系列と同一の機械分類に依存する。
- K1248 の status 昇格は 14チェックの overall PASS + bad 0 + 3回
  byte-identical + fail-closed 電池合格まで行わない。
- A子の x=21 行は正準順序 {20,21}≡{21,20} で y=20 族 x=21 行と同一状態になる
  （合流子 cand20(z,21,R-1)）。この行の特殊扱いを誤ると C4 型機械が偽陽性を
  生む（y=14 の C11 事故型で実証済み）。
- 実行環境がメモリ上限に達した場合は census cap を下げて再実行し、決定的再現を
  記録する（cap 低下は値に影響しない・誠実記録する）。
- byte-identical 主張にはバイトコードキャッシュ衛生（__pycache__ purge・
  python3 -B・PYTHONDONTWRITEBYTECODE=1）を適用する（y=18 fit レーンの
  運用正則を継承）。
- fail-closed 電池（y20 機の種を y21 に翻訳・scratch copy で検出確認）:
  census.txt 欠落・行削除・行重複・T/P 改ざん・idx 改ざん・C11r tail flip・
  C1d anchor 誤結合・lowR R→R+1・merge 境界 z-22→z-21・clip 44→42・
  in_P21 tail parity x%2==0→==1〔奇数 y 型 x 偶行 tail の flip〕・
  band parity 改ざん。検出不能なら電池設計を誤りとして正直記録する。
- 並走実行への配慮: プッシュ直前に最新 main を再取得し、K番号競合・
  同時書込み・取得失敗が起きた場合は無理に押し進めず記録して次回実行に
  回す（publish-then-execute: 宣言は実行に先行して出版する）。
