# 宣言: PG(2,5) s=4 極大safe集合・最小2重ブロッキングの PGL(3,5) 軌道分類 (全数)

- 日時: 2026-11-28
- 種別: 高速レーン (publish-then-execute・単一オーナー)
- 宣言時 HEAD: 709c85152c97a38ae2b88b63d2d4b88a8289e04c
- 目的: K1370 レジューム (c)「PG(2,5) s=4 の軌道分類」の決定。
  K1370 は 2^31 全列挙で個数 (13:15,500 / 14:372,000 / 15:604,500 / 16:595,975・
  計 1,587,975) を確定したが軌道分類は未実施 (「2^31 はこの手法のスケール外」)。

## 手法

1. **C DFS列挙器** (zig cc 0.13.0 build・sha256 pin `d45312e6...` と同一tarball):
   PG(2,q) の点・直線を正準射影座標 (最初の非零座標=1) で構成し、
   31点の include/exclude DFS + 直線カウント枝刈り (>s 即枝刈り) +
   full-line witness カウンタで極大性を葉で O(除外点数) 判定。
   極大safe mask (uint32) を全件ダンプ。各記録集合について補集合の
   2重ブロッキング性・最小性を定義直接検査 (fail-closed: 1件でも違反で exit 1)。
2. **PGL(3,5) 軌道分類** (Node.js): 生成元 4個 (shear×2・座標cycle・対角) で
   |PGL(3,5)| = 372,000 の全要素を BFS 構成して位数検証、
   1,587,975 mask をサイズ別に軌道分割。
   各軌道: サイズ・代表 (最小mask)・line-histogram・
   **安定化群位数を372,000全要素での固定元全数で直接計数** (orbit-size×stab=372,000 を
   fail-closed assert)。生成元集合を変えた再分類で分割独立性も検証。
3. **独立検証** (Python・アフィンモデル): C と異なる点ラベリング
   (z=1 の25点 + z=0,y=1 の5点 + (0,1,0)) で PG(2,5) を再構成し、
   (a) 全 1,587,975 mask を安全性・極大性・補集合の最小DB性について再検査、
   (b) Python 独自生成元で PGL(3,5) を再構成 (位数 372,000 検証) し、
   全 13 軌道代表の軌道サイズを再計算して JS 結果と照合。
