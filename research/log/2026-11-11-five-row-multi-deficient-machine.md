# 2026-11-11 複数行欠損クラス機械（two_deficient_pair_runner）の開発・制御・初スライス

単一行欠損クラス（{0}/{1}/{2}、K0728/K0738/K0739）が完結した後の残課題は
5×19 の複数行欠損 occupancy パターン（≥2行が ≤5 石・他行ちょうど6石）の否定である。
K0727 の blocker-obligation-fill DFS を2行欠損に一般化した。

## 機械（ハイブリッド設計）

- 外側ケース: 欠損行 Y0 の石列 S0（鏡映代表・canonical 順、単一行キャンペーンと同一列挙）。
- 内側: Y0 の空点への blocker 割当に加え、欠損行 Y1 の各点を「石」または「空+blocker」に分岐。
- soundness/completeness 議論: 欠損行の空点 p の blocker は p を含む危険曲線でちょうど6石。
  自分の行は ≤5 石で blocker になれず、他の行は p を含まないため、blocker は census 円
  （7点円・8点円）に限る。全分岐が欠損行の全点を決定し、葉で非欠損行をちょうど6石に fill。

## 制御・検証

1. **全分岐版（非ハイブリッド）の陽性対照**: 欠損行 Y0 の石も分岐する版を 5×18 に適用
   （Y1 は非欠損 = 単一行欠損設定）。**既知2 witness と異なる第3 witness を発見**:
   rows = [[0,1,5,13,17],[3,6,8,10,12,15],[1,3,6,10,12,15],[2,4,6,9,10,14],[6,7,9,11,12,16]]。
   29石・行占有 (5,6,6,6,6)・全89曲線（行5本含む独立census）で ≥7 石なし・
   全66空点がblocker付きで追加不能（独立検証 PASS・鏡映非同値: 既知の
   {0,1,2,6,14}/{5,8,12,14,17} およびその列鏡映とは一致しない）。
   → 石分岐の健全性・witness検出の端まで実証。
2. **2行全分岐（S0 事前決定なし）は爆発**: 5×18 で 600k ノードでも葉に到達せず →
   ハイブリッド設計（S0 列挙を外側に出す）が必要。
3. **5×18・pair {0,1}・S0={5,8,12,14,17}（既知witnessの行0）**: 行1も欠損にした設定で
   17,511 ノードの完全探索で witness 0・leaves 0。つまりこの S0 では
   2行欠損の極大安全配置は存在しない（5×18 でも）。

### 最適化版runnerの重大バグ検出（教訓）

- 本セッションで新規に書いた flat typed arrays 最適化版の**初回実装は2箇所の
  共有バッファバグでunsoundだった**: ①fillRows の unk 配列を module-level 共有
  バッファ化すると fillComb の反復中に再帰 fillRows が同じ配列を破壊する、
  ②tryBlocker の unknowns を共有バッファ化すると再帰 dfs→tryBlocker が破壊する。
  原版は呼び出しごとに新規配列を確保する点が本質。
- バグ版は START=1464 で idx 1464 が 9 ノード（verbatim は 14,442）など
  極端な早期終了を示したのですぐ検出できた。**バグ版の実行結果
  （5504..8377 完走と誤読した分・idx 1464..5141 の 60k cap 実行）はすべて破棄**。
- 修正版（unk/unknowns を呼び出し毎に新規確保、circ/pc/row のみ flat 化）は
  **START=1464 で verbatim A10 と全サンプル ノード数完全一致**
  （14442/14900/890/1502/2548/931/1596/3072/5565/3548/2692/634/1035・
  nextIdx 1677 一致）→ 等価性検証済み。上表 B9' 以降は修正版。
- 修正版の実測速度は verbatim と同水準（600k global cap で安定完走）。
  本環境の16MiB制約下では flat 化の実利は主にメモリで、速度差は小さい。
- 修正版を scripts/two_deficient_pair_runner_flat.ts として保存。
