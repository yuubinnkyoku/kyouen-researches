## 運用記録（教訓）

- **並走との重複回避**: 本レーンの着手時点では w=69..72 まで push 済みで
  w=73..82 が空きだったため 73..82 を担当したが、実行中に並走が
  73..82 も完走させていた。結果は証明内容として完全に一致したため
  「二重独立実装による全幅一致」として昇格格付けに反映した
  （重複計算は無駄にならず、むしろ両レーンの実装独立性で強化された）。
  以後は push 済み state の有無を最初に確認してから計算に着手する。
- **ノード総数のプロトコル依存性を明示**: cap 2.4M 連続チャンクでは
  中止 chunk の部分 mask 探索が再開時に再計上されるため、
  同一探索でも総ノードが実行分割に依存する。
  結論（leaves/生残/完走）は不変・性能比較には clean 単一連続値を使う。
- **実行環境**: 1回のリセット（ローカル state 全喪失）と 1回の一時不能を経験。
  数値はトランスクリプトに即時に記録し、リセット後に制御から再構築した。
  バックグラウンド nohup 実行は run_typescript 呼び出しを挟むと
  kill される観察（bash 呼び出しのみの間は生存）— 長時間計算は
  同期チャンク＋chunk毎永続化が最堅牢。
