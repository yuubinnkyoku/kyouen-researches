# 2026-10-25：11×11四石証明書の二石root合法辺生成を直接四点検査に置換

開始時main: `0cb37a6ccbf6a22433aaf2246a36447f113a9efc`。AGENTS.md、knowledge README、K0023・K0329・K0414・K0416、11×11の実験・最新log・S4検証器とCIを確認した。標準11×11空盤はUNKNOWN。

## 構造的改善

従来の `build_s4_edge_index` は二石rootから第三手を選び、毎回 `legal_after(base | {a})` で121候補を走査した後に `a<b` で重複を捨てていた。しかし標準q=4では二石rootからの第三手はすべて合法であり、四石局面の合法性はその四点の共円行列式が0かどうか**だけ**で決まる。

したがってroot以外の119頂点の無順序対7,021個を各1回だけ直接 `forbidden(first,r2,a,b)` で検査し、合法辺だけを正準化する。S4 classの鍵、raw edge、coverage、S5子検証、cache判定の意味は変えない。不正な二石rootは明示的に拒否する。

## 実測と照合

同じ4×4整数行列式とD4鍵生成を使う局所Python複製で、旧二段 `legal_after` と新しい直接四点判定の全辺リストを比較した。

| root | 合法raw辺 | 旧索引時間（3回） | 新索引時間（3回） |
| --- | ---: | --- | --- |
| {60,0} | 6,894 | 0.1287 / 0.1225 / 0.1244秒 | 0.0686 / 0.0697 / 0.0715秒 |
| {60,27} | 6,871 | 0.1285 / 0.1348 / 0.1260秒 | 0.1238 / 0.0656 / 0.0678秒 |

全辺リスト一致、対称類数はそれぞれ3,396・3,384。中央値で約1.77倍・1.90倍の索引生成高速化（{60,27}新方式1回に外れ値あり）。**局所複製の計測**であり、リポジトリの実行環境・S4検証器全体の速度ではない。

既存の{60,0}全辺照合に加え、{60,27}と非対称root{17,83}を旧二段列挙と全件照合する回帰、および不正root拒否試験を追加。これらのリポジトリ内実行とCIはこの変更時点では未確認。再現：

```sh
python3 -m unittest discover -s research/experiments/n11-search-methods/scripts -p 'test_dfpn_s4_manifest_verify_cache.py'
```

この変更は独立証明書の検査費用を減らすが、**新たな勝敗証明はない**。二石rootの新規閉鎖0、標準11×11空盤UNKNOWN。
