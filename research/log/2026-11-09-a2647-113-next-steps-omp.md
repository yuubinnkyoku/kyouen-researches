## 3. 次の一手の候補（実在するツールに限定）

### 候補A: 固定 d 分割（K0712 形）を ternary 符号化で d 掃引

- **何をどう変えるか**: クラスCNF（c=1 を全対で cardinality）を捨て、K0712 の fixed-d 形で
  1323 個の部分問題に分ける。既存 `parabola-ternary-selection-20261109/ternary.py` は
  まさにこの符号化（d=1323 固定、3値 exactly-one、空対の atmost、
  `--target 1322` で empty_bound = h+2-1322 = 3）で、`run.py` から
  `--target 1322 --budget N --timeout T --output <fresh>` で起動できる。
  サイズ 1323/1324/1325 の既知 UNSAT があるため atmost 3 は exactly 3 と同値（単調）。
  - 規模（**推定**）: `target1293` の init.json は 142,992 節 / 45,249 vars（empty_bound=32）。
    empty_bound=3 では atmost の seqcounter 補助が約 1321×3 に減るため、
    約 6.7万節 / 約8千 vars 程度。クラスCNF（8.6万節）より小さく、かつ d の選択を
    ソルバに押し付けない。[INFERENCE]
  - 全 d を回すには driver が必要（`audit_all_d.py` は `clauses_for_pair` の二値等号CNF用で
    3値＋atmost 版ではない。`ternary.py` は d=1323 直書き・証明出力なし）。
    既存部品: `ternary.encode`, `CardEnc.atmost`, `drat_check_incremental.cpp`（DRAT 検査）、
    `verify.py --audit`（幾何検査）。新規に必要なのは d ループと proof 保存のみ。
- **30分以内の小さな検証**:
  ```sh
  uv run --locked --with python-sat==1.9.dev21 python research/experiments/parabola-ternary-selection-20261109/run.py \
    --target 1322 --budget 100000 --timeout 60 \
    --output /tmp/w3-a113-d1323
  ```
  = d=1323 の1スライスを60秒壁時計で1回だけ。`result.json` の status を見る。
  決着しなければ同一 d で `--timeout 300` を1回だけ。
- **本実行の判断基準**:
  - d=1323 が **SAT** → 点集合を `verify.py --audit` の独立整数幾何で検査し、
    通れば A(2647) ≥ 1322 が確定（上界 1322 と合わせて A=1322）。
  - d=1323 が **UNSAT かつ <60秒**、かつ代表 20 d（例: 1, 50, 100, …, 1000）が
    すべて <60秒 → 1323 d の掃引に進む（各 d に DRAT receipt を保存し、
    `drat_check_incremental.cpp` で VERIFIED を取る。総時間は代表20の中央値×1323で見積もる）。
  - 代表 d のいずれかが 300秒 UNKNOWN → 掃引しない（候補Bへ）。
  - 全 d UNSAT + 全 DRAT VERIFIED が得られて初めて A(2647) ≤ 1321。

### 候補B: 単一クラスCNF上で B_d を assumption にした d 掃引（学習節共有）

- **何をどう変えるか**: `search_shape_class.py` の `build()`（4値＋cardinality）をそのまま使い、
  ソルバを1個だけ作って `solve(assumptions=[v(d,"B")])` を d=1..h で繰り返す。
  各クエリは「その d が唯一の完全対」に制限した部分問題で、学習節は d 間で共有される。
  c=1 の cardinality はアサインで固定されるため、探索空間の d 重複が消える。
  UNSAT の全 d 被覆はクラス UNSAT と同値（c=1 より完全対が存在する）。
- **30分以内の小さな検証**: 新規 30–60 行の driver（既存 `build()` を import）で
  d=1..50 のみ実行し、1クエリあたりの秒数分布（中央値・最大）と学習節共有の効果
  （最初の10 d と最後の10 d の時間比）を測る。総予算 20分で打ち切り。
  注意: クラスCNFの (1,1,3) は d 非固定で「1.5時間 UNKNOWN」なので、この実験は
  「assumption で d を固定すると実際に速くなるか」の測定であって、本実行ではない。
- **本実行の判断基準**: 50 d のうち 45 以上が <2秒、最大 <30秒 → 残り 1273 d を掃引
  （見込み 1–2時間）。中央値 >10秒 または 1件でも >300秒 → 中止し候補Aの代表 d 結果と比較して
  「d 固定で速くならない」ことを確定させる（負の結果として記録）。
- **注意**: この形では DRAT 証明の取得が素直でない（assumption 下の UNSAT 証明は
  assumption を単位節として追加した CNF で取り直す必要がある）。監査可能な receipt が
  必要な場合は候補Aのように d ごとに CNF を書き出す。

### 候補C: (1,1,3) クラスCNFの 1–3 節緩和 probe で下界側の候補点集合を作る

- **何をどう変えるか**: クラスCNFの各辺節に緩和変数 r_c を足し `atmost(k)` を課して
  k=1..3 を問う（`maxsat_probe.py` の方式）。SAT なら違反節の支持点を1点ずつ除いて
  サイズ 1322−k の点集合を作り、`verify.py`/`verify_subset.cpp` の独立整数幾何で
  禁止四点0件を確認する。成功すれば A(2647) ≥ 1321 が一気に得られる
  （現下界 1296）。既存 `maxsat_probe.py` は fixed-d 二値等号CNF専用で、
  4値・cardinality 版は未実装。`decode_model` の負リテラル/支持点の修正
  （README「SATモデル解釈の修正」）を流用する。
- **30分以内の小さな検証**:
  1. p=5,7,11,13,17 の小素数でクラスCNF＋緩和の符号化を全列挙と照合
     （既存 `parabola-ternary-selection-20261109/regression.py` の三値全割当検査と
     `test_projection.py` の整数4×4検査を雛形にする）。
  2. p=2647 (1,1,3), k=1 を 60秒壁時計で1回。SAT/UNSAT/UNKNOWN を記録。
- **本実行の判断基準**: k=1 が SAT かつ修復点集合が幾何検査を通る → 直ちに k=2,3 へ進み、
  得られた最大サイズを K 項目化。k=1 が UNSAT → k=2,3 は見込みが薄いので
  （規模が増えるだけ）打ち切り、候補A/B に資源を寄せる。k=1 が UNKNOWN → 60秒では
  判断せず、候補Aの結果を待つ。
- **限界**: この候補は (1,1,3) の UNSAT を証明しない。目的は上界ではなく**下界の引き上げ**で、
  上界 1321/1322 の決着には候補A（またはB）が必要。

### 補足（候補に数えない）

- **単一CNFの再実行（既定 20M conflicts、壁時計上限なし）**: 記録は 3M/1.5時間のみなので、
  予算を上げただけの再実行は未試行ではある。ただしアプローチの変更ではなく、
  同じUNKNOWNの再現にしかならない可能性が高い。候補A/B の比較対照としてのみ価値がある。

  単独では不十分で、候補A/B の各CNFに併用する小改善としてのみ意味がある。
