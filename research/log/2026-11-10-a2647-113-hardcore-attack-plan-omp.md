### 2.2 候補A方式(d ごとに固定CNF+DRAT、W10 第2部)

**符号化の候補は2つ**:
- (a) W10 が書いた (1,1,3) クラスCNF 17,180 変数 / 90,891 節(実測)に単位節 `[B_d]` を足す。
- (b) K0712 の三値符号化。実測されている d=1323 固定版は **7,926 変数 / 68,404 節**で
  約1/3の大きさ。以下 (b) の実測値で見積もる。

件数は **1,323 CNF**(d=1..1323)、硬い核のみなら **1,294 CNF**。

**符号化の同値性(`ternary.py` を読んで確認)**: 三値版は d を「両点選択」に固定し、
残り 1,322 対に low/high/empty の三値を割り当て、`:68` で
`CardEnc.atmost(empty_vars, bound=h+2-target)` を課す。h=1323、target=1322 なので
bound=3 = **空き対 ≤ 3**。`:102` の不変量 `size = h+2-len(empties) = 1325-e` より、
許可されるモデルは **サイズ 1322, 1323, 1324, 1325** の (1,1,·)。
- サイズ1322(e=3)はまさに (1,1,3)。
- サイズ1323 は4クラスとも UNSAT(`shape_class_2647_1323.json`、実測)。
- 安全集合族は**下方向に閉じる**(サイズ n の安全集合の任意の部分集合も安全)ので、
  サイズ1323 の不在はサイズ 1324/1325 の不在を含意する。
よって三値版と (1,1,3) は**同じ可解性**を持ち、三値版の UNSAT は (1,1,3) の UNSAT と同値
[INFERENCE: 上記2点からの推論]。ただし receipt には「三値版で UNSAT」と書き、
「(1,1,3) の UNSAT」への読み替え根拠(サイズ1323 UNSAT + 下方向閉包)を併記すること。
読み替えの鎖のうち 1323 側は独立監査済みの別 receipt に依存する。

### 2.3 cube-and-conquer 等の分割

**データから言えること**:
1. d 間の独立性は本物(full100k の各 d は互いに別の部分問題)。したがって**並列化の第一手段は
   d 方向の分割**であり、これは既に 1 コアで直列に走らせているのを 4 コアに広げるだけで
   3–4 倍の壁時計短縮になる。追加の研究は不要。
2. **d の内部**を分割する根拠はデータに無い。100k 掃引の秒数分布は
   中央値 44.0 / p99 80.7 と**単峰で裾が薄い**(p99.9 = 158.9、最大 431.9 は1点)。
   ただしこの分布は **100k で打ち切られた分布**であり、これより右側については
   情報が無い。裾が薄いのではなく、裾を観測できていないだけかもしれない。
   「一部の d だけが極端に硬い」のではなく「大半の d が同じくらいの硬さ」である。
   これは [INFERENCE] だが、cubing の効く典型形(探索木の上部に大きな分岐)とは逆の像で、
   一様に硬い問題は cubing しても部分問題が全部硬いまま残りやすい。
3. したがって cube-and-conquer の期待は**壁時計の短縮(≤コア数倍)**であって、
   総仕事量の削減ではない。総仕事量はむしろ増える(文献的には 1.2–3 倍)[INFERENCE]。
   1,294 h の見積もりを cubing で 100 h にすることはデータ上期待できない。
4. 反証的データ: d=488 が 431.9 s(他は 44 s)。局所的な難所は存在する。もし難所が
   cube で割れるなら効くが、1 点の観測では設計根拠にならない。

**結論(データが支持する範囲)**: 分割は「d 方向の並列」に限定して有効。d 内部の cubing は
根拠なし。候補Aの d ごと独立CNF はまさにこの d 方向分割を最大化した形である。

### 2.4 補足: SAT 側の費用

もし (1,1,3) が SAT なら証人は安い。1296点の独立幾何検査が 28.9 s、1322点でも同オーダー
(約35 s)[INFERENCE]。**探索の側**は無料ではなく、局所探索の実績は
「1,000,000 flips / 9.144 s / 最良41違反」(サイズ1325 等号テンプレート、seed=20261009)で、
10^10 flips なら約 25 CPU-h。ただし (1,1,3) クラスの CNF に局所探索を当てた実績は
**repo に存在しない**(grep で確認: `flips` を含むログは p2647-local-walk 系のみ)。

## 第3部: 優先順位つき次手(3件)

前提として1つ、データが否定した仮説を先に潰しておく。

**「d ≡ 32 (mod 63) 族が易しい」は d=851 で途切れている。** 族の全21要素は
32, 95, 158, 221, 284, 347, 410, 473, 536, 599, 662, 725, 788, 851, 914, 977, 1040, 1103, 1166, 1229, 1292。
実測では **k=0..13 (d=32..851) の 14 件が全部 UNSAT**、所要は 0.081–14.236 s で
k とともに増える(0.11, 0.10, 0.11, 0.09, 0.10, 0.09, 0.12, 0.13, 0.29, 0.31, 6.12, 14.24)。
**k=14..19 (d=914..1229) の 6 件は全部 UNKNOWN(100k)**。つまり族は
「易しい d の集合」ではなく「難度が単調に上がる列」であり、100k 予算では k≈14 で切れる。
W9 の合同式シグナル(d≡4 mod 7 等)は、**この族についてすでに予算の壁に当たっており、
1M でも未検証**である。加えて W9 が挙げた反例 d=1300 は 1300 mod 21 = 19 で族の外にあり、
1M で 0.022 s の UNSAT。すなわち合同式は「易しさ」の必要条件でも十分条件でもない
(偽陽性・偽陰性の両方が実測されている)。**停止条件には使えない**のは勿論、
順序付けにも「多重検定で選んだ mod 7 / mod 3 のセル」は使わない。順序に使えるのは
**実測 100k 秒数**だけであり、これは仮説ではなく測定値である。

### 次手1(推奨): 候補A の予算ラダーを層化19 d で測る = 決定可能性のゲート

**何をするか**: 候補A(三値・d 固定・target=1322)で、層化抽出した19 d について
3M → 10M → 20M を順に。各段で決まったら止める(次の d へ)。抽出は
100k 秒数の層から: 速い層 {602, 194, 188}、中央層 {1258, 622, 820}、高層 {717, 1003, 703}、
裾 {1266, 147}、外れ値 {488}(431.9 s)、族の未決着 {914, 977, 1040, 1103, 1166, 1229} と **1292**(sweep 完走後に記録が付く)。
出力は既存の `parabola-ternary-selection-20261109/output/` の流儀(`init.json` に
CNF/入力/worker の SHA-256、`result.json`、`run.json`)で新規ディレクトリに。
これら19 d は捨て実験ではなく **1,294 件本番の最初の19件**になる。

**予算**: 求解のみ。層化12 d + 族の未決着6 d(914, 977, 1040, 1103, 1166, 1229)+ 1292 の
計 **19 d** でも、1 d あたり 605 + 2,017 + 4,034 = 6,656 s(3M のみ実測、10M/20M は
4,958 cps の線形外挿)なので **126,464 s = 35.1 h 単一コア**、3 コアで **約 11.7 h**。
途中で決まった d は以降の段を飛ばすので、実際はこれより短い。
DRAT は決定した d についてのみ取る(易例実績のチェック中央値 1.4 s、
硬い d では未測 — 10 倍見ても 19 件で数分)。

**期待される情報利得**: これが今の唯一の**分岐点**。今あるデータは「候補B が 100k で 0/421
(d>851)、1M で 0/13」しか持っていない。予算を上げると決まり始めるのか、
それとも全く決まらないのかは、この 19 d で初めて測れる。
- 19/19 がどこかで決まる → 決定可能性は開いている。20M の実測 cps から総量を再外挿し、
  本番(1,294 件)の実行計画を確定できる。同時に A(2647) の判定手順が receipt 付きで立つ。
- 一部だけ決まる → 「決まる d と決まらない d」の境界ができ、それは
  2.1 の総時間見積もりの分散を実測で置き換える。
- 0/19 が 20M でも UNKNOWN → 候補A も候補B も硬い核に対して決定手続きでないことが判明し、
  1,280 h の支出を回避できる(この情報だけで 35 h の元は取れる)。

**やめる条件**: 20M 段で 19 件中 0 件も決まらなければ、その時点で
「候補A/B の予算増は無効」と結論し、次手3(SAT 側)へ移る。個々の d については
20M(4,034 s)を使い切ったら打ち切る。**打ち切りは判定ではなく UNKNOWN のまま記録する。**

### 次手2(ほぼ無料): 100k 掃引の完走と、残り d の UNKNOWN 確定

**何をするか**: 走っている `w7-assump-2647-1322-full100k.json` を d=1323 まで完走させる。
追加コストは **残り 49–51 d × 44 s ≈ 36–37 分**、介入不要(プロセスが既に走っている)。

**期待される情報利得**: 小さい。d>851 の 421 d で UNSAT 0 件だったので、
残り約 50 d でも 0–1 件と予想される[INFERENCE]。得られるのは
(i) 「100k 予算の全 d 完了」という完全な難度地図、(ii) 次手1 の層化抽出を
全 d から引けること、(iii) W10 第3部の下書きを「未実行 818 d」から「全 d 実行済み」に更新できること。

**やめる条件**: 無し(既に走っているので止める理由がない)。ただし
**この掃引を「クラス UNSAT の証拠」と読まないこと**。100k で UNKNOWN の 1,243 件は
UNSAT でも SAT でもない。判断は次手1 の結果を待つ。

### 次手3(並行可): SAT 側の局所探索ポートフォリオ

**何をするか**: (1,1,3) クラスの三値 d 固定 CNF(7,926 変数 / 68,404 節)に対し、
無作為再スタート付きの局所探索(WalkSAT/Minos 系、seed 固定、1 試行 10^8 flips 程度)を
d を巡回させながら回す。証人が出たら独立幾何検査(1296 点で 28.9 s、1322 点で同オーダー)
だけで A(2647) = 1322 が確定する。

**予算**: 局所探索の実測は 1,000,000 flips / 9.144 s(**ただしサイズ1325 の等号CNFで、
(1,1,3) クラスでの実績は repo に存在しない**)。flips 速度をそのまま流用すると
10^10 flips ≈ 25 CPU-h。まずは **4 コア × 6 h = 24 CPU-h** の上限で 1 バッチ。

**期待される情報利得**: 不確実だが非対称。SAT が1件でも出れば A(2647)=1322 が
35 秒の検査で確定し、以降の 1,280 h が不要になる。出ない場合は
「24 CPU-h 探して見つからない」という弱い情報しか得られない(不在の証拠にならない)。
局所探索の強みは、厳密求解が UNKNOWN を返し続ける領域でだけ効く点にある。

**やめる条件**: 24 CPU-h を使い切ったら止める。**その結果を UNSAT の根拠にしない。**
また、局所探索の「最良違反節数」を進捗指標にして予算を延長しない
(サイズ1325 では最良41違反で止まっており、その数値は幾何的最大値と別の量 — W10 §2.3 と同じ留保)。

### 位置づけの補足(硬い核の外だが前提)

A(2647) ≤ 1321 を主張するには 4 クラス全部の UNSAT が要る。サイズ1322 の残り3クラスは
(0,0,1) 0.6 s、(0,1,2) 618.4 s、(1,0,2) 7.8 s でいずれもソルバ主張 UNSAT だが
**DRAT receipt が無い**。この3件の監査は求解 627 s + チェックで数時間規模であり、
(1,1,3) が決着した瞬間に必要になる。次手1–3 と独立に進められる。

## 第4部: 結論 — 最初に実行すべき1手

**次手1(候補A の予算ラダー、層化19 d、3M→10M→20M)を最初に実行する。**

根拠を実測に結びつける。

1. **今のデータは「決定可能性」について何も言っていない。** full100k の UNKNOWN 1,243 件(12:33 読取。12:35 には 1,245)は
   100k で決まらなかったという**打ち切り付き観測**であり、その先の分布について情報が 0。
   probe1m は 13 件の UNKNOWN(いずれも予算全消費)で、1M でも決まらなかったという
   同じ種類の打ち切りを 13 件追加しただけ。**現在の観測から 10M で決まる確率は推定できない。**
   推定できないまま 1,280 h を投じるのは、コストの 99% を無情報の上に賭けることに等しい。

2. **分岐点を測る費用は 35.1 h 単一コア(3 コアで 11.7 h)。** 候補Aの実測
   605 s / 2,017 s / 4,034 s(3M は実測、10M/20M は外挿)を 19 d に適用した値。
   これに対し、ラダーを通さずに走らせた場合の支出は
   候補B 10M = **918–1,613 h 単一コア**、候補A 3M 全 d = **232–322 h 単一コア**。
   **35 h(3 コアで 11.7 h)で 1,000 h の可否が決まる**のがこの手の唯一の理由である。

3. **候補Aを選ぶ理由は総時間ではなく receipt。** 候補A は 100k で 6,975 cps、
   候補B は 2,278 cps(全 d 平均)なので、同じ予算なら候補A が 1.7–3 倍速い。
   さらにクラス UNSAT を主張するには DRAT が要り、assumption-UNSAT は receipt にならない
   (W10 §2.1)。候補Aで決まった d はそのまま監査資産になる。**同じ費用で
   より強い主張ができる側を先に測るのは、無料の選択。**

4. **候補Bを先に 1M で全 d に広げる案は、既に部分的に反証されている。**
   probe1m が決めたのは 3/16。うち d=1, 300 は 100k でも UNSAT の既知易例、d=1300 は
   100k 未実行だが 1M で 0.022 s(易例)。**100k で UNKNOWN だった13件は 1M でも全部 UNKNOWN
   — 硬い核の d で 1M が決めた例は 0/13。**
   1M 全掃引は 92–161 h 単一コアで、期待される決定数は 0–数件[INFERENCE]。

5. **d≡32 (mod 63) 族を先に潰す案は、予算の壁で止まっている。** 族の
   k=0..13(d=32..851)は全部 UNSAT だが所要は 0.08→14.2 s と増加し、
   k=14..19(d=914..1229)は全部 UNKNOWN(100k)。族は易しさの集合ではなく
   **難度が単調に上がる列**である。族を優先するなら、まず
   「914, 977, 1040, 1103, 1166, 1229, 1292 が 3M で決まるか」を測る必要があり、
   これは次手1 の層化サンプルに含めてある(族の 6 件は実測で既に UNKNOWN と分かっているので、
   無駄打ちにならない)。**族だけを特別扱いして予算を積む根拠は無い。**

6. **多重検定の留保を明記**: 「UNSAT 29件の 55%(16/29)が d≡11 (mod 21)」は
   21 通りのセルを見た後の最大値であり、事前に選んだセルではない。しかも
   d=1300(1300 mod 21 = 19)が 1M で 0.022 s の UNSAT という反例がある。
   よって **mod 7 / mod 21 / mod 3 のシグナルは順序付けにのみ使い、打ち切り・除外・
   クラス判定の根拠にしない。** 順序付けに実測以外を使わない、が本ログの運用方針。

### 実行順(具体)

1. 走っている full100k を完走させる(執筆時点の残り 49 d、約 36 分、介入不要)。これで難度地図が閉じる。
2. 次手1: `parabola-ternary-selection-20261109/ternary.py` を target=1322 で、
   d ∈ {602, 194, 188, 1258, 622, 820, 717, 1003, 703, 1266, 147, 488,
        914, 977, 1040, 1103, 1166, 1229, 1292}(19 d)
   に対し 3M → 10M → 20M の順で。3 コア並列、1 d 1 プロセス。各結果は
   `output/` の下に新規ディレクトリ、`init.json` にベースCNF/入力/worker の SHA-256 を記録。
3. 決まった d についてのみ `drat-trim` で証明を取り、`independent_check.py` で検証。
4. 20M で 0/19 なら次手3(SAT 側 24 CPU-h)へ移り、候補A/B の予算増を打ち切る。
5. 並行して次手2補足: サイズ1322 の残り3クラス(0,0,1)/(0,1,2)/(1,0,2)の DRAT を取る
   (求解 627 s、receipt 化は数時間規模)。これは A(2647)≤1321 の前提を固める作業で、
   次手1〜3 の成否に依存しない。

## 付録: 使用した計数スクリプト

すべて読み取り専用(`json.load` のみ、書き込みなし)。repo 内のファイルは本log以外変更していない。
以下は実行内容の記録で、bash のヒアドキュメントから実行した。

```python
# A. 掃引の形状・内訳・UNSAT一覧・区間統計
import json, statistics as st
d = json.load(open('.../w7-assump-2647-1322-full100k.json'))
r = d['records']; B = d['budget']
assert [x['d'] for x in r] == list(range(1, len(r)+1))      # 連続・欠番0
uns = [x for x in r if not x['unknown'] and not x['sat']]
print(len(r), len(uns), sum(x['unknown'] for x in r), sum(x['seconds'] for x in r))
for lo in range(1, 1301, 100):                               # 100 d ビン
    xs = [x for x in r if lo <= x['d'] < lo+100 and x['unknown']]
    if xs: print(lo, st.median(x['seconds'] for x in xs),
                 st.median(B/x['seconds'] for x in xs))       # 秒 / 実効 cps

# B. 打ち切り分布の分位点(UNKNOWN のみ)
u = sorted(x['seconds'] for x in r if x['unknown'])
print(len(u), [round(st.quantiles(u, n=100)[k-1], 1) for k in (50, 90, 95, 99)], round(u[-1], 1))

# C. 候補A の予算別総量(実測 1 点 d=1323 からの線形外挿)
for cost, budget in ((14.34,1e5), (605.0557,3e6)):
    print(budget, cost, cost*1323/3600, cost*1294/3600)      # 単一コア時間

# B'. cps の d 依存(単回帰と遅い窓の除外)
x = [(rec['d'], B/rec['seconds']) for rec in r if rec['unknown']]
mx = sum(d for d, _ in x)/len(x); my = sum(c for _, c in x)/len(x)
slope = sum((d-mx)*(c-my) for d, c in x)/sum((d-mx)**2 for d, _ in x)
print(slope, my - slope*mx)          # -0.0217, 2408
w = [c for d, c in x if 426 <= d <= 489]
print(len(w), st.mean(w), st.median(w))   # 60, 2116, 1963

# D. probe1m の決定率(d=1,300 は 100k で既知、d=1300 のみ新規)
p = json.load(open('.../w7-assump-2647-1322-probe1m.json'))['records']
print(sum(1 for x in p if not x['unknown']), [x['d'] for x in p if not x['unknown']])

# E. 合同式の確認(多重検定の留保つき)
from collections import Counter
print(Counter(x['d'] % 21 for x in uns))                     # 11: 16 件
print(sorted(Counter(x['d'] % 63 for x in uns).items()))      # 32: 14 件
fam = [(x['d'], x['seconds'], x['unknown']) for x in r if x['d'] % 63 == 32]
print(fam)   # k=0..13 UNSAT(0.081-14.236s), k=14..19 UNKNOWN(30.7-52.0s)
```
