# z=11・y>=6 一様 2トークン全Grundy分類（K1055）研究ログ

2026-11-19。高速レーン。着手時点の main は K1051 前後・HEAD `161924293309...` だったが、作業中に並走レーンが K1052..K1054（z=19,20,21 の y=2 切片）を連続出版したため、反映前に最新 main を取り直し、本項のK番号は K1055 に確定した。

## 動機と重複確認

- 未解決リスト確認: K1037（z=11,y=5）は「z=11のy=6（B=K1037・C=1⊕K1008で着手可能）」を残し、K1043（z=12,y=5）も「z=11のy=6が着手可能」と明記していた。他レーンの宣言は z>=16,y=2 系と z=13..15,y=3..5 切片で、z=11,y>=6 一様族は未着手。
- K1011（z=10,y>=9 一様）の proof 構成（y強帰納+行内x外帰納、(y,d)パラメトリック署名帯表）を z=11 に移植し、値レベルで試算すると y=6 行から既に一様パターンが成立していたため、y>=6 全域を 1 本の定理にまとめる方針とした（K1011 が y=9 まで 3 切片を要したのと対照的）。

## 導出

1. エンジン実装（順序保存版・降順正準化版の 2 直接 mex 再帰）と K1037/K1002 の転写を整備。K1037 転写はエンジン照合 0 不一致、K1002 転写（y>=6 全域一様式、proved）は 3,380 点照合 0 不一致。
2. 値閉形式候補 v11（T/P + tail）を導出し、y=6..12・d=0..15、y=15,20,25・d=0..9 の濃密グリッドでエンジン照合 6,037 点 0 不一致。
3. 子署名 {B,A,C} を閉形式で計算する導出器（band_derive.py）を書き、parity 別に帯圧縮して (y,d) クラス構造を読み取り。初版で K1037 呼び出しの引数バグ（r=R-1 を渡すべき所にリテラル 5）を発見・修正。
4. クラス分類確定: 偶 d 段階形 {0},{2,6},{4,8},10 境界、d>=12 定常; 奇 d は t=min(2y+7+2⌊(d+1)/4⌋,2y+13) の格子クラスと pin 規則（d≡3 (mod 4) または d>=11）。d=12 掃引、d=13 の偶末尾署名「12」は A 子が d-1=12 掃引列で全域に値 2 を供給する影、d=11 の偶末尾「023」は A 子 d=10 列の値 0 と C 子の z=10 掃引行 d=11 の 1 xor 2=3、d>=15 で A の pin が単点に戻り末尾「1」に定常化。(y,d)=(6,0) の縮退セル（K1037 h=z 行 x=6 のラダー O[1,15] による値 2 混入）を別クラス化。
5. 署名帯表 bands.py を正本アーティファクトとして実装し、まず 122,057 点の被覆検査（一意被覆・parity 一致）で 0 不良、次いで帯表 sig = 閉形式子・mex = v11 を y=6..60 全 d=0..40 + 大 y (1000) で 531,543 点ずつ 0 不一致。
