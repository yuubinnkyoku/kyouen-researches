## 結果

`p=3251`（`h = 1625`）。サイズ `h+1 = 1626` の 3 形状すべてが UNSAT:

| 形状 | `(x,c,e)` | 判定 | 時間 | 変数/節 |

- 形状 (c) は `D:\tmp\shapec\shape_c_3251.cnf` を WSL の cadical 1.7.3（**既定設定**、
  `--sat` ではない）で解いた。ログは `cadical_3251_def.log` で最終行が `s UNSATISFIABLE`。
  200 万衝突（1,210 秒）では未決だったものが、既定設定の長時間走行で決着した。
- 3 形状はサイズ `h+1` の分類を尽くすので、**サイズ 1626 の安全集合は存在しない**。
  したがって `A(3251) <= 1625 = h`。
  従来の上界は K0708 の「サイズ `h+2 = 1627` が無い」からの `A <= 1626` だったので、1 改善。

## 検証の状態

- いま記録した `A(3251) <= 1625` は **cadical の主張**であり、まだ証明書を検査していない。
- CNFは repo に入れた: `output/cert-3251-1626-shapec/a3251_1626.cnf`
  （12,998 変数・91,135 節、sha256 `ac06449e...`）。証明を出した CNF と再生成 CNF の hash 一致を確認。
- cadical のテキスト DRAT（`--no-binary`）は **212 秒で 143,562,752 バイト**に達し、
  全体で 2 GB 超の見込み。既存の `drat_check_incremental.cpp` は約 1.3k 行/秒なので
  検査に数日かかる。→ 走行を中断した。
- 代わりに Glucose4（pysat、`with_proof=True`）で証明書を作り直している。
  p=2647 での予備測定は 45,974 行（12.8 秒）で cadical の 126,556 行より短かった。
- 併せて Glucose4（証明なし）で同じ CNF を 2,000 万衝突まで走らせ、独立に UNSAT を確認中。
- 検査が通るまで K0775 の status は `needs-review`。通れば `computed` に上げる。
