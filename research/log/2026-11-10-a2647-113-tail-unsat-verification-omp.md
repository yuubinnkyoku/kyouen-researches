# W17: 掃引尾部「即UNSAT」現象の独立検証（p=2647, size=1322, 形状 (1,1,3), 候補B）

- 日付: 2026-11-10
- 対象: p=2647, size=1322, 形状クラス (x,c,e)=(1,1,3)、候補B（assumption `B_d` の d 掃引）
- W11 の続き: W11 は「易UNSAT は昇順共有学習節のアーティファクトか」(H4) を
  d∈{851,478,300,1} で棄却した。本タスクは新事実「d=1279..1316 の 38 連続
  即UNSAT」に対し、同じ独立性検査（履歴ゼロの新規インスタンス）を適用する。

## 方法

読み取り:
- 掃引本体 `output/w7-assump-2647-1322-full100k.json`（同時刻に走行中のため増加する。
  本節の数値は **2026-11-10 12:53 JST 時点のスナップショット**を `/tmp/w7-snapshot.json`
  に複製して読んだもの、1,320 レコード、クラス (1,1,3)、vars=17180, clauses=90891,
  kept_edges=53886, budget=100000）。
- 参考 `output/w7-assump-2647-1322-probe1m.json`（budget 1M、16 点）。
- W11 出力 `output/w11-artifact-reverse.json`, `output/w11-artifact-fresh.json`。
- W14 出力 `output/w14-cross-solver.json`（交差ソルバ、d∈{1,100,300,478,851} のみ）。

新規プローブ: `research/experiments/parabola-p2207-no-equality-witness-20261107/tail_fresh_probe.py`
（W11 の `reverse_order_probe.py` の fresh-each モードを土台にした別ファイル）。
出力: `output/w17-tail-fresh.json`（掃引 JSON へは書き込まない）。

掃引と**同じ**点:
- クラス CNF は `search_shape_class.build(p, edges, 1, 1, 3)` をそのまま使用。
  生成器 `forbidden_edges.exe` は `run_gen` 経由（`$TEMP` 既定、本実行では
  `$HOME/workspace/kyouen-omp/bin/forbidden_edges.exe` を明示）。
- ソルバ `pysat.solvers.Cadical195`、`conf_budget(100000)` + `solve_limited(assumptions=[B_d])`。
- 判定は sat / unknown / UNSAT の3値。SAT 時は `decode` + 禁止4点集合の `safe_against_edges` 検査。

掃引と**違う**点（独立性の差分）:
- 掃引: **1 インスタンス**で d=1..1323 を昇順。各 d の CNF は同一で、学習節は全 d で共有。
- 本プローブ: 対象 d を **1 件ずつ新規 Cadical195**（bootstrap 直後、学習節ゼロ）で解く。
  掃引の昇順履歴も、同一起動内の他 d の履歴も存在しない。
- 追加計測（解き直しなし、統計のみ）:
  - `unit_conflict`: `propagate(assumptions=[B_d])` が単体伝播だけで矛盾を出すか。
    ここが True なら「即UNSAT」は探索なしの伝播閉包だけで説明できる。
  - `conflicts` / `decisions` / `propagations`: その d の解に費やした Cadical 統計。
    `solve_limited` 前後の `accum_stats()` 差分。
- 1 件の実時間上限 **300 秒**（`threading.Timer` → `solver.interrupt()`）。判定は
  `solve_limited` の 3値のまま（打ち切り時は `unknown=True` かつ `wall_timeout=True`）。

対象 d（8 件、指定どおり）:
- 尾部内: {1280, 1290, 1300, 1310, 1316}
- 境界: {1317}（掃引では UNKNOWN）
- 尾部外の対照: {1322, 1200}

時間予算: 全体 ~20 分。CNF 構築は約 1 秒（W14 の cache 元 build_seconds 0.8）。
硬い側（1317/1322/1200）は 100k conflicts で 27〜181 秒/件と見積もられるため、
超過しそうなら対照側から削り、削った d をここに明記する。

**留保（W11 と同一の上限）**: 全モードが同一ソルバ (Cadical195)・同一符号化・同一予算。
排除できるのは「学習節の履歴依存」だけで、「この符号化＋このソルバの組合せに固有の
易しさ」は排除しない。完全な独立検証ではない。

  この「窓」は本節の観察事実であり、機構の説明ではない（§結論で仮説として扱う）。

**観察**: 掃引は 1 インスタンスの昇順実行なので、d=1279 の時点で既に 1,278 回分の
学習節が積まれている。区間の切り方が d についても r についても鋭いことは、
「履歴」と「d 固有の算術」のどちらでも説明可能で、掃引だけでは分離できない。
（この分離が §2 の fresh-each の目的。）

`unit_conflict` は全 8 件 `false`（assumption の単体伝播だけでは矛盾を出さない）。
`wall_timeout` も全 8 件 `false`（総実時間最大 72.4 秒 < 300 秒）なので、

（seconds は `solve_limited` 区間、`total_seconds` は CNF 構築込みで 0.215〜72.374 秒。）

読み取り:

- **尾部 5 点は履歴ゼロでも全て UNSAT**。掃引で UNSAT だった d=1280/1290/1300/1310/1316 は、
  学習節も昇順履歴もない新規インスタンスで同じ判定に到達した。
- **ただし「伝播だけで即 UNSAT」ではない**。全点 `unit_conflict=false` で、
  1280/1290/1300/1310 は 565〜946 conflicts（0.10〜0.21 秒）、1316 は 33,464 conflicts
  （20.9 秒、予算の約 1/3）を要した。「即UNSAT」の実体は
  「予算 100k に対して 3 桁小さい探索で閉じる」であり、探索ゼロではない。
- **尾部は一様でない**。1280〜1310 は約 0.1〜0.2 秒・10³ conflicts 級だが、
  1316 は 1 桁上の 20.9 秒・3.3×10⁴ conflicts。掃引の秒数（1314 が 2.057、
  1315 が 1.368、1316 が 4.319）と同じく、区間の上端で費用が増える向きに一致する。
- **境界と対照は UNKNOWN**。1317 は 100,004 conflicts で打ち切り（55.1 秒）、
  1322 は 100,003 conflicts（72.2 秒）、1200 は 100,000 conflicts（59.0 秒）。
  いずれも掃引判定（1317/1200 は UNKNOWN）と一致し、W11 の fresh/逆順での
  d=1322 UNKNOWN とも判定が一致する（秒数は 34.493 対 72.204 で異なる）。
- **掃引との費用差（実読事実）**: d=1316 は掃引 4.319 秒 / fresh-each 20.853 秒。
  履歴はこの点で約 5 倍の高速化を与えたが、判定 (UNSAT) は変えていない。

## 結論

1. **尾部 UNSAT は履歴ゼロで再現する。** d=1280, 1290, 1300, 1310, 1316 の 5 点は、
   学習節も昇順履歴もない新規 Cadical195 で、掃引と同じ UNSAT に到達した。
   したがって尾部 UNSAT は「d≤1316 までの学習節の蓄積」の産物ではなく、
   **CNF（p=2647, size=1322, クラス (1,1,3)）と assumption `B_d` の組に固有の性質**である。
   掃引が短いのは履歴による加速（1316 で約 5 倍）を含むが、判定自体は履歴非依存。
2. **「即」の内実は探索の省略であって探索の不在ではない。** 全点 `unit_conflict=false`、
   1280〜1310 は 565〜946 conflicts、1316 は 33,464 conflicts を要した。
   主張として書けるのは「予算 100k に対し 3 桁小さい探索で UNSAT が閉じる」であって、
   「伝播だけで矛盾する」ではない。区間は一様でもなく、上端 1316 で費用が 1 桁上がる。
3. **境界・対照は掃引と整合する。** 1317 は fresh-each でも UNKNOWN（100,004 conflicts で
   打ち切り、55.1 秒）、1322 は UNKNOWN（100,003 conflicts、72.2 秒）、1200 は UNKNOWN
   （100,000 conflicts、59.0 秒）。境界 d=1317 が UNKNOWN である点は掃引と一致し、
   「1316 まで UNSAT / 1317 から UNKNOWN」という切れ目は履歴なしでも保たれる。
   W11 の d=1322 fresh UNKNOWN とも判定が一致する（秒数 34.493 対 72.204 は実行差）。
   よって境界は履歴依存のアーティファクトではない。
4. **§1 の r = p−2d 窓（r=89,87,…,15 が易 UNSAT、r=91 と r=13 は UNKNOWN）は観察事実のまま。**
   本タスクは「履歴」対「d 固有」を分離しただけで、r の算術が機構であることは示していない。
   fresh-each が示すのは d 固有性までであり、その d 固有性の由来（r の窓・符号化の性質・
   ソルバのヒューリスティクスのいずれか）は未分離である。
5. **限界（W11 と同じ）。** 全モードが同一ソルバ・同一符号化・同一予算なので、排除したのは
   「学習節の履歴依存」だけであり、「この符号化＋このソルバの組合せに固有の易しさ」は
   排除していない。完全な独立検証ではない。交差ソルバでの尾部確認は未実施
   （W14 は d∈{1,100,300,478,851} のみ）。
