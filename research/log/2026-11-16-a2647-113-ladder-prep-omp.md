### 1.3 CLI 確認結果（`--help` とソース `src/cadical.cpp` より）

usage は `cadical [ <option> ... ] [ <input> [ <proof> ] ]`。本ラダーで使うのは:

| 目的 | 正確な指定 | 根拠 |
|---|---|---|
| conflicts 予算 | `-c <limit>`（スペース必須） | `--help`「`-c <limit>  limit the number of conflicts (default unlimited)`」 |
| DRAT 証明出力 | 第2位置引数 `<proof>` | `--help`「If '<proof>' is given then a DRAT proof is written to that file」 |
| wall-clock 上限 | `-t <sec>` | `--help`（`_WIN32` 以外） |
| 証人出力 | `-w <sol>` | `--help` |
| 結果行 | `s SATISFIABLE` / `s UNSATISFIABLE` / `c UNKNOWN` | 実測（下記 §3・§2 のスモーク） |
| exit code | 10=SAT, 20=UNSAT, 0=UNKNOWN | 実測（§3） |

**証明フォーマットは既定でバイナリ DRAT**。`--help`「By default the proof is stored in the
binary DRAT format unless the option '--no-binary' is specified or the proof is written to
'<stdout>' ...」。証明ファイルは `trace_proof()` 経由で**名前付きファイルへ直接**書かれ、
RAM に載らない（W23 の pysat 経路との本質的差）。実測の proof 先頭は
`a \xaf\x8b\x02 ...`（`a` + バイナリリテラル、§3.3）。

`-c` を超えて解き続けることはなく、`c conflicts: 1000000 4364.81 per second` を
使って実効スループットを直接読める。

### 3.3 確認事項

1. **pysat 結果との整合**: W23 の pysat Cadical195 は同じ 1M 予算で UNKNOWN・326.828 s。
   ネイティブも UNKNOWN で一致（**矛盾なし**）。時間は real 349.77 s 対 326.828 s で、

2. **証明はディスクへ直接書かれる**: 実行中 `proof.drat` は 4.4 MB（13:09）→ 186 MB（13:13）

3. UNKNOWN のため drat-trim 検証対象なし（空節を含まない）。W20 の「監査済み」規約に従い、

### 5.1 使い方

```sh

#           LADDER_TIME_LIMIT（秒、CaDiCaL の -t に渡す。未設定=無制限）
```

### 5.2 要件との対応（実測で検証済み）

| 要件 | 実装 | 検証 |
|---|---|---|
| 段ごとに独立ディレクトリ | `$WORK/class-113-b<budget>/`（input.cnf.gz, run.log, proof.drat, solver.json, witness.txt, drat-trim.log, audit-drat-trim.json）| 実測 |
| 既存 solver 結果のある段はスキップ | `solver.json` 存在で skip | 実測「already has solver.json ... -> skip」 |
| 下位段が決着済みなら上位段はスキップ | `lower_stage_decided` が下位 `solver.json` の status を走査 | 実測「a lower-budget stage already decided ... -> skip」 |
| solver を setsid で起動 | `setsid --wait "$CADICAL" ...`（呼び出しセッション非依存、終了コードは保持）| 実測（exit code を solver.json に記録） |
| UNSAT 段は gzip してから別ステップで検証 | `$D verify <budget>` が `gzip -c proof.drat > proof.drat.gz` 後に `gzip -dc ... \| drat-trim input.cnf -i` | 実測 verdict=VERIFIED（合成 UNSAT 入力） |
| SAT 段は証人を保存 | `-w witness.txt`。SAT 時は `s SATISFIABLE`+`v ...` 行を含む | 実測（`v -1 2 0`） |
| 進捗ログへ追記 | `$WORK/progress.log`（start/end/gzip/verify/skip を ISO 時刻付きで追記）| 実測 |
| 引数で段を指定 | 第1引数を budget（数値）として受理 | 実測 |

補足:
- 段は決着するまで次へ進めず、**決着済みならラダーはそこで停止**する
  （UNSAT→p≤1321、SAT→p=1322 が確定）。UNKNOWN の段は呼び側が次段を起動する。
- 検証段は SAT/UNKNOWN の段を拒否する（`not SOLVER_UNSAT; nothing to verify`）。
- 入力 SHA-256 を solve 前に必ず検査し、不一致なら中止する。
- 証人出力は UNKNOWN 時は `c UNKNOWN`（判定不能、無害）。

### 5.3 検証に使った実行（すべて実測・一時ディレクトリ）

- `$D 1000` / `$D 2000`: UNKNOWN、solver.json に budget/conflicts/real_seconds/proof_sha256 を記録。
- 合成 4-clause UNSAT: `$D verify <b>` → `verdict=VERIFIED`（drat-trim `s VERIFIED`）。
  バイナリ DRAT を **stdin から読む場合は `-i` が必須**（実測: 引数なし stdin では
  drat-trim はバイナリを自動判定せず `s NOT VERIFIED` になる。`-i` を付けると `s VERIFIED`）。
  本ドライバは `gzip -dc proof.drat.gz | drat-trim input.cnf -i` の形で常に `-i` を渡す。
- 合成 SAT: `witness.txt` に `v -1 2 0`、`$D verify <b>` は拒否（rc=2）。
- 一時テストディレクトリは削除済み。本番 `$WORK`（`tasks/w30-ladder-113`）は空のまま。
