# 2026-10-30：11×11 LOSS6由来LOSS5と凍結S5 cacheの交差監査・S4被覆差分

開始時main `3313c527de181864db0e6249ed96128b1f3149ca`。AGENTS.md、research/knowledge/README.md、K0105/K0329/K0414/K0415/K0420/K0426、当日のS7/S6/S5関連log、既存監査器を確認した。標準11×11空盤は **UNKNOWN**。

## 何を追加したか

`research/experiments/n11-s6-win117-loss173-conflict-audit-20261030/verify.js` に、既存のLOSS6→LOSS5逆向き伝播を**別のS5厳密判定cache**と照合する監査を追加した。入力は既存のSHA固定172個の歴史的exact LOSS6、独立終局証明済みLOSS6 1個、2026-10-12凍結S5 cache 5,851件（Git blob `2dccf42b92337cbcbfb62ea5c77db487b1ad8ead`）。いずれも現在の探索結果を再計算したものではない。

全ての局面鍵について11×11盤のD4正準化、4点共円・共線の3×3整数行列式、石数、重複を検査。LOSS6の一石除去で得たLOSS5と凍結S5 cacheのWIN/LOSS衝突を検査し、追加で凍結cacheにないLOSS5からS4親を作り、各親の**全合法S5子**を盤面から再生成して被覆差分を求めた。

| 指標 | 結果 |
| --- | ---: |
| 歴史的LOSS6 / 終局証明LOSS6 | 172 / 1 |
| 逆向きに導く相異なるLOSS5 | 903 |
| 凍結S5 cache | 5,851（LOSS 5,692、WIN 159） |
| 903 LOSS5と凍結cacheの重複 | 873（全てLOSS） |
| WIN/LOSS衝突 | **0** |
| 凍結cacheにないLOSS5 | **30**（歴史的LOSS6由来24、終局証明LOSS6由来6） |
| 30局面が接続する相異なるS4親 | **112** |
| 凍結cacheに対して被覆が増えるS4親 | **112** |
| 新たに被覆されるS4→S5類別辺 | **149** |
| S4親1個あたり最大増分 | 3辺 |
| 更新後の最少未被覆S5子数 | 48 |
| 新規S4 LOSS閉鎖 | **0** |

最少残差48のため、今回の逆向き伝播だけではこの112個のS4親は閉じない。既知のS4 `00000000000000401000400040000000` は合法S5子94類、凍結cache上LOSS1類、今回の追加でLOSS4類・残り90類となり、K0426の局所監査（93→90）と一致した。

**注意**：30局面・149辺は2026-10-12の固定比較集合に対する追加被覆であり、2026-10-30時点の全証明集合に対する純増ではない。歴史的LOSS6の172件はsolver-trustedな保存exact判定であり、今回終局まで再計算していない。従って903個のLOSS5を新規の独立終局証明に昇格させない。S4の新規勝敗確定0、二石rootの新規閉鎖0、空盤UNKNOWN。

## 再現と安全性

```sh
node research/experiments/n11-s6-win117-loss173-conflict-audit-20261030/verify.js
```

凍結S5 cacheのSHA・行形式・5石合法性を検査し、架空のWIN5をLOSS5集合に混入させる負例を実際の矛盾検査関数で拒否する。S4被覆数と最少残差を回帰条件に固定。更新後のコードを同じGitHub固定入力でインメモリ実行し、上記件数・負例をPASSした。GitHub Actionsの最終結果は別途確認する。

証明戦略上、古いcacheを含めて全てを再探索するより、既存のS6証拠をS5へ伝播し、重複873件を排除する方が安全かつ安価である。一方、S4閉鎖に必要な残差は最少48類で、現時点ではこの経路を重計算の最優先対象にしない。
