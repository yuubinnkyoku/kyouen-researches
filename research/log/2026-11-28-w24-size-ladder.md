# 2026-11-28 第62-65ラウンド: W_24 s=7 サイズラダー全層の全数対応（ドデカッド/極大13-cap部分集合）

  K1349（サイズ 9-13 層マップ、極大拡大プロファイルはサンプル）を先に出版したため、

## 第62ラウンド: dodecad は s=7 で非極大 — K1348 k=12 行の修正

- K1348 の k=12 行「2,576, 0（極大・終端）」と、K1342 evidence の
  「サイズ 12 の G=0 1,020,096 は極大 12-キャップ（ドデカッド 2,576 を含む）」が
  dodecad-octad 交差プロファイル {2:132, 4:495, 6:132}（最大 6）と矛盾する疑い。
- `quick_dodecad_moves.py`（fullcheck.c と同一の ok_add 規約）で 5 個の dodecad を検査:
  **12 個の合法手（子はすべて極大 13-cap）、Grundy = 1**。
- 結論: dodecad は s=7 では非極大・非終端で **G=1**。上記 2 件の記述は誤り。
  正しくは極大 12-cap 1,020,096 = caps_12 − T_12 に dodecad は含まれない。

## 第63ラウンド: 全数 census（census.c）

- 759 octad の F2 張から Golay 符号を再構成（重み分布 {0:1, 8:759, 12:2576, 16:759, 24:1}）。
- 極大 13-cap = octad-free 13-点集合を全列挙: **30,912**（K1342 の SIZE 13 と一致、
  5 個の極大性スポット検査付き）。dodecad 2,576。
- 全部分集合を 2^24 マスク配列に多重度付きでマーク（重複排除）、サイズ別に集計。
  多重度総和の自己チェック（2,576×C(12,k)、30,912×C(13,k)）は全 k で PASS。
- 主要結果:
  - **T_k（13-cap k-部分集合）= 全 k-cap（k ≤ 11）**。すなわちサイズ ≤ 11 の全キャップは
    極大 13-cap に含まれる（k ≤ 7 は全部分集合、k=8 は全 8-cap）。
  - D_k ⊆ T_k が全 k で成立（dodecad 部分集合は必ず 13-cap に延長可能）。
  - d11→13-cap: 両方向一様 12/12、incident 総数 370,944 = 30,912×12（全数）。
  - dodecad（k=12）は**ちょうど 12 個**の極大 13-cap に含まれる（第62ラウンドの裏付け）。
  - D_7 = 340,032 = C(24,7) − 6,072（欠け = 759×8、octad の 7 点集合）、
    D_8 = 637,560（欠け = 759×8×16 = 97,152、octad の 7 点 + 外部 1 点）。
    8-点集合全体は 735,471 = 637,560 + 97,152 + 759（octad は非局面）と完全分割。
  - 13-cap 包含多重度: dodecad 9-部分集合 21 / 非ドデカッド 14、
    10-部分集合 12 / 4、11-部分集合 12 / 1、12-部分集合 12 / 1。

## 第64ラウンド: 全数 DP（dpverify.c）— サイズ 9-13 の全 6,661,168 局面

- fullcheck.c と同一の memoized DP でサイズ 9-13 の**全局面**の Grundy を厳密計算
  （memo 2^23 に全体が収まるため、サンプリングではなく全数にした判断）。
- (k, G) ヒストグラムが公式 GSIZE 行と**全 k で完全一致**（独立再計算になる）。
- クラス別（D = dodecad k-部分集合 / Tonly = 13-cap 部分集合の非ドデカッド / neither）:
  - k=9: D 566,720 全て G=2、Tonly 728,640 全て G=1、neither 0。
  - k=10: D 170,016 全て G=1、Tonly 1,700,160 全て G=0、neither 0。
  - k=11: D 30,912 全て G=0、Tonly 2,040,192 全て G=2、neither 0。
  - k=12: D（dodecad）2,576 全て **G=1**、Tonly 370,944 全て G=1、
    neither（極大 12-cap）1,020,096 全て G=0。
  - k=13: 30,912 全て G=0。
- k ≤ 8 はミッション指示どおりサンプル: ランダム 100 × 8 サイズと
  構造クラス（octad-6 / octad-free-6 / octad の 7 点 / dodecad 8-部分集合 /
  octad の 7 点 + 1 点）各 50 がすべてパリティ `G = k mod 2` どおり。
  k ≤ 8 では dodecad/13-cap の所属は G を分裂させない（パリティ層のまま）。

## 第65ラウンド: d11 拡大監査（d11ext.c）と統合

- 全 30,912 d11 の 12-cap 拡大（S+{x} 合法）は**ちょうど 13 個**で、
  **すべて T_12 に属する = 非極大**（極大 12-cap 拡大は 0）。
- census と併せて、d11 の極大拡大プロファイル **{13:12}** が全数で確定
  （K1349 はサンプル 3-5 個のみだった）。
- `assemble.py` で公式 GSIZE/SIZE 行・census・DP・d11ext を統合し
  `output/correspondence.json` を生成。**all_checks_pass: true**。

## 監査結果（K1349 × K1342 × 本実験）

- K1349 の 9 行の個数（566,720 / 728,640 / 170,016 / 1,700,160 / 30,912 /
  2,040,192 / 1,020,096 / 373,520 / 30,912）は K1342 GSIZE 行とすべて一致
  （転記ミスなし）。ただし dodecad の所属は「12 極大」ではなく「12 非極大」側。
- K1349 のプロファイル主張のうち、d11 {13:12}・非ドデカッド 11 の 13-cap 数 1・
  dodecad 9-部分集合の 21・dodecad 10-部分集合の 12 は本実験で全数確定。
  極大 12-cap 拡大数（{12:180} 等の 12 側）はサンプル主張のまま未検証。
- K1348 の k=9,10,11 行は本全数 DP で再確認（正しい）。k=12 行は誤り（第62ラウンド）。
- 結論は K1350（仮番号）に記録。K1342/K1348 の該当記述は統合時に正本側で修正が必要。

## 意義

- W_24 s=7 のサイズラダーが**全層 k=0..13** で「dodecad 部分集合 / 極大 13-cap
  部分集合 / 極大 12-cap」の 3 構造で完全に説明された（全数計算・全数 DP）。
- 特に「サイズ ≤ 11 の全キャップは極大 13-cap に含まれる」は、
  K1349 で層説明に使った「局所系・mex」議論の前提を全数で裏付ける。
- dodecad 非極大（G=1）の修正により、サイズ 12 の G=0/G=1 の構造説明
  （極大 / 13-cap 延長可能）が dodecad を含めて整合。
