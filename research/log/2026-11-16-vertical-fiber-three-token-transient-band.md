# 2026-11-16 3トークン過渡帯の値2位置（κ=1・対角線と c≤−(2k+1) スライス）

## 選定の経緯

- 天井トークン付き残余ゲームの値2位置分類（K0832・同日着地済み）の次課題として、3トークン (x,y,w) の過渡帯（x<R、R>z+1、R<S+z+2）を体系掃引することにした。2トークン族では家族B（過渡位置）の予想が既にあるが、3トークン族の過渡帯は未着手だった。
- 最新 main・AGENTS.md・knowledge README・K0832 を確認し、過渡帯の掃引・対角線 OK 表が既存成果（ラダー系・ブリッジ・位置族予想・高さのみ縮約・tail）と重複しないことを確認した。

## 経過と判断

1. 前回セッションの「2x_max=S+z、R=2x_max−1 で H=2 になるか」の m 別観察を再確認したところ、compaction メモの「m=4 は z=0 全OK」が誤りであることが分かった。多重集合を正規化して広グリッドで完全抽出すると、m=4 の OK は (z=0: 先頭2個が (1,1) でない ∨ all-ones) と (z=1: 先頭2個が (1,1)) の2層だった。旧観察は降順トークン表記での狭い抽出に由来する記憶違いの可能性が高い。
2. m=5,6,7,8 の OK 族を完全抽出した。m=5 では OK が rest=(a,1,1,1) 族に限られ、「m 奇数なら対角線 OK」説（m=1,3 で支持）が反例になった。m=6,8 では z∈{0,1} の2層構造（z=1 層: 先頭 m−2 個が1、z=0 層: 先頭 m−3 個が1＋2 の族）が現れた。m=4 の z=0 層だけが例外形。
3. 3トークン族の c=R−2x が奇数の過渡スライス R=2x−(2k+1) を j=x−(y+w+z) 座標で掃引し、k≥1 で統一形（予想U）を発見した。初期の統一式は w=1・j≥1 の行で偽陽性 931 件を出したが、(j=0∧w=1) の上端なし行を分離することで双方向 0 ミスマッチになった（k=1,2,3・20,052ケース）。
4. k=0（c=−1）は統一形の外の特異ケースで、j=0 と j=2 が全OK、j=1 は z=0 のみ、j≥3 は帯外と3本に整理した。R+1=2x が cap 係数に一致する（k=0）か最大トークンが cap される（k≥1）かの構造差が説明候補として残る。
5. 検証器は cap 付き正準多重集合エンジンと cap なし順序ラベルエンジンの相互照合を全計算に課し、36,958照合・不一致0・二回実行 byte-identical を確認した。

## 教訓

- 多重集合の OK 条件を書くとき rest[1:]（末尾側）と rest[:n]（先頭側）を混同すると大量の偽ミスマッチが出る。今回 m=5 の条件を rest[1:]==(1,1,1) と誤実装し、200件の偽ペナルティを生んだ。昇順正規形で「先頭の1の個数」を使う場合は必ず接頭辞で書く。
- 旧セッションの抽出メモ（compaction summary）は再計算で必ず検証する。今回 m=4 行の記憶違いを訂正できたのは、広グリッド完全抽出を最初にやったからである。
