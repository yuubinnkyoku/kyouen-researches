# 2026-11-23 知識項目の数値監査：生データとの自動照合（不一致0）

## 何をしたか

この一連の作業（反転平面のアーク・MDS対応・Grundy 完全計算）で作った K項目に書かれた
**数値を生データと自動照合**した（一時スクリプトで、項目中の表の数値をJSON/テキスト出力と比較）。

| 照合対象 | 生データ | 結果 |
|---|---|---|
| K1251 の `K(q)` 表（q=7..49 の下界） | `output/arc_maxsearch*.json` の**検証済み証人** | 17/17 一致 ✓ |
| K1250 の M_4 表 | `output/mds_maxlength.json` の `M4_lower` | 整合 ✓ |
| K1253 の安全局面数・g(空盤) | `output/grundy_q{5,7,9}*.txt` | 一致 ✓ |

**不一致 0 件。** 項目の数値はすべて生データで裏づけられている。

## ついでに直したもの（同ラウンド）

- K1250 と K1058 の上界記述が K1252 の改善（`K ≤ q`, q奇数 q≥9）より古いままだったので
  現在の最良上界に更新（K1058 には `K ≤ q` と `K ≤ q+1` が併記された重複行があった）。
- push 手順の落とし穴：ローカルに複数コミットを溜めると push の再適用ルーチンが
  最新以外を落とす。K1250 の監査コミットがこれで外れたため、検出・再コミット・push した。
  → **コミットごとに即 push** を徹底する。

## 再発したミス：artifact 挿入で YAML を壊す（2回）

新規 artifact を**既存エントリの `path:` 行の直後**に挿入すると、直前のエントリが
`role`/`note` を失い、新エントリに `role` が2つできて **YAML の重複キー**になる。
これで K1252（1回）と K1251（1回）の front matter が解析不能になり、
check.py は他項目の relation を「unknown relation target」として大量に報告した
（一見無関係な K1250/K1252/K1253 のエラーに見えるのが厄介）。

**対策**：artifact を足すときは必ず**直前エントリの note 行の後**に挿入し、
追加後に `yaml.safe_load` で front matter を検証する（このログの監査スクリプトの
最初のステップをそうする）。

## q=9 の構造化族の全数検査（同ラウンド）

- F_p-線型グラフ：q=8(0/512), **q=9(24/81)**, q=16(0/65,536), q=25(0/625),
  q=27(0/19,683), q=49(0/2,401) → **q=9 のみ**。
- q=p² の2次元 F_p-部分空間（サイズ q の点集合）：q=9 は 130個中 **40個がアーク**、
  q=25 は 806個中 0、q=49 は 2,850個中 0 → **q=9 のみ**。
- q=9 は「`K ≤ q` が tight な唯一の既知の位数」であり、構造化族が極大アークを与えるのも
  そこだけ、という対応が見えてきた（機構は未解明）。
