## 2. 選択肢の設計と比較

前提となる実測（W13 §2.4 からの転記）:
- SAT witness の検証は安い: 1,296点証人の独立幾何検査 28.903 s。
  1,322点なら C(1322,4) は同オーダーで約 35 s[INFERENCE: 点数比で線形]。
- 局所探索の実績: 1,000,000 flips / 9.144 s / 最良 41 違反
  （**サイズ1325 等号テンプレート**、seed=20261009 の walk。
  (1,1,3) 三値CNFでの局所探索実績は repo に存在しない）。
  flips 速度 ≈ 109,000 flips/s[INFERENCE: 9.144s からの換算]。

### S1: 固定 d 三値インスタンスへの局所探索（WalkSAT 系・再起動付き）

- **対象**: (1,1,3) 全体（候補Aの d 固定三値CNF、d を巡回）。
  11 d は最優先だが後述の通り「11 d だけ」では設計として不正確。
- **実装コスト**: 中。新規スクリプト1本。CNF リテラルへの素朴な WalkSAT は
  one-hot 制約（`[-low,-high]`, `[-low,-empty]`, `[-high,-empty]`）と
  相性が悪いので、探索状態は「各 pair ∈ {low, high, empty}」の多値変数とし、
  base 節（53,886 edge、四点禁止）の違反数 + ペナルティ
  λ·max(0, 空き対数 − 3) を目的関数にする。移动は「違反 edge に関わる
  1 pair の状態を、その edge を満たす値に変える」形式（WalkSAT の
  多値版）。seqcounter の cardinality 符号化は探索に使わない
  （評価は base 節と空き対数のみで完結するため）。
- **期待できる判定**: 違反 0 に到達すれば witness。三値CNFの SAT は
  サイズ 1322–1325 のどれか（W13 §2.2 の同値性の鎖）。いずれのサイズでも
  |parameters| ≥ 1322 なので **A(2647) = 1322 が約 35 s の独立幾何検査で確定**。
- **失敗時の情報量**: 弱い。「予算内に見つからない」は不在の証拠にならない
  （W13 次手3 と同じ留保）。得られるのは d 別・seed 別の最良違反数分布と、
  それが 0 から遠いか近いか（探索の難度の指標）のみ。**UNSAT 根拠にしない**。

### S2: CDCL を SAT 寄りにした長時間実行（位相・再起動パラメータ）

- **対象**: 同じ三値CNF。具体的には (i) 位相を warm 候補の逆（より多くの pair を
  「empty」側に初期化する等）や target に変える、(ii) 再起動間隔を短く固定、
  (iii) 20M 以上の予算を 11 d に再投資。
- **実装コスト**: 低。`ternary_general.py` の `phases()` と
  `solver.set_phases` 周りの変更のみで、出力形式・監査経路（DRAT）はそのまま流用できる。
- **期待できる判定**: どちらも出る可能性がある。UNSAT なら DRAT 付きで
  その d の receipt になる（S1 に無い利点）。SAT なら A = 1322。
- **失敗時の情報量**: ほぼ 0。20M conflicts × 11 d がすべて UNKNOWN という
  実績が既にあり、同じ符号化でパラメータを変えても硬さが変わる根拠は
  データに無い[INFERENCE]。d=147 の 20M は 6,187.7 s（result.json 転記）、
  これの数倍を 11 d に掛けるだけで数 CPU 日が消えうる。
- **位置づけ**: 主戦力ではないが、S1 と出力形式を共有するため、
  S1 の実装後に出力ディレクトリを流用して並行で走らせるのは妥理。

### S3: cube-and-conquer での (1,1,3) 攻撃

- **対象**: (1,1,3)。ただし W13 §2.3 の実測に反する期待は持てない:
  d 方向の独立性は本物で、並列化の第一手段（d 方向分割）は候補Aがすでに
  完全にやっている。d 内部の分割（cubing）の根拠はデータに無く、
  「一様に硬い」問題は cubing でも部分問題が硬いまま残りやすい
  （W13 §2.3 の [INFERENCE]）。総仕事量はむしろ増える（文献的に 1.2–3 倍）。
- **実装コスト**: 高（cuber + 分割管理 + 部分問題の集約管理）。
- **期待できる判定**: UNSAT なら全 cube の DRAT を合わせて receipt。
  SAT なら witness。
- **失敗時の情報量**: 低。コスト倒れのリスクが高い。
- **結論**: **後回し**。d 方向並列（候補A）が既に同じ並列性を持っており、
  その上で 11 d が 20M でも決まらない事実は「決定手続きとしての
  候補A」の限界を示している。cubing が効くという新規の根拠
  （探索木上部に大きな分岐がある等の観測）が得られるまで投資しない。

### S4: 既知 witness（A ≥ 1296 構成）からの構成的近傍探索

- **対象**: size 1322 の (1,1,3) witness を直接作る。
  既存の warm start 候補は 1,292点（`walk-1000000-seed20261109/candidate.txt`、
  `ternary_general.py` が assert で検証済み: `warm[1] == 1292`）。
  A ≥ 1296 の証人は独立幾何検査 28.903 s 済み（W13 §1.3 転記）。
  1292 → 1322 は +30点。
- **実装コスト**: 中〜高。「安全集合に点を足して違反を修復する」操作は
  `parabola-local-repair-20261109` の系で前例がある（1M flips / 最良 41 違反 /
  9.144 s、サイズ1325 等号テンプレート）が、その最良値 41 は
  幾何的最大値とは別の量であり、41 → 0 が届くという根拠は無い
  （W13 §2.4 の留保）。
- **期待できる判定**: witness が作れれば A = 1322（S1 と同じ検査経路）。
- **失敗時の情報量**: S1 と同程度（弱い）。加えて「等号テンプレートでは
  最良違反が 41 で頭打ち」という既存の否定的観測がすでにある。
- **位置づけ**: S1 と実体が近い（どちらも局所探索で witness を探す）。
  差は探索空間の表現だけ。S1 は CNF 違反を直接目的関数にでき、
  base 節の意味が符号化に埋め込まれている分、実装と評価が単純。
  **S1 に一本化して、S4 の資産（warm 候補 = 初期状態として再利用）は
  S1 の初期状態に吸収する**。

### 比較表

| 案 | 対象 | 実装コスト | SAT時の確定 | UNSAT/失敗時の情報 | 判定 |
|---|---|---|---|---|---|
| S1 局所探索（多値WalkSAT） | (1,1,3)、d巡回 | 中 | A=1322（~35 s 検査） | 弱い（不在の証拠にならない） | **主軸** |
| S2 CDCL SAT寄り | 11 d 三値 | 低 | A=1322 または d単位のDRAT receipt | ほぼ 0 | 副次（S1と並行可） |
| S3 cube-and-conquer | (1,1,3) | 高 | receipt または A=1322 | 低、コスト倒れ | 見送り |
| S4 witness近傍 | size 1322 | 中〜高 | A=1322 | 弱い（41違反の頭打ち観測あり） | S1 に吸収 |

**S1 を主軸にする理由**（非対称性）:
1. SAT が1件でも出れば、残る全作業（11 d のUNSAT証明 1,294件規模の
  見積もりは W13 §2.2 で 3M でも 232–322 CPU-h 単一コア）が
   約 35 s の検査ひとつで不要になる。
2. 失敗しても、その時点で失うのは電気代のみで、主張は何も汚さない
   （「UNSAT根拠にしない」を守れば）。
3. CDCL（候補A）が 20M まで全滅している領域は、局所探索が唯一
   勝負できる領域（W13 次手3 と同趣旨）。

**重要な設計修正（W13 次手3 に対する）**: W13 次手3 は「11 d のような硬い d」に
局所探索を当てる書き方だったが、これは対象の選び方として根拠が無い。
(1,1,3) が SAT なら、その witness の d は 1,294 個の UNKNOWN d の
**どこにあってもよい**。CDCL が硬い d がSAT witness の所在と無関係である
保証は無い[INFERENCE]。したがって pilot は「11 d に深く」ではなく
「全 UNKNOWN d に浅く + 層化サンプルに深く」の二段構成にする（次節）。

## 3. パイロット計画（S1、実行は次タスク以降）

### 3.1 対象インスタンス

- CNF: `ternary_general.py` による固定 d 三値CNF（target=1322, empty_bound=3）。
  本日の再現確認済み（§1）。1 d あたり 7,926 変数 / 68,404 節 / base 53,886 節。
- 探索は CNF リテラルではなく **pair 状態空間**: 1,322 pair
  （d を除く）× {low, high, empty} の 3 値。基数制約（空き対 ≤ 3）は
  ペナルティ λ·max(0, 空き対 − 3) で扱い、seqcounter 部は探索に使わない。
- d の選び方（二段）:
  - **浅い段（全走査）**: 100k 掃引で UNKNOWN だった全 d（最終的な全 d 完走後の
    1,294件を想定；ラダーlog 時点の実績では 8 d が 3M/10M/20M で決着済みなので
    残りは 1,286件[INFERENCE: 1,294−8、ただし100k掃引の完走状態は
    ラダーlogに集計が無く要確認]）。各 d に 10^6 flips。
  - **深い段（層化）**: 浅い段で最良違反数が最も低かった d と、
    既知の難所 11 d（147, 188, 194, 488, 602, 703, 717, 1003, 1103, 1166, 1229）
    から 20 d 程度を選び、各 d に再起動付きの 10^8 flips × 複数 seed。
- 初期状態: (a) warm 候補（1,292点）を pair 状態に変換したもの
  （`parameters()` の逆写像に相当）、(b) ランダム（seed 固定）。
  再起動ごとに交互に使う[INFERENCE: warm 側に引かれすぎないため。
  効果は未測]。

### 3.2 予算

- flips 速度の点推定: 109,000 flips/s（§2 の実績換算[INFERENCE: 
  サイズ1325 テンプレートでの実測の (1,1,3) 三値CNF への転用]）。
- 浅い段: 1,294 d × 10^6 flips = 1.3×10^9 flips ≈ **3.3 CPU-h**。
- 深い段: 20 d × 10^8 flips = 2×10^9 flips ≈ **5.1 CPU-h**

- 上限は W13 次手3 を継承して **24 CPU-h**（4コア × 6 h 壁時計）。
  実測速度が立たなかったら浅い段で打ち切り、速度を再計測してから
  深い段の d 数を決める（先に予算を確定しない）。

### 3.3 成功条件と witness の幾何検証手順

成功 = 違反 0 の pair 状態割当の発見（base 節 53,886 全て充足 かつ 空き対 ≤ 3）。
発見時の手順:

1. pair 状態割当を `ternary_general.py` の SAT パスと同じ形式
   （`parameters()` 相当で集合 S、`candidate.txt` = `p |S|` + パラメータ列）に変換。
   |S| ≥ 1322 を assert（三値符号化上のサイズは 1322–1325 のいずれか）。
2. **符号化を経由しない独立幾何検査**: S を全く別のコード（1296点証人で
   28.903 s の実績がある独立検査器）に掛け、全四点組の同円条件を検査
   （C(1322,4) ≈ 1.27×10^11 組、約 35 s[INFERENCE: 点数比で線形]）。
   通過なら **A(2647) = 1322**（下界 1296 は既存証人、上界 1322 は
   サイズ1323 の監査済み実績 — どちらも本タスクの範囲外の既存資産）。
3. witness と探索設定（seed、flips 数、最良違反の軌跡）を
   `research/experiments/` に新規ディレクトリで保存、K 項目を更新、
   1296 ≤ A ≤ 1322 を A = 1322 に改める。以降の UNSAT 側予算
   （W13 §2.2 の 232 h〜）は全て取りやめ。
4. 手順2で**落ちた**場合（符号化バグまたは探索器の評価バグ）は
   その旨を log に残し、評価器と `encode()` の差分を突き合わせて
   修正後に再実行。幾何検査は符号化の外側にあるので、
   この二重検査で偽 witness が A = 1322 の主張に到達することは無い。

### 3.4 失敗時の記録と解釈の境界

- 24 CPU-h 使い切って witness 無し → 「24 CPU-h のこの探索器では
  見つからなかった」のみを記録。**UNSAT の根拠にしない**
  （W13 次手3 と同じ）。
- 記録するのは: d 別の最良違反数（浅い段の全 d 分布、深い段の
  seed 間分散）、warm 初期化 vs ランダム初期化の差、
  flips 数に対する最良違反の減衰曲線。減衰が flat なら
  探索器の移動設計の見直し（例: 複数 pair 同時変更、
  ペナルティ λ の調整）が次の一手になり、その判断材料になる。
- 最良違反数を幾何的量と混同しない（W13 §2.4 の留保の継承）。

### 3.5 出力・管理

- 実験ディレクトリ: `research/experiments/` に新規
  （例: `parabola-ternary-walksat-20261116/`）。`init.json` に
  edge cache SHA-256（bb1c0201…, 4e17fe10…）、CNF SHA-256、
  探索器ソース SHA-256、seed、λ、を記録。候補Aの流儀を踏襲。
- 長時間探索系 workflow なので AGENTS.md に従い手動起動のみ。
  push しない。
- 予算ラダー（100k→3M→10M→20M）と違い、S1 は d ごと独立に
  打ち切れるため、VM 再起動耐性は「d×seed 単位で result を分割保存」で
  対応（ラダー運用の教訓、ラダーlog の方法欄から）。

## 4. まとめ

- S1（固定 d 三値CNFへの多値 WalkSAT、d 巡回は「全 UNKNOWN d に浅く +

  バイト同一 SHA-256 で再現することの確認）のみ。solver の長時間実行はしていない。
