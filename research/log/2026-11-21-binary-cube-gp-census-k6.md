# GP-census による K_6 = 9 の確定（2026-11-21）

## 経緯と動機

K0568 の残課題は「exactly-10 CNF の UNSAT 証明か、GP-10 集合の発見」だった。
CNF 路線は (a) 完全版 CNF が 255M 節でメモリ不足、(b) circuit 削減 CNF は
K0591 が示した包含極小化の誤用を含むうえ 8h10m の kissat でも UNSAT 未取得、
という二つの壁で止まっていた。そこで SAT ソルバを介さず、
GP 集合そのものの有限完全列挙（census）で上界を直接確定することにした。

## 設計

- **頂点0アンカー分割**。$x\mapsto x\oplus u$ は座標鏡映の合成で実アフィン自己同型、
  頂点推移的。ゆえに頂点0を含む GP 集合の計数 $s_k$ から全計数 $s_k\cdot64/k$ が従う。
  ペア $(0,v_2)$、$v_2=1..63$ の63本で木を完全分割（各ペアの生計数は r6-results.jsonl）。
- **高速ゲート**: GP 前置行列 $W$ の fraction-free 両側掃き出しで $EW=$対角（ピボット非零）
  を作り、追加候補の全ゲート判定を $W^{-\top}x$ 型疎関数の零検定に帰着。
  関数は真の行置換行列式の定数倍なので零検定は正しい。この「定数倍不変性」により
  逆行列を分数なしで持てるのが高速化の本体。
  - 設計段階の失敗: 最初 $W^{-1}x$ 型で書き、恒等式の数値照合で恒等式が立たないことを検出。
    正しくは $W^{-\top}x$ 型（転置を含む行置換恒等式）。数値例での恒等式検証を関数実装前に
    行うことが重要だった。
- **正確性**: ゲートはすべて 0/1 成分 7×7 行列式の零検定に帰着し、Hadamard 限界
  $(\sqrt7)^7=907.5\ldots$ より真の行列式の絶対値は 908 未満。
  $p=67{,}108{,}859$（PA）未満なので有限体で零検定すれば整数でも零。
  doubles/triples は第二素数 PB=67,108,837 でも重ねて検定（belt-and-suspenders、片方で厳密）。
- **サイズ別判定**: サイズ6拡張は 7×7 行列式、サイズ5以下は rank。

## 実行

- 全63ペア・maxSize 10・計 2 CPU で約13分（最重量 pair(0,1) 64秒）。
  サイズ10の GP 候補は全ペアで一度も受理されなかった。
- アンカー計数: $s_2{=}63$, $s_3{=}1{,}953$, $s_4{=}39{,}410$, $s_5{=}571{,}340$,
  $s_6{=}6{,}029{,}142$, $s_7{=}40{,}050{,}850$, $s_8{=}53{,}334{,}038$, $s_9{=}408{,}240$, $s_{10}{=}0$。
- 非アンカー総数: GP-7 $366{,}179{,}200$、GP-8 $426{,}672{,}304$、GP-9 $2{,}903{,}360$、GP-10 $0$。
- 下位次元: $K_3{=}5$（GP-5 総数 8）、$K_4{=}6$（GP-6 総数 1,088）、
  $K_5{=}7$（GP-7 総数 309,056）。

## 交叉検証（battery 20/20 + 監査表照合）

1. s4/s5/s6/s7 が d=6 監査表（依存 4,816 / 311,360 / 10,663,520・独立七点組 366,179,200）から
   独立に導かれる $(\binom{64}{k}-\mathrm{dep}_k)\cdot k/64$ と全桁一致。
   ここで d=6 の s7 は 366,179,200×7/64 = **40,050,850**（開発中の一時メモにあった
   40,048,344 は計算誤りだったことが監査表照合で確定）。
2. d=3/d=4 全サイズ、d=5 サイズ6以下が独立 brute 全列挙と全桁一致（battery B6）。
3. d=5 七点 GP 総数 309,056 = K0591（全局面DP・独立実装）の七石安全局面数。
   $K_5$ の第三手法による一致。d3/d4 も既刊依存数（12/100）と
   $58=C(8,4)-12$、$1{,}720=C(16,4)-100$ で一致。
4. 関数族恒等式を BigInt Laplace と照合（battery B1-B4、7000+ trials）。
5. 9点証人 {11,22,28,37,42,49,57,58,63}、第二9点集合 {0,5,6,14,21,26,35,41,52}、
   XOR 正規化 0 アンカー像の GP 性を brute 再検証（B7）。
6. ツリー内ゲートの brute 再照合（B8）: (0,62)/(0,61)/(0,58) は全ゲート、
   (0,45)/(0,40)/(0,35) は上限付き、不一致 0。
   最重量 (0,1) は check6 で先頭600,000ゲート、不一致 0（打切りあり）。
7. (0,45) の v3-スライス分割整合（B9）。

## 証拠の水準と限界

- 結論 $K_6=9$ は**単一実装の有限完全列挙**に由来する。上の交叉検証はアルゴリズムの
  各部品を多角度から検証するが、d=6 の全走査をもう一つの独立実装でなぞることは
  できていない。今後課題: 独立第二実装（異なる分割・異なる判定原理）での同時計数再現。
- GP 条件は最大安全石数の定義そのものだが、Grundy 値・勝敗は別問題（d=5 では
  K0546/K0591 が全局面DPで解いた。d=6 の同種の DP は本項目の対象外で未着手）。
- ペアごとの s9 計数は非一様（v2=1:17,280 / 3:40,320 / 7:52,992 最大 / v2≥31 で 0）。
  十分条件の構造説明は得ていない（未主張の観察）。

## 11×11 等への接続

本手法は GP 集合の完全計数に限る。共円ゲームの高速レーンの各課題（固定幅・q点版の
安定化長、s_n・K_n の未確定値）への直接の波及はない。ただし「有限完全列挙で上界を
確定する」この型は、盤が小さく補題で分割できる類似課題に転用可能。
