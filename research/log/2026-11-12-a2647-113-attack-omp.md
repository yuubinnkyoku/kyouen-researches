## 3. 予算ラダーの設計

段階: **1M → 10M → 100M → 1G conflicts**。各段階で DRAT 証明を保存し、drat-trim で検証する。
各段階は決着したら停止、UNKNOWN なら次段へ進む。

### 3.1 実装上の確定事実（本作業中に実測で確認）

ラダー設計は以下を前提にする。いずれも本セッションで実際に確認した:

1. **pysat Cadical195 の証明は名前の無い一時ファイルに書かれ、`get_proof()` が全内容を
   RAM に読み込む**（`Solver.new` の `self.prfile = tempfile.TemporaryFile()`、
   `get_proof` の `bytearray(self.prfile.read())`）。`/proc/self/fd/N` は `…(deleted)` を指し、
   通常ディレクトリに実体パスは現れない。**証明はディスク上のパスを持たず、プロセス終了で消える。**
2. **pysat Cadical195 は `incr`・`warm_start` をサポートしない**（構築時に
   `NotImplementedError` を送出。実測確認）。ライブラリ内に途中再開の口は無い。
3. 当環境に**ネイティブの CaDiCaL 実行ファイルは存在しない**（`which cadical` は空）。
   ネットワークは利用可能（`git ls-remote https://github.com/arminbiere/cadical` 成功）。

### 3.2 証明サイズの外挿と RAM 上限 → ネイティブ CaDiCaL が必須

W20 (0,1,2) の実測から証明サイズを外挿する: 証明 575,649,195 バイト RAW / 992,331 conflicts =
**約 580 バイト/conflict**、2,143,709 行 → 約 268 バイト/行。

| 予算 | 推定 conflicts | 推定 RAW 証明 | gzip 後（≈1/5）|
|---:|---:|---:|---:|
| 1M | 1,000,000 | ≈ 0.58 GB | ≈ 0.12 GB |
| 10M | 10,000,000 | ≈ 5.8 GB | ≈ 1.2 GB |
| 100M | 100,000,000 | ≈ 58 GB | ≈ 12 GB |
| 1G | 1,000,000,000 | ≈ 580 GB | ≈ 116 GB |

（`[INFERENCE]` 上下の 580 バイト/conflict 一定仮定、および gzip 約5倍。硬い問題ほど
行あたりバイトは増え得る。）

**メモリ実測**: MemTotal 7.9 GiB、MemAvailable ≈ 2.3 GiB。
pysat 経路（2.1 節）では 10M 段の証明 ≈5.8 GB を RAM に読む時点で破綻し、100M/1G は
不可能である。したがって**ラダーは pysat ではなく、証明を名前付きファイルへ直接書ける
ネイティブ CaDiCaL で走らせる**。ネイティブ CaDiCaL は起動時に
`--conflicts=N`（または `-c`）で予算を与え、証明を第2引数またはオプションで実ファイルに
書ける（正確な CLI はビルド版に合わせて確定すること — 本作業では未ビルドのため未確認）。

作業ディスクは十分: `/home/hatch` 118 GB 空き（100M 段 RAW ≈58 GB までなら可、
1G 段は 1 段だけで破綻する点に注意）。

### 3.3 drat-trim 検証段の設計

- drat-trim はファイルを読む独立チェッカーで、W20 実績:
  (0,0,1) 22,379 行→0.425 s、(1,0,2) 790,206 行→4.998 s、(0,1,2) 2,143,709 行→249.726 s。
  実測レートは 8,584〜158,104 行/秒と幅がある（`[INFERENCE]` 各区間で一定と仮定せず幅で扱う）。
- 10M 段の証明 ≈2.7M 行なら検証は数百秒〜数十分、100M 段 ≈27M 行なら数時間規模 `[INFERENCE]`。
  drat-trim 自身も途中再開の口を持たないため、**検証は1段単位で完結させる**。
- **RAM リスク**: drat-trim は補題をメモリに保持する。100M 段（数千万補題）は当環境の
  8 GiB では検証自体が不可能な可能性が高い `[INFERENCE]`。ラダーでは各段の
  検証時間・メモリを段ごとに記録し、ある段が窓/RAM に収まらなければそこで打ち切り、
  「N 段まで監査済み」と正直に記録する。
- 検証結果は段ごとに `audit-drat-trim.json` に保存し、proof と input の SHA-256 を併記する
  （W20 と同じ流儀。`w23_probe_113.py` は既にこの形で保存する）。

### 3.4 再起動対策

観測事実: VM は約2時間おき、時に40分間隔で再起動する（W20 ログ記載）。単一の
CaDiCaL 実行は途中再開できないため、対策は「窓に収める」＋「段単位で再開する」の二本立て。

1. **段の予算を窓に収める（第一の防衛）**。1M プローブ実測 cps ≈3,060 を使うと、
   2400 s（40分窓）で ≈7.3M conflicts、3600 s で ≈11.0M conflicts、5400 s で ≈16.5M conflicts。
   したがって **1M 段（≈327 s）は安全に窓内**、**10M 段（≈3,268 s ≈55分）は40分窓を超え得る**。
   硬い問題では cps が落ちる（W20 (0,1,2) は 819 cps）ため、10M 段は 40分窓に収まらない
   可能性が高い `[INFERENCE]`。運用は次による。
2. **段単位の再開ドライバ**。`w23_probe_113.py` は既に「`solver.json` があればスキップ、
   `audit-drat-trim.json` の署名一致なら検証もスキップ」する再開可能構造である。
   ラダーはこれを予算ごとのディレクトリ（`class-113-b<budget>`）に対して順に起動する
   ドライバに拡張する。再起動で殺された段は、その段の出力ディレクトリが無い（または
   `solver.json` が無い）ので、**次回起動時に最初から再実行される**。
3. **段の途中経過は残らない**ことを明記する（ネイティブ CaDiCaL にチェックポイントは無い）。
   40分窓に収まらない大段（10M 以上）は、再起動に当たるたびに最初からになる。
   そのため運用は「小段から順に、各段の結果 JSON を残しながら進める」。
4. 各段が UNSAT を返したら、**証明を gzip 圧縮して保存してから** drat-trim を別段として実行する
   （検証も再起動で中断し得るため、proof を残しておけば再検証が可能）。
   各段の作業ディレクトリは `~/workspace` 配下（再起動で消えない）に置く。
   `/tmp` は 512 MiB tmpfs で再起動時に消えるため使わない。
5. 長時間実行は `nohup` 等でバックグラウンドに置き、stdout を
   `~/workspace/kyouen-omp/tasks/w23-ladder-<budget>.log` に落とす（W20 と同じ流儀）。

### 3.5 ラダーの停止条件と記録

- いずれかの段で UNSAT + drat-trim VERIFIED が出たら、その時点で
  「A(2647) ≤ 1321（(1,1,3) クラスは監査済み UNSAT）」を確定し停止する。
- SAT が出た場合は証人を保存し（幾何検査は別段、W13 記載の 1322 点検査 ≈35 s `[INFERENCE]`）、
  A(2647) = 1322 を確定する。
- 全段 UNKNOWN なら「1G まで未決着」として記録し、A(2647) ∈ [1296, 1322] を動かさない。
- 各段の `solver.json` / `audit-drat-trim.json` / ログを `w23-113-probe/` 配下に残す。

### 3.6 代替経路（設計上の併記）

W13 が示した候補A（三値固定 d=1323、7,926 vars / 68,404 clauses）は本クラスより小さく、
d=1323 の 100k で UNKNOWN 14.34 s（6,975 cps）、3M で UNKNOWN 605.06 s（4,958 cps）と
実測 cps が高い。三値版 UNSAT ⇔ (1,1,3) UNSAT はサイズ1323 UNSAT（K0711）＋安全集合族の
下方向閉包から従う `[INFERENCE; W13 §2.2 の読み替え鎖に依存]`。ラダーを三値 d=1323 固定で
回す方が1段あたりが安くつく可能性があるが、読み替えの鎖が別 receipt に依存するため、
本ラダーの主経路は (1,1,3) クラス CNF 直接とする。併走させる場合は三値を補助経路とし、
どちらの receipt か（クラス CNF 直接か、三値＋読み替えか）を必ず併記する。
