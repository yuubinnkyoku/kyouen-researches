## 2. 分割方式の候補検討（健全性の厳密比較）

### 2.1 候補A: アシンプション（assume/restart による in-process cube 分割）

python-sat の `solve(assumptions=…)` 形式で変数の真仮定を与えて解く方式。W7 がまさにこの形式
（`w7-assump-2647-1322-…`）で試みた。

- **被覆**: assume リテラルの集合が全割当を被覆することは自明に示せる（枝の和割当が全称的）。
- **UNSAT→全体 UNSAT**: 各枝で assume 下 UNSAT なら全体 UNSAT、という推論は**正当**。
- **決定的欠陥: DRAT 領収書が独立しない。** pysat Cadical195 は仮定下 UNSAT を「USAT」
  （core 含む）として報告するが、証明は仮定を前提とする派生を含み、**そのままの DRAT チェーンは
  元 CNF 単独では検証できない**。仮定下 UNSAT の証明は「CNF ∧ assume ⊢ ⊥」であり、
  各 assume 節を CNF に加えて初めて独立検証可能になる。さらに:
  - pysat Cadical195 は `incr`/`warm_start` 非対応・証明は RAM 読込で消失（W30 §0・W23 §3.1 実測）。
  - **本 repo の主張規律（「検証を通過していない DRAT を監査済みと書かない」、W20 流儀）に照らすと、
    in-process 仮定ベースの UNSAT は監査可能な領収書を残せない**ため、A(2647) の確定主張には使えない。
- **結論: 不採用。**

### 2.2 候補B: CNF への単位節追加による独立サブ問題化（cube-and-conquer 相当の静的分割）

分割 $t$（枝の集合 $\{(v_i,\varepsilon_i)\}$）ごとに、元 CNF に対応する**単位節**
$\{(-1)^{\varepsilon_i} v_i\}$ を行として加えたサブ CNF $F \wedge \mathrm{units}(t)$ を
**独立ファイル**として書き出し、各サブ CNF を独立の CaDiCaL プロセスで解く。

- **被覆の完全性**: 分割族 $\{t_1,\dots,t_N\}$ が全割当を被覆することは、
  「$¬\bigvee_k \mathrm{units}(t_k)$ を導く割当が存在しない」こと、すなわち
  単位節の和集合が CNF の全変数割当空間を尽くすことで示す。
  3分木の場合、順序対 $(v_a,v_b)$ に対する
  $t_1=\{(v_a,1)\},\ t_2=\{(v_a,0),(v_b,1)\},\ t_3=\{(v_a,0),(v_b,0)\}$ は
  $v_a$ の両値を持ち、枝は互いに排反かつ全割当を網羅する。合成 cnf-check による
  機械検証も可能（§3.3）。
- **各サブ UNSAT ⇒ 全体 UNSAT**（健全性の核）: $F \wedge \mathrm{units}(t_k) \vdash \bot$
  が DRAT 検証済みで全 $k$ について成り立つとき、$F \models \bigwedge_k \bot \Leftrightarrow F \models \bot$ が
  成り立つ（各 $\mathrm{units}(t_k)$ は CNF 上の **正当な追加仮定**——もし $F$ が SAT ならその充足は
  いずれかの枝 $t_k$ に一致し、その枝は SAT になるはず）。各サブ証明は「サブ CNF を入力とする
  独立した DRAT チェーン」として drat-trim でそのまま検証できる。
  **領収書の独立性が重要**: 各サブ CNF の SHA-256 を確定しておけば、サブ証明の検証が
  過去の領収書に一切依存しない。
- **SAT の場合**（分工の落とし穴）: いずれかの枝が SAT なら**全体は SAT**（units を加えた
  CNF の充足は $F$ の充足）。 SAT/LUSAT/UNKNOWN のどの組み合わせでも停止できる。
- **UNKNOWN 枝**: 予算内に決着しない枝は**再分割**（§3.2）またはその枝だけ再実行すればよい。
  枝ごとに再実行しても健全性は失われない。
- **再起動耐性**: 各サブ問題は独立プロセスとして走り、終了時に `solver.json` が primitive atomically に
  残る。VM が再起動しても完了済みの枝の結果は失われない（proof は CaDiCaL が段階的にディスクに
  追記するため、強制終了された枝は `solver.json` が無い＝未完、として切り捨てられる）。
- **欠点**: 各枝が独立に 0 から学習するため、枝を跨ぐ学習が持ち越せない（学習節の共有は
  ドライバ層で実装可能だが、本設計では採らない——学習節を渡すと「枝が独自の学習条件の
  下で作られた節に依存する」ため健全性の説明が難しくなる。**持ち越し無し（毎回素の CNF から）が
  明確かつ監査容易**）。

### 2.3 候補C: 衝突予算の段階化＋学習節の持ち越し

段階 k で予算 $B_k$ まで解き、その学習節を次段に持ち越す方式（incremental solving）。

- **実装不可能**: ネイティブ CaDiCaL に「学習節をファイルへ保存／次実行時に入力として与えて
  再開する」公式手段は**存在しない**（W23 §3.1 に pysat を含め同様の実測。`--learned` 等の
  オプション無し、`cadical --help` の W30 §1.3 の表に該当項目なし）。学習節を `/tmp` 経由で
  独自 dump する改造は本体改変を要し、監査性も落とす。
- 仮にできたとしても、持ち越した学習節を含む CNF は元 CNF と区別されなければ
  DRAT 検証が曖昧になる（「入力 CNF の SHA が何を指すか」が不定になる）。
- **結論: 不採用。**

### 2.4 候補D: 段階化のみ（1M→10M→100M ラダー、分割なし）

W23/W30 の現行ラダー。100M 段が素朴な単一ラン＝13.6 h となり、再起動で失われる。
**空振りコストが全額**（≈13.6 h の演算が消失）である点が致命的でないのは、10M までの
実績で単一ランが到達しないことが分かっている段階に限る。1M・10M がすでに UNKNOWN である以上、
100M を保険なしの単一ランにする理由は無い。

### 2.5 推奨

**候補B（単位節追加による独立サブ問題化）+ 段階化の組み合わせ。**
理由: (1) 唯一「各サブの DRAT 証明が独立ファイルとして検証可能」な構造で本 repo の監査規律に合う、
(2) VM 再起動に対して枝単位の再開が効く（失うのは高々1枝の実行中分）、
(3) 被覆完全性が合成トートロジーとして機械検証可能。

## 3. 推奨方式のパラメータ設計

### 3.1 分割木

- 最上位の分割は **2変数 3枝**（対 $(v_1,v_2)$ の三方分割: $\{v_1\},\{¬v_1,v_2\},\{¬v_1,¬v_2\}$）。
  理由: 独立サブ問題は枝ごとにフォークするため、各枝の予算を「1枝 ≈ 1窓」に収める設計が要る。
  100M conflicts を総予算として枝ごとに均等配分するなら、3枝なら各 ≈33M conflicts、
  4枝（2変数4分割）なら各 25M conflicts となる。
- 本設計では **3枝を推奨**: 25M conflicts では1窓（約1.5〜2 h ≈ 5,400〜7,200 s）に収まらない
  可能性が高い（10M で 4,856 s かかった実績から 25M は ≈12,000 s、3枝の 33M では
  ≈16,000 s＝窓の約2〜3倍）。**どちらにせよ1枝は複数窓にまたがる**ため、
  枝の中でさらに予算を段階化する。
- 枝の選び方（どの変数対で割るか）: 最も出現数の多い変数は v15847・v15868（各 1,495 回出現、
  本作業中に DIMACS から実測。次点 v15846/v15869 の 993 回）。**ただし高頻出変数対で割るのが
  最良とは限らない** `[INFERENCE]`。本設計では第1パイロット（§5）で v15847/v15868 を使い、
  枝ごとの 100k 予算消費ペースを測ってから本番の分割変数を確定する。

### 3.2 枝内段階化（再起動耐性の主機構）

各枝のサブ CNF に対し、予算ラダーを枝内で走らせる:

```
枝 k のサブ CNF F_k = F ∧ units(t_k)（SHA-256 確定済み・凍結）
  段階 j: cadical -c 5000000 F_k proof_k_j.drat
  段階 j が UNSAT + DRAT 検証済み → 枝 k 完了（残り段階不要）
  段階 j が SAT → 全体 SAT、A(2647)=1322 で全ラダー停止
  段階 j が UNKNOWN → 段階 j+1 を最初から（学習無しで）実行
```

**枝内の各段階は独立プロセス・独立証明**。VM 再起動で失われるのは「実行中の1段の進行中分」のみで、
完了段階の solver.json・proof はディスクに残る。敗者復活戦的な学習の持ち越しは**意図的にしない**
（§2.2 の欠点項目参照: 監査容易性を優先）。

### 3.3 枝の健全性チェック（実行前に毎回）

各サブ CNF F_k について実行前に機械検証する（W30 ドライバの SHA 検査パターンを踏襲）:

1. **被覆検査**: 3枝の units が全割当を網羅すること（ブール全列挙。本作業で実施済み: §5.1）。
2. **sha 確定**: 各 F_k の SHA-256 を `sub-sha.json` に記録し solve 時に照合（W30 ドライバが
   input SHA 不一致で中止するのと同じ流儀）。
3. **clause 数整合**: ヘッダ clause 数 = 90,891 + 追加単位節数。本パイロットで確認済み
   （90,892 / 90,893 / 90,893）。

## 4. 計算量・証明サイズ・ディスク所要の見積もり

### 4.1 予算配分と時間

3枝均等、枝内 5M conflicts 段階ラダー×7（5M×7 = 35M ≧ 33.3M/枝）。総予算 105M conflicts。

| 項目 | 楽観（cps=2,059）| 保守（cps=1,700）`[INFERENCE]` |
|---|---:|---:|
| 1段（5M）の所要 | ≈ **2,430 s ≈ 40 分** | ≈ **2,941 s ≈ 49 分** |
| 1段の証明（RAW） | 5M × 274.7 B ≈ **1.37 GB** | 同左 |

### 4.3 drat-trim 検証

## 6. 失敗条件と中止基準

1. **枝内全段 UNKNOWN**: その枝は「35M conflicts まで未決着」と記録。3枝すべて未決着なら
   「(1,1,3) は 2変数3枝分割×35M conflicts でも未決着」と記録するのみで、
   **1296 ≤ A(2647) ≤ 1322 は動かない**。
2. **いずれかの枝で SAT**: 全体 SAT（§2.2 の方）。証人を保存し W13 流儀の幾何検査
   （1322 点、≈35 s `[INFERENCE]`）を経て A(2647) = 1322 を確定、停止。
3. **3枝すべて UNSAT + DRAT VERIFIED**: 全体 UNSAT、A(2647) ≤ 1321 を確定して停止。
4. **検証不能**: drat-trim が RAM 不達の段は「N 段まで監査済み」と正直に記録し監査済み主張から
   外す（W23 §3.3 の規律）。段 5M 切りで回避見込み `[INFERENCE]`。
5. **再起動密集（40分間隔が続く）**: 段予算を 2M に切り下げ。段予算の再配分は各段の独立性から
   健全性に影響しない。窓が安定するなら 10M に上げ空振りを減らす。
6. **中止基準**: 総 105M conflicts を消費しても全枝未決着なら本分割での決着を断念し、
   「100M 級分割探索でも未決着」を記録して次手段（1G 級再設計、または三値固定 d=1323 経路の
   再評価、W23 §3.6）へ移る。
