# 2026-11-09 p=2647 ではサイズ h+1 = 1324 の石が存在しない（訂正版は後続ログ参照）

## 結果

- サイズ h+1 = 1104 の安全集合は、`x + c - e = 1`（x: 0 を含む、c: 完全対数、e: 空対数）から
  次の 3 形状に限られる。
  - (a) `(1,0,0)`: `0` ＋各対一側（完全対なし）
  - (b) `(0,1,0)`: `0` なし、一完全対＋各対一側
  - (c) `(1,1,1)`: `0` ＋一完全対＋一つの空対
- p=2647（h=1323）で 3 形状すべてを単一 CNF で判定:
  - 形状 (a): **UNSAT**（`clauses_for_pair(p, edges, 0)`、既存エンコーダ）
  - 形状 (b): **UNSAT**（0.2 秒、71,078 節、7,937 変数）
  - 形状 (c): **UNSAT**（8.2 秒、79,017 節、10,582 変数）
- したがってサイズ 1104 の安全集合は存在せず、**サイズ 1324 の集合は存在しない**（正しい上界は `A(2647) <= 1323 = h`。1104 は p=2207 の h+1 であり、本ログの表題は誤り。訂正版は `2026-11-09-p2647-no-size-h1-set-corrected.md`）。

## 方法のメモ

- 形状 (b): 各対を {BOTH, LOW, HIGH} の 3 値（NONE なし）、BOTH はちょうど 1 個。
  点の選択を補助変数 `a_t <=> side_t or BOTH` で表し、**原点を含まない**禁止四点だけを節にする
  （原点を含む辺は集合に 0 が無いので無関係）。台形辺（二完全対）は BOTH=1 の制約から冗長なので落とす。
- 形状 (c): 各対を {BOTH, NONE, LOW, HIGH} の 4 値、BOTH=1 かつ NONE=1。原点を含む辺も節にする。
- どちらも p=2647 では数千〜1 万変数・7〜8 万節の単一インスタンスで、数十秒以内に決まった。

## 意味と限界

- 等号不達成（1105 石なし）に加えて、**1104 石も存在しない**ことを示した。上界との差は 2 以上。
- 正確な `A(2647)` は未確定。サイズ 1103（= h）の形状は `x + c - e = 0` から
  `(0,0,0)`, `(1,1,0)`, `(0,1,1)`, `(1,0,1)` の 4 形状があり、同様の単一 CNF で順に判定できる見込み。
- 単一 CNF は素数によって難易度が大きく変わる（p=2207 の形状 (c) は長時間未決だった）。
  p=2647 は証明サイズが小さい「頑健な失敗」であり、形状探索も容易だった。
