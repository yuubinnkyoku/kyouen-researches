# 2026-11-08 p=2207 の 1104 石（次サイズ）の形状探索と DRAT 監査の見通し

- 前提: K0693 により p=2207 では等号 1105 石が存在しない（全 d の CNF が UNSAT、監査待ち）。
  次の問いは「1104 石はあるか」、すなわち `A(2207)` の値。
- **形状の数え上げ（訂正）**: ペア `{i,p-i}` を `h` 個とし、`0` の有無を `x`、両方含むペア数を `c`、
  どちらも含まないペア数を `e` とすると `|S| = x + c + h - e`。
  - サイズ `h+2`（1105）: `x + c - e = 2` は `(x,c,e)=(1,1,0)` のみ → 一意（K0693 の根拠は正しい）。
  - サイズ `h+1`（1104）: `x + c - e = 1` は **3 通り**:
    (a) `(1,0,0)` = `0` ＋各対一側、(b) `(0,1,0)` = 完全対一つで `0` なし、
    (c) `(1,1,1)` = `0` ＋完全対一つ＋**空ペア一つ**。
    当初 (a)(b) の二形だけを数えていたが、これは誤り。(c) を別途調べる必要がある。
- 結果:
  - **形状 (a) は UNSAT**（`clauses_for_pair(p, edges, 0)`、31,868 節、cadical 26 秒）。
  - **形状 (b) は UNSAT**: d = 1103..1 の全 d を走査（前半 d>=約643 は 8 並列の初回走査、
    後半 d=1..660 は再走査。unknown 0・SAT 0）。したがって「`0` なし・完全対一つ」の 1104 石は無い。
  - **形状 (c) は探索中**。単一 CNF で全 (d,e) を覆う符号化を実装:
    各対に {BOTH, NONE, LOW, HIGH} の4値（exactly-one）、点 t の選択を補助変数 `a_t ⟺ (side_t ∨ BOTH)` で表し、
    各禁止四点は `∨_t ¬a_t`。BOTH の個数 = 1、NONE の個数 = 1 を基数制約で課す。
    初期実装には符号化の誤り（辺の節の極性・補助変数番号の衝突）があり、修正して再実行中。
- DRAT 監査の見通し（K0693 の信頼境界を閉じるため）:
  - cadical は DRAT を出力できる（既定はバイナリ、`--binary=false` でテキスト）。実測サイズは
    d=1: 22 行/252 B、d=1103: 111 行/2.5 KB、d=1050: 159 行/4 KB と小さい例がある一方、
    d=7: 41 MB、d=100: 26 MB、d=600: 34 MB、d=800: 47 MB など**大多数は巨大**。
  - 現環境に drat-trim 等は無い。`drat_check.cpp`（RUP を watched literal で、非 RUP は RAT）を実装し、
    自明例・d=1・d=1050・d=1103 で **VERIFIED**（`output/drat_audit_sample.json`）。
    巨大証明は from-scratch 伝播では非現実的なので、増分チェッカーが次の実装課題。
- 限界: 形状 (c) の結果待ち。`A(2207)` は 1104 未満の可能性も残る。UNSAT の全数 DRAT 監査は未実施。
