# 2026-11-08 p=2207 の 1104 石（次サイズ）の形状探索と DRAT 監査の見通し

- 前提: K0693 により p=2207 では等号 1105 石が存在しない（全 d の CNF が UNSAT、監査待ち）。
  次の自然な問いは「では 1104 石はあるか」、すなわち `A(2207)` の値。
- 構造: サイズ `h+1` の集合は次の二形に限る。
  - (a) `0` ＋各対 `{i,p-i}` の一側（完全対なし）。
  - (b) `0` を含まず、ちょうど一つの完全対 `{d,p-d}` ＋他の各対の一側。
  （サイズ `h+2` では `0` と完全対が両方必要だったのに対し、`h+1` では片方ずつ。）
- 方法: 既存の厳密 CNF 生成器 `clauses_for_pair(p, edges, double)` を使う。
  `double=0` が形状 (a)、`double=d` かつ原点を含む辺を除いた辺集合が形状 (b)。
  SAT モデルは集合に戻し、全禁止辺との照合で検査する。
- 結果:
  - **形状 (a) は UNSAT**（31,868 節、cadical 24.5 秒）。`0` を含む 1104 石は存在しない。
  - 形状 (b) は d ごとの走査。d = 1103 から約 450 個（d >= 約 650）を走査して**全て UNSAT**、
    SAT 証人なし。残りは d = 1..660 を走査中（2026-11-08 01:2x 開始）。
- DRAT 監査の見通し（K0693 の信頼境界を閉じるため）:
  - cadical は DRAT を出力できる。実測サイズは d=1: 126 B、d=1103: 1,082 B（前処理で即 UNSAT）、
    d=550: 17.5 MB、d=289: 18.9 MB。すなわち**大半の d は極小の証明**で、難しい少数が巨大。
  - 現環境に drat-trim 等の検査器は無い（PyPI にも該当パッケージが見つからない）。
    全数監査には独立な DRAT チェッカー（RUP＋RAT、C++ 実装）が必要。次の実装課題。
- 限界: 形状 (b) の走査は未完。`A(2207)` の確定には (b) の全 d の判定が必要。
  いずれも UNSAT の信頼はソルバ依存で、DRAT 監査は未実施。
