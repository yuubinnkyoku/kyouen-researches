# n11 残余72行 WIN8-D10候補 `0000000800000000380000000810000a` の証明書抽出・独立検証 単一オーナー宣言（2026-11-20）

宣言時の main は `de8c44ac96fbde0616a216f184dd54b42b3f2c49`。

本レーンは K1095 の replace-12 depth-10 sweep で両AND順序 uncapped `loss=true` となった次の8石rootだけを担当する。

```
0000000800000000380000000810000a
```

K1095正本 SHA-256 は `335eca5ecb7c72e6fb0ee41eb740de736bf4eb78791823ae55f6375a68cb4707`。記録済みprobeは andclose1: 1,226,804 nodes、andclose0: 1,416,679 nodes、いずれもuncapped、終局石数範囲 [14,18]。K1097のWIN8候補16根にも含まれる。

このrootは、既存のWIN8二手応答被覆計画で固定根の第2候補として使われている。K1096で証明済みのrootとは別に、親行 `00000000000000003800000008001080` の初手bit 9・109への返しを担う。ただし、これは二手応答義務2個の被覆であり、S6親行の閉鎖ではない。

## やること

- K1095 sweep正本・runner v17・K1097 refsolve正本・WIN8応答被覆計画をhashで固定し、対象rootの両AND順序probeとpilot controlを再現する。
- 4×4整数行列式でroot安全性・D4正準形・全合法初手を独立導出する。
- 既存のWIN8 extractorをroot引数で再利用し、全合法初手58通りから戦略証明書をblind抽出する。
- 抽出を同一条件で2回、別プロセス・別作業場所でもう1回実行し、証明書bytesが完全一致することを確認する。
- 探索器をimportしないBigInt 3×3余因子検証、Bareiss 4×4検証、Python標準ライブラリによる第三実装で、root・全subroot・全winner局面・全loser応手・終局条件・証明書行の過不足をfail-closed検査する。
- 成果は `research/experiments/n11-residual72-win8-cert-extract-root0810000a-20261120/` に置き、K1095候補の状態を証明書検証済みに更新する。既存の149-root応答被覆計画は、根数や被覆義務を変えずに第2固定根の証拠状態だけを更新する。

## やらないこと

- 他のWIN8候補の抽出、147追加候補のprobe・sweep、safe8 pool再解決、response-cover最適化のやり直しは行わない。
- 8石証明書からのS6 receipt fold、S6行の閉鎖、二石root・空盤の勝敗判定は行わない。
- K1097独立第二検証、replace-9 depth-10 sweep、別root `00000000000200003800200008180000` の抽出には着手しない。各単一オーナーの範囲を尊重する。
- 新規探索は対象rootのK1095 probe再現だけに限定する。抽出処理の同時実行は最大4プロセスとする。

## 解釈規約

- 両AND順序の `loss=true` と証明書は、指定された8石rootで手番側が負けることだけを示す。
- 既知のREFUTED-D10はLOSS証明ではない。nodes・solved数は勝敗ではない。
- 第2固定根が証明書検証済みになっても、149-root計画の147追加根はすべて未証明候補のままである。
- **標準11×11空盤、二石root `{49,60}`・`{59,60}`、S2 `{59,60}`、class 1/2/4はUNKNOWNのまま。S6行も本レーンでは閉じない。**
