### 実装教訓（第2セッション）

- **この環境のjq（jaq系）は $var[.] で入力 . を添字に使えない（常にnull）**。null == null により「不一致0」がvacuousに成立する事故が発生。検証は必ず keys[] as $k | $var[$k] 形式にすること。
- **awkは数字のみの長い文字列を数値化する**（16進鍵の "…01" と "…02" が等値判定）。文字列比較は接頭辞を付けて数値化を阻止する。
- **busyboxの tail -c +N は先頭からの位置指定として動作しない**（末尾Nバイト扱い）。中央部分列は tail -c L | head -c M で作る。
- pair証明書ビットは p+2p=3p（隣接2ビット）であって 2p ではない。所属判定は「bを割り切る最大の2の冪」q を求め、b/q==3 ならペア・==1 なら単ビット。
- 旧 {78,86}=412316847416 は 3×2^37+13,000（下位散在ビット）。合成マスクは「2冪または隣接2冪の和」であることを数値検証してから所属判定に使う。
- セッションFS上限8MiBは/tmp・tool-results自動保存も含む。大規模get_file_contentsの後は不要分を削除する。
- **GitHub API書き込みが一時全面失敗することがある**（tiny write含め tree API timeout・contents API 500 が約10分継続した完全な一時障害。数分おきのretryで回復）。1.78MBの分割pushは1ファイル1コミット（594KB×3）で成功。
- top-level bashのprintfで多バイト文字列を書くとmojibake化する場合がある。日本語の追記はrun_typescript内のwrite_fileで行う。
